## 一、安全防护评审（评分：7.5/10）

### 1.1 认证与授权

**双 FilterChain 设计**（管理端 + 门户端）：
- `PortalSecurityConfig`（`@Order(1)`）匹配 `/portal/**`，JWT Token 认证。
- 管理端 SecurityConfig 匹配 `/system/**` 等，Session + Token 混合（RuoYi 基座）。
- 密码编码：BCryptPasswordEncoder，强度合理。
- Token 配置：HS512 算法，secret 通过环境变量注入，要求至少 64 字节。

**优点**：
- `@Anonymous` 注解 + `PermitAllUrlProperties` 扫描，公开接口声明式管理。
- 密码错误锁定（5 次/10 分钟）、风险验证码（密码错误 2 次或 30 天未登录强制验证码）。
- 门户端 stateless 会话，适合分布式部署。

**风险点**：
- `TOKEN_SECRET` 通过 `${TOKEN_SECRET:}` 注入，缺省值为空字符串。若生产环境未配置，启动可能失败或使用了弱密钥。**必须在部署检查清单中强制校验**。
- JWT Token 过期时间未在 application.yaml 中明示，需确认生产环境设置合理（建议 30 分钟 access + 7 天 refresh）。
- 管理端和门户端的 Token 是否使用同一 secret？若是，存在权限提升风险（门户 Token 伪造管理端请求）。建议分离密钥或增加 audience 校验。

### 1.2 输入安全

| 防护措施 | 状态 | 评估 |
|----------|------|------|
| XSS 过滤 | ✅ 启用 | `XssFilter` 覆盖 `/portal/*`、`/cms/*`、`/system/*`、`/monitor/*`、`/tool/*` |
| SQL 注入 | ✅ 基本消除 | v12.1 全部迁移 XML，MyBatis-Plus 条件构造器防注入 |
| CSRF | ✅ 禁用 | 前后端分离 + JWT，CSRF 不适用，已 `csrf.disable()` |
| Prompt 注入 | ✅ 防护 | `PromptInjectionGuard` 扫描 DANGEROUS 直接拒绝 |
| 文件上传 | ⚠️ 需确认 | 限制 JPG/PNG/WebP/GIF ≤500KB，但需确认是否校验文件头（防改后缀上传） |
| 敏感词过滤 | ✅ 启用 | DFA 词树，`sys_sensitive_word` 表管理，输出过滤复用 |

### 1.3 数据安全

- **敏感数据脱敏**：`SensitiveJsonSerializer` 存在，但需确认是否覆盖所有接口（如用户手机号、邮箱、身份证）。
- **数据库密码**：开发环境 `application-local.yaml` 含明文凭据（符合规范，仅本机使用），生产环境通过环境变量注入。
- **MinIO 密钥**：生产环境通过环境变量注入，符合安全规范。
- **日志脱敏**：需确认日志中是否打印了敏感信息（如 Token、密码、支付回调报文）。

### 1.4 AI 安全

**安全三件套已落地**：
1. **注入防护**：`PromptInjectionGuard` 基于规则扫描（指令覆盖/提示词探取/角色扮演）。
2. **成本熔断**：`TokenCostGuard` 场景日限额，超限降级。
3. **输出过滤**：`AiOutputFilter` 复用 DFA 词树脱敏。

**待加强**：
- 注入防护基于规则而非模型，对抗性输入（如 Base64 编码、Unicode 变体）可能绕过。建议增加输入解码规范化步骤。
- AI 执行日志记录了完整输入输出，需确认日志存储的访问权限和保留周期，防止敏感对话泄露。

## 二、配置管理评审（评分：7.0/10）

### 2.1 配置文件结构

| 文件 | 用途 | 评估 |
|------|------|------|
| `application.yaml` | 基础配置 | ✅ 公共部分，无敏感信息 |
| `application-dev.yaml` | 开发环境 | ✅ 环境变量回退 |
| `application-local.yaml` | 本地开发 | ⚠️ 含明文凭据，已纳入 .gitignore？实际 .gitignore 排除了 application-prod.yaml/test.yaml，local 未排除。需确认是否含真实凭据 |
| `application-prod.yaml.example` | 生产模板 | ✅ 模板正确，但需复制为 prod.yaml 并配置 |

### 2.2 运行时配置（sys_config）

v11.98 将 AI 运行时开关全面迁移到 `sys_config` 热配置化：
- `ai.global.enabled`：全局 AI 开关。
- `ai.resume.advice.enabled`：简历建议开关。
- `ai.interview.gateway.gray.enabled`：面试网关灰度开关。

**优点**：
- 无需重启即可调整配置，运营灵活性高。
- 与 `ai.enabled`（YAML 层 Bean 装配开关）分层清晰：YAML 管 Bean 是否存在，sys_config 管业务是否可用。

**风险**：
- `sys_config` 表数据被篡改可能导致功能异常，需限制后台配置权限（仅超级管理员可改）。
- 配置变更无审计日志，建议增加 `sys_config` 修改记录。

## 四、监控与告警（评分：5.0/10）

**现状**：
- Spring Boot Actuator 已引入，但 `management.health` 为空配置，未启用具体端点。
- Druid 监控页面存在，但生产环境需确认是否暴露（有 druid 用户名密码）。
- AI 执行日志可观测（管理端查询），但无实时告警（如 Token 成本突增、错误率飙升）。
- 支付网关无实时监控（如订单堆积、回调失败率）。

**建议**：
1. 启用 Actuator 健康检查端点（`/actuator/health`、`/actuator/info`）。
2. 接入 Prometheus + Grafana（或云监控），暴露 JVM/数据库/Redis/业务指标。
3. 关键业务告警：支付回调失败率 > 5%、AI 调用错误率 > 10%、Token 日消耗 > 预算 80%。
4. 日志聚合：接入 ELK（或云日志服务），统一收集后端/前端/Nginx 日志。
