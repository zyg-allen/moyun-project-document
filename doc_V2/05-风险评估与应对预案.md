## 二、合规风险应对

### R-01: ICP 未备案即上线

| 维度 | 内容 |
|---|---|
| 风险描述 | 未完成 ICP 备案即对外提供服务 |
| 法律后果 | 《互联网信息服务管理办法》罚款 + 关停 |
| 应对策略 | 发版前必须完成备案；如用海外服务器需评估跨境合规 |
| 应急预案 | 备案期间仅做内测，不对外公开访问 |
| 责任人 | 运维 |

### R-02: UGC 内容违法

| 维度 | 内容 |
|---|---|
| 风险描述 | 用户发布涉政/涉黄/涉暴等违法内容 |
| 法律后果 | 《网络安全法》罚款 + 关停 + 刑事责任 |
| 应对策略 | 接入阿里云内容安全 SDK + 自建敏感词库 + 人工审核 |
| 应急预案 | 发现违法内容立即删除 + 保存记录 + 向主管部门报告 |
| 责任人 | 内容安全负责人 |

### R-03: 用户数据泄露

| 维度 | 内容 |
|---|---|
| 风险描述 | 黑客攻击或内部泄露导致用户数据外泄 |
| 法律后果 | 《个人信息保护法》罚款（最高 5000 万或营业额 5%） |
| 应对策略 | 敏感信息加密 + 数据库访问审计 + 应急预案 |
| 应急预案 | 72 小时内评估 → 上报监管 → 通知用户 → 复盘 |
| 责任人 | 技术负责人 |

## 三、安全风险应对

### R-04: 明文密码被拖库

| 维度 | 内容 |
|---|---|
| 风险描述 | 数据库被攻击，存量明文密码泄露 |
| 影响范围 | 所有存量用户 |
| 应对策略 | 立即强制改密或批量 BCrypt 迁移 |
| 应急预案 | 检测到拖库 → 强制全量改密 → 通知用户 → 安全审计 |
| 责任人 | 后端负责人 |

### R-05: 代码执行 RCE

| 维度 | 内容 |
|---|---|
| 风险描述 | 代码运行功能被利用执行恶意代码 |
| 影响范围 | 服务器被完全控制 |
| 应对策略 | 已下线；未来需 Docker/gVisor 沙箱化后重启 |
| 应急预案 | 检测到异常 → 立即下线功能 → 服务器重置 |
| 责任人 | 后端负责人 |

### R-12: 服务器被攻击

| 维度 | 内容 |
|---|---|
| 风险描述 | DDoS / SQL 注入 / XSS 等攻击 |
| 应对策略 | WAF + 限流 + SQL 注入防护 + XSS 过滤器覆盖全部路径 |
| 应急预案 | 监控告警 → 自动限流 → 人工介入 |
| 责任人 | 运维 |

## 七、应急预案总览

### 7.1 数据泄露应急流程

```
发现泄露（监控/用户报告/第三方通报）
  ↓
1 小时内：评估范围 + 止损（切断访问）
  ↓
24 小时内：上报监管（网信办/公安）
  ↓
72 小时内：通知受影响用户
  ↓
7 天内：完成复盘 + 整改报告
```

### 7.2 违法内容应急流程

```
发现违法内容（用户举报/审核发现/监管通知）
  ↓
立即：删除内容 + 保存记录
  ↓
1 小时内：向主管部门报告（如涉及违法）
  ↓
24 小时内：处理违规用户（警告/封禁）
  ↓
记录归档：违规内容 + 处理结果 + 报告记录
```

### 7.3 服务器攻击应急流程

```
监控告警（DDoS/异常流量/入侵检测）
  ↓
自动：限流 + WAF 拦截
  ↓
人工介入：评估攻击类型
  ↓
严重：切换服务器 + 数据恢复
  ↓
复盘：加固 + 补丁
```
