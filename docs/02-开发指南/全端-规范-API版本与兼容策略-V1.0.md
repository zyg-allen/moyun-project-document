# API 版本与兼容策略（V1.0）

> 现状：977 个接口统一在根路径，无版本前缀。
> 目标：在不破坏现有客户端的前提下，建立可演进的版本策略。

---

## 一、版本标识

| 方式 | 取值 | 说明 |
|---|---|---|
| 响应头 | `X-API-Version: 1` | 所有接口统一返回，便于客户端识别 |
| 路径（新接口） | `/api/v1/...` | 仅新模块使用，旧接口不强制迁移 |
| 兼容窗口 | 至少 2 个小版本 | 旧字段保留，新增字段可选 |

## 二、兼容规则

### 允许的变更（向后兼容）

- 新增可选字段；
- 新增接口；
- 放宽校验（如长度上限变大）；
- 错误信息文案调整（不改 `code`）。

### 禁止的变更（破坏性）

- 删除字段、改字段类型；
- 改接口路径或 HTTP 方法；
- 收紧必填/长度限制；
- 改 `code` 语义。

> 破坏性变更必须：新路径（`/v2`）或新接口名 + 旧接口保留一个兼容窗口。

## 三、废弃流程

1. 旧接口标 `@Deprecated` + Javadoc 指明替代接口；
2. 响应头增加 `Deprecation: true`（可选）；
3. 保留至少 2 个发布周期；
4. 用 `/cms/monitor/api-stats` 观察调用量，归零后删除。

## 四、契约测试要求

- 新增/修改接口必须补契约测试（字段存在性 + 类型）；
- 列表接口统一断言 `records` 为数组、`total` 为数字；
- 契约测试命名：`XxxContractTest`。

## 五、当前落地

| 项 | 状态 |
|---|---|

| VO 化模块 | 存钱、流水、资产、商品、消息 |
| 契约测试 | 8 个 |
| 公开接口冒烟测试 | 本次新增 |
