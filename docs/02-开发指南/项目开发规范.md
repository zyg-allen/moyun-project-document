### 1.4 Lombok 使用规范

项目全局启用 Lombok，**优先使用注解**而非手写 getter/setter/toString。

| 场景                 | 推荐写法                                                      | 禁止写法                                                             |
| ------------------ | --------------------------------------------------------- | ---------------------------------------------------------------- |
| 普通实体/VO/DTO/Query  | `@Data`                                                   | 手写 `getXxx()/setXxx()`                                           |
| 继承 `BaseEntity` 的类 | `@Data`（子类注解即可）                                           | 手写 `getParams()/setParams()`                                     |
| 日志                 | `@Slf4j`                                                  | `private static final Logger log = LoggerFactory.getLogger(...)` |
| Builder 模式         | `@Builder` + `@NoArgsConstructor` + `@AllArgsConstructor` | 手写链式 setter                                                      |

**例外情况（保留手写）**:

- `UserDetails` 实现类（`LoginUser`、`PortalLoginUser`），接口方法有明确语义

- `BaseEntity.getParams()`，内部有懒加载逻辑

- 方法上有 `@Size`、`@NotBlank` 等 Bean Validation 注解，需保留 getter 以生效

- 反射工具类中 `@SuppressWarnings("unchecked" / "rawtypes")`，用于抑制泛型警告

### 1.5 OpenAPI 注解规范

**所有 Controller 和方法必须有 OpenAPI 注解**，以便 Knife4j 自动生成 API 文档。

```java
// 类级别：@Tag
@Tag(name = "门户文章", description = "门户文章的增删改查操作接口")
@RestController
@RequestMapping("/portal/article")
public class PortalArticleController extends BaseController {

    // 方法级别：@Operation + @Parameter
    @Operation(summary = "获取文章详情", description = "根据文章ID获取文章详细信息")
    @GetMapping("/{id}")
    public AjaxResult getInfo(
        @Parameter(description = "文章ID") @PathVariable Long id) {
        // ...
    }

    @Operation(summary = "分页查询文章")
    @GetMapping("/list")
    public TableDataInfo list(ArticleQuery query) {
        // ...
    }
}
```

**必须项**:

- ✅ 每个 `@RestController` 必须有 `@Tag(name = "...", description = "...")`

- ✅ 每个接口方法必须有 `@Operation(summary = "...")`

- ✅ `@PathVariable` / `@RequestParam` / `@RequestBody` 关键参数建议加 `@Parameter(description = "...")`

### 1.6 Controller 层规范

**返回格式统一**：使用 [AjaxResult](file:///workspace/moyun-project-document/moyun-server/src/main/java/com/moyun/core/base/AjaxResult.java) 和 [TableDataInfo](file:///workspace/moyun-project-document/moyun-server/src/main/java/com/moyun/core/base/TableDataInfo.java)：

| 场景                  | 返回类型                            | 示例                                |
| ------------------- | ------------------------------- | --------------------------------- |
| 普通操作（新增/修改/删除/单条查询） | `AjaxResult`                    | `return AjaxResult.success(data)` |
| 分页列表                | `TableDataInfo`                 | `return getDataTable(list)`       |
| 文件下载                | `void`（写 `HttpServletResponse`） | 见 CommonController                |

**权限注解使用**:

- 管理端接口：`@PreAuthorize("@ss.hasPermi('system:user:list')")`

- 匿名接口：`@Anonymous`（需配合 `SecurityConfig` 的放行规则）

- 角色校验：`@PreAuthorize("@ss.hasRole('admin')")`

**方法命名建议**:

| HTTP 方法                 | 语义     | 推荐方法名前缀                             |
| ----------------------- | ------ | ----------------------------------- |
| `GET /xxx/list`         | 分页查询列表 | `list` / `page`                     |
| `GET /xxx/{id}`         | 单条查询详情 | `getInfo` / `get`                   |
| `POST /xxx`             | 新增     | `add` / `create`                    |
| `PUT /xxx`              | 修改     | `edit` / `update`                   |
| `DELETE /xxx/{id}`      | 删除单条   | `remove` / `delete`                 |
| `DELETE /xxx/batch`     | 批量删除   | `removeBatch` / `batchDelete`       |
| `POST /xxx/{id}/action` | 特殊业务操作 | `toggleLike` / `publish` / `setTop` |

### 1.8 Mapper / Repository 层规范

- **必须继承** **`BaseMapper<T>`**：自动获得基础 CRUD

- **禁止在 Mapper 中写复杂业务逻辑**：复杂查询放到 Service

- **禁止手写 JDBC**：统一走 MyBatis-Plus

### 1.9 实体类规范

**继承链约定**:

- 有 `createBy/createTime/updateBy/updateTime/remark/params` 字段的实体：**继承 BaseEntity**

- 树形结构实体：**继承 TreeEntity**

- 其他：独立 POJO + `@Data`

**字段注解要求**:

- 主键：`@TableId(type = IdType.AUTO)` 或对应业务策略

- 逻辑删除：`@TableLogic` + 字段 `delFlag`

- 非表字段：`@TableField(exist = false)`

- 日期时间：`@JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss")`

**禁止事项**:

- ❌ 禁止在 Entity 中写业务计算方法

- ❌ 禁止直接返回 Entity 给前端（必须转 VO）

### 1.10 VO / DTO / Query 区分

| 类型                             | 用途           | 位置              | 示例                  |
| ------------------------------ | ------------ | --------------- | ------------------- |
| **VO** (View Object)           | 响应给前端展示      | `domain/vo/`    | `CmsArticleVO`      |
| **DTO** (Data Transfer Object) | 前端请求体 / 内部传输 | `domain/dto/`   | `ArticlePublishDTO` |
| **Query**                      | 查询条件对象       | `domain/query/` | `ArticleQuery`      |

> 三者严禁混用：Controller 入参 → DTO；Service 内查询 → Query；Controller 返回 → VO。

### 1.11 异常与日志规范

**异常抛出**：优先抛出 `ServiceException(msg)` / 自定义业务异常，**禁止**吞掉异常。

**日志级别约定**:

```java
log.error("XX失败, userId={}", userId, e);   // 异常（附异常对象）
log.warn("XX条件不满足, data={}", data);      // 可恢复问题
log.info("用户{}登录成功", username);          // 业务流程记录
log.debug("queryParams={}", params);         // 调试信息（仅 dev 启用）
```

> **禁止**：`e.printStackTrace()`、`System.out.println()`、拼接字符串打日志（使用 `{}` 占位符）。

### 1.12 异步 / 定时任务规范

**`@Async` 硬约束（v13.4 新增，来自真实缺陷）**：

- **`@Async` 方法禁止在同一个 Bean 内被调用**（`this.method()` 会绕过 Spring AOP 代理 →
  方法**静默退化为同步执行**：不报错、不打日志，只是悄悄变慢，而文档仍在宣称它是异步的）。
  必须抽到**独立 Bean**，由调用方注入后调用（范例：`ToolCallLogWriter`、`AiTaskAsyncExecutor`）。
- 带线程池的写法同样受约束：`@Async("xxxExecutor")` 一样会因自调用失效。
- **方法名含 `Async` 就必须真异步**：若确为同步实现，请改名（去掉 `Async`）——命名与行为不一致
  会让后来者据此做出错误判断（真实案例：`ToolRegistry#logToolCallAsync` 长期是同步的）。
- **结构守卫**：`AsyncSelfInvocationGuardTest` 会扫描 `src/main/java` 全量源码，
  发现任何 `@Async` 方法被同类调用即**测试失败**。新增 `@Async` 方法时无需额外写测试，但不得自调用。

**异步执行器硬约束（v13.5 新增，来自真实缺陷）**：

- **禁止 `CompletableFuture.runAsync/supplyAsync` 不传执行器**：默认执行器是
  `ForkJoinPool.commonPool()`——**全 JVM 共享、并行度只有 CPU-1**，还同时服务 `parallelStream()`。
  几个长任务就能占满它，症状是**全站并行任务一起变慢/卡住**，而日志里没有任何"线程池满"的痕迹
  （真实案例：架构图对话 `latch.await(5, MINUTES)`、知识库向量化、VIP 统计落库共 4 处）。
- **禁止裸 `new Thread()` / `Executors.new*`**：线程无命名（排障无法定位）、队列无上限（可无限堆积）、
  无优雅停机（关停时任务被硬杀）、并发数不受控。确属"池化会改变语义"的场景
  （worker loop、子进程排水线程等），必须在守卫白名单中登记并写明理由。
- **按语义选池，不要找"万能池"**：

  | 场景 | 用哪个 Bean | 关键参数 |
  |---|---|---|
  | SSE / 分钟级长任务（架构图对话、工作流流式、语音面试回合） | `sseStreamExecutor` | queue=0、**满即拒绝**（AbortPolicy） |
  | 短任务（统计落库、元数据同步） | `applicationTaskExecutor` | 队列 500 + CallerRuns |
  | 知识库文档处理（PDF/切片/向量化） | `knowledgeProcessExecutor` | 有界队列 50 |
  | 工作流并行分支 | `workflowParallelExecutor` | 有界队列 100 |
  | 非关键且允许丢弃（会话摘要预生成） | `contextSummaryExecutor` | 队列 200、**满则丢弃并告警** |

- **拒绝必须让调用方看见**：长任务池用 AbortPolicy（不排队、满即拒绝）时，调用方**必须捕获
  `RejectedExecutionException`** 并给客户端明确错误（本项目三处 SSE 均已如此）。
  若用 CallerRuns 把 5 分钟长任务降级到 Tomcat 请求线程，比拒绝更糟。
- **结构守卫**：`ExecutorGovernanceGuardTest` 扫描 `src/main/java` 全量源码——
  `runAsync/supplyAsync` 未传执行器、或出现白名单外的裸线程创建，即**测试失败**。
- **定时任务（Quartz）硬约束（v13.7 新增，来自真实缺陷）**：

  - **JobStore 必须用 JDBC 集群模式**（`core.config.QuartzConfig`）：显式 `SchedulerFactoryBean`
    注入**物理主库** `masterDataSource`（**不得**用 `@Primary` 的 `dynamicDataSource` 路由数据源，
    否则启动抛 `No local DataSource found`），`isClustered=true` + `instanceId=AUTO`
    + 集群内 `instanceName` 一致。**禁止**退回 `RAMJobStore`——多实例会重复执行
    （实测：两个 RAMJobStore 实例 7 秒触发 16 次，集群形态 8 次）。
  - **启动注册禁止 `scheduler.clear()`**：JobStore 是多实例**共享**状态，清库会删掉别的实例
    正在用的任务。启动同步必须是**幂等同步**（缺则建 / 变了才重建 / 一致不动 / 孤儿仅在
    `sys_job` 出现过的组内清理）。
  - **任务必须幂等**：Quartz 只保证"同一触发器同一时刻只在一个节点执行"，**不保证"只执行一次"**
    （故障转移、misfire 补偿都可能重放）→ 业务侧仍要有幂等键（如定时记账的
    `sched:{taskId}:{execDate}`）。
  - `@Scheduled` 注解任务不走 Quartz，**必须自加 `DistributedLockUtil` 互斥**。
  - Quartz 属性键注意层级：`batchTriggerAcquisitionMaxCount` 是 **scheduler** 级
    （`org.quartz.scheduler.*`），写到 `org.quartz.jobStore.*` 会启动失败。
  - `qrtz_*` 表带**物理外键**（触发器子表 → `qrtz_triggers` → `qrtz_job_details`）：
    清理/删除数据必须**子表在前**。

- 异步任务框架：`ext/job` 模块的 `SysJob`；一次性异步任务用
  `AsyncManager.me.execute(task)`（两者都不得绕开上面的执行器约束）。

### 1.13 配置文件规范

- 所有自定义配置项：声明在 `application.yml` 的 `ruoyi:` / `minio:` 等前缀下

- 敏感信息（账号/密码/密钥）：禁止硬编码，必须走 `${}` 占位符 + 环境变量 / VM options

- 多环境区分：`application-dev.yml` / `application-prod.yml`

#### 1.13.1 外部通道「就绪判定」规范（硬约束）

**不得用「Bean 是否存在」判断"外部通道是否可用"。**
Spring Boot 的自动装配条件通常比直觉宽松，**Bean 存在 ≠ 配置完备**。已发生的真实事故（邮件链路）：

- `MailSenderAutoConfiguration` 的装配条件只有 `spring.mail.host`（或 `jndi-name`），**不校验 password**；
  而 `application-dev.yaml` 的 host 是固定值 → `JavaMailSender` **恒存在** →
  三处 `mailSender == null` 的"未配置"兜底**全是死代码**：请求会真的去连 SMTP 拿 535，
  最终把"**服务端未配置**"报成"**请检查邮箱地址**"（误导用户，也误导排查方向）。
  回归测试：`MailSenderAutoConfigurationConditionTest`。

**正确做法**：

1. **就绪判定收敛到一个组件**（单一事实来源），调用点只问"是否就绪 / 原因是什么"，
   不各自判断。既有范例：`core/mail/MailChannelStatus`、`core/sms` 下 `AliyunSmsSender.isChannelNotConfigured`。
2. 判定依据是**配置项本身**（host/username/password、accessKey/secret/signName/templateCode 等）；
   占位值（`todo-`、`admin123`、`moyun-dev-`）一律等同"未配置"。
3. **未就绪 → 明确失败**（拒绝执行 + 可操作文案）。**禁止**伪装成功
   （如 `success=true` + `simulated=true`）或静默降级。确有联调需要时，必须与真实通道
   **同名对称**地提供 mock 实现（如 `MockSmsSender`、`MockPayoutChannel`），
   并在日志显式标注"资金/消息未实际发出"。
4. **认证类错误与用户输入类错误必须分开报**：如把 `MailAuthenticationException`
   与"收件人地址错误"区分开，不要把服务端配置问题写成"请检查你的邮箱地址"。
5. **生产必须强制关闭 mock**：参照 `PayProperties.init()`（强制 `wechat/payout.mock-enabled=false`）
   与 `ConfigWiringValidator`（prod 下短信 mock 未关闭即阻断启动）。
6. 对外通道的健康检查开关（如 `management.health.mail.enabled`）默认关闭，
   确认凭据可用后再显式打开——否则健康检查会因认证失败整体 DOWN，掩盖 MySQL/Redis 的真实故障。

3. 定期检查 `EXPLAIN` 和 Druid 慢查询监控

**慢查询规避**:

### 2.7 事务规范

**使用方式**:

```java
@Transactional(readOnly = true)              // 读多写少的查询
public List<PortalArticle> listArticles() { ... }

@Transactional(rollbackFor = Exception.class) // 多步写入
public void publishArticle(Long id) { ... }
```

**注意事项**:

- `@Transactional` 必须标注在 public 方法上

- 不要在 Controller 层加事务，必须放到 Service 层

- 同类内部调用（`this.method()`）会绕开 AOP，导致事务失效

- 长事务严禁出现，事务内部避免 HTTP 调用、锁等待

**并发更新规范（硬约束，来自真实事故）**：

- **禁止"读出来 → 改字段 → 写回"的覆盖式更新**（read-modify-write）。两个并发事务会各自读到同一旧值，
  后写者覆盖先写者 → **丢更新**。必须改为**单条原子 SQL**：
  `UPDATE t SET a = f(a), b = g(a) WHERE ...`（让 InnoDB 行锁串行化），或条件更新 + 校验影响行数。
  真实事故：VIP 续费两笔订单并发 → 用户付两次只得一期（已修，见报告六附录 I-5）。
- **不要在事务内部用分布式锁来"解决"丢更新**。锁在方法返回时释放，而事务提交发生在其**之后**
  → 第二个事务仍会读到旧快照，丢更新依旧存在，只是更难发现。要么把锁提到事务**之外**
  （包住 `transactionTemplate`/`@Transactional` 边界），要么改用上面的原子 SQL。
- **`UPDATE ... SET` 的赋值顺序有语义**：MySQL 从左到右求值，后面的表达式会读到前面
  **已更新**的列值。若 `b` 需要用到 `a` 的旧值，必须把 `a` 写在**后面**；写反不报错，只会静默产生错误数据。
  典型：`SET start_time = GREATEST(COALESCE(expire_time, NOW()), NOW()), expire_time = DATE_ADD(start_time, ...)`
  ——这里 `expire_time` 用的是**旧值**（因为它排在后面），这正是本项目的会员卡续期写法，
  且已有真库回归测试锁定（`VipGrantCardDbTest`）。
- **"影响行数为 0"能否当作"记录不存在"要看驱动语义**：Connector/J 默认 `useAffectedRows=false`
  → 返回**匹配行数**（matched rows），只要 `WHERE` 命中就 ≥1。若将来有人打开 `useAffectedRows=true`，
  所有"0 行 = 不存在"的判据都会失效，需同步回归。

- **"改字段"的接口禁止用 `updateById(整表实体)` 写回整表**（v13.1 新增，来自真实资金事故）。
  `updateById` 会把实体里所有非 null 字段一起写进 `SET`，其中**可能包含余额、版本号等"别人负责维护"的列**。
  正确做法：用 `LambdaUpdateWrapper` 做**列级 UPDATE**，只列本次真正要改的业务属性列，
  并永久排除：① 由其他链路原子维护的资金列（`balance`）；② 并发控制列（`version`）；
  ③ 归属与状态列（`user_id`/`status`）。
  真实事故：记账账户"改属性/归档"把并发记账的余额写回旧值（流水 +50、余额没变），
  并把 `version` 写回旧值破坏 `WHERE version = ?` 乐观锁（已修，见报告六附录 K）。
  > 注意：**"写前重新读一次最新值"不构成防护** —— 它只能防住调用方传入的陈旧值，
  > 防不住"读之后、写之前"这段时间里**别人已提交**的写入（TOCTOU）。判断是否为资金缺陷，
  > 要看 **SET 列集合里有没有资金列**，而不是看有没有重读。

- **并发更新后必须验证测试装置本身有效**：涉及并发的修复，回归测试要**先证明它能抓到旧缺陷**
  （临时还原旧实现 → 测试必须失败），再宣布修好。否则容易得到"假绿/假红"
  （案例：曾用 `@SpyBean` 拦 Mapper 试图制造交错，实测根本没插进读写之间）。

- **缓存/共享存储必须按用户隔离**（v13.2 新增，来自真实安全缺陷）。
  凡是缓存**完整响应体/用户数据**的地方（语义缓存、结果缓存、导出缓存…），
  键与"扫描/模糊匹配范围"都必须带 **userId 命名空间**，且 `userId` 为空时**不查也不写**（fail-closed）。
  真实事故：AI 网关语义缓存键为 `ai2:cache:{scene}:{md5(input)}`、语义扫描为 `ai2:cache:{scene}:*`，
  都不区分用户 → 只要场景打开 `enable_cache`，A 用户的响应（简历/财务/面试等私有内容）
  就可能作为 B 用户的命中结果返回（精确命中或余弦 >0.95 命中）。**已修，见报告六附录 L**。
  > 注意"当时没开所以没泄漏"不构成豁免：开关是后台可改字段，**等于把雷留在代码里**。
  > 若确有可跨用户共享的公共数据，应显式声明作用域（如 `cache_scope=global`），
  > 而**不是**默认共享。

  **属投产初始化脚本，会清空同名表，严禁在已有数据的库上重复执行**）

- `init-sql/moyun-db-dml-init.sql`：基础初始化数据（单文件 70 条 INSERT）

- `init-sql/moyun-menu-redo.sql`：菜单初始化（`TRUNCATE` + 显式 `menu_id` 全量重插，
  用于保证投产环境菜单 id 可复现；仅初始化执行一次）

- `increment-sql/YYYYMMDD-NN-{功能名}.sql`：存量库增量脚本（日期 8 位 + 当日两位序号 + 功能名，
  如 `20260925-01-portal_user唯一索引升级与存量清洗.sql`；同日多个脚本按序号递增）

**禁止的 DDL（必须评审）**:

- 大表（> 100 万行）的 ALTER TABLE：MySQL 5.x 会锁表；8.x 需评估

- 变更主键 / 唯一索引 / 外键结构

- 重命名表或列

- 删除生产列 → 改为 `del_flag` 软删除后观察 1\~2 个版本

### 2.9 数据库安全

- 生产库账号与应用账号分离：应用账号只有 `SELECT/INSERT/UPDATE/DELETE`

- 敏感字段加密：密码用 BCrypt，身份证/手机号用 `@Sensitive` 脱敏

- 备份策略：每日全量 + binlog 增量，备份异地保存

- 严禁在 `.sql` 文件中写入真实生产数据

### 2.10 建表自检清单

## 3 代码安全规范

### 3.1 安全架构总览

本项目基于 Spring Security 6.3.1 构建**双 SecurityFilterChain** 认证体系：

| 安全域     | 请求前缀                                                           | 认证方式                   | 入口配置                 |
| ------- | -------------------------------------------------------------- | ---------------------- | -------------------- |
| **管理端** | `/system/*`、`/monitor/*`、`/tool/*`、`/cms/*`、`/job/*`、`/file/*` | JWT Token (Bearer xxx) | SecurityConfig       |
| **门户端** | `/portal/*`（**不含** `/portal/admin/**`）                          | JWT Token              | PortalSecurityConfig |
| **后台管理接口** | `/portal/admin/**`（名义属门户前缀，实际**归核心链**）                            | Admin JWT Token        | SecurityConfig       |

**用户对象**：

- 管理端：`LoginUser`（实现 `UserDetails`）

- 门户端：`PortalLoginUser`（实现 `UserDetails`）

> 以上两个 User 对象是 Security 框架内部使用的特殊类，**禁止使用** **`@Data`** **替换其手写方法**。

#### 3.1.1 双链重叠路径的硬约束（v13.6 新增，来自真实缺陷）

`/portal/admin/**` **同时被两条链匹配**（核心链经 `SecurityConfig#shouldApplyTo` 显式包含；
门户链经 `securityMatcher("/portal/**")`），谁生效**只取决于链顺序**。因此：

- **`@Order` 必须标在 `@Bean` 方法上**（核心链 `@Order(1)`、门户链 `@Order(2)`）。
  实测把 `@Order` 标在 `@Configuration` **类上不生效**——链顺序会退化为注册顺序，
  于是"哪条链管后台接口"变成偶然。
- **两条链对 `/portal/admin/**` 都必须 fail-closed**（`authenticated()`），**禁止写 `permitAll`**
  ——包括"反正轮不到这条链"的写法。真实教训：门户链上那句 `permitAll` 长期是死规则，
  但只要顺序一翻转，它立刻变成**匿名可进后台接口**（已在测试中实证：匿名请求
  `HTTP 200` 直达一个漏注解的后台端点）。
- 顺序被改动的后果必须是**响亮的失败**（拒绝所有人），不能是**无声的漏洞**（放行匿名）。

#### 3.1.2 后台接口权限（`/portal/admin/**`）

- 链级只保证"持有合法 admin token"；**权限粒度必须由每个端点的 `@PreAuthorize` 决定**
  （方法级或类级）。
- **结构守卫**：`PortalAdminAuthorizationGuardTest` 在运行期用 `RequestMappingHandlerMapping`
  枚举 `/portal/admin/**` 下的真实端点，缺 `@PreAuthorize` 即**测试失败**；
  同时锁定"该前缀由核心链处理"与"匿名访问被拒（401）"。

### 3.2 认证与授权

#### 3.2.1 权限注解使用

| 注解                                             | 作用               |
| ---------------------------------------------- | ---------------- |
| `@PreAuthorize("@ss.hasPermi('xxx:yyy:zzz')")` | 按钮级权限校验（需配置菜单权限） |
| `@PreAuthorize("@ss.hasRole('admin')")`        | 角色级校验            |
| `@Anonymous`                                   | 允许匿名访问（白名单）      |

**禁止行为**:

- ❌ 禁止在生产环境用 `permitAll()` 通配放行整段路径（如 `/**`）

- ❌ 禁止把敏感接口（用户列表、订单明细）标记为 `@Anonymous`

**必须行为**:

- ✅ 所有写操作（新增/修改/删除）必须带权限注解

- ✅ 管理端 Controller 的读接口必须带权限注解

- ✅ **`/portal/admin/**` 的每个端点都必须带权限注解**（链级只校验"已登录的 admin"，
  不区分权限；漏注解即任意 admin 账号可调用）。由 `PortalAdminAuthorizationGuardTest` 强制。

- ✅ 确需匿名的接口必须用 `@Anonymous` 显式标注，同时补充在 SecurityConfig 白名单里

#### 3.2.2 Token 管理

- 管理端：`TokenService`（基于 JJWT）

- 门户端：`PortalTokenService`（基于 JJWT）

- 存储：Redis（key：`login_tokens:{uuid}` / `portal_tokens:{uuid}`）

**Token 安全**:

- 密钥 (`jwt.secret`) 严禁硬编码，必须通过环境变量注入（`${JWT_SECRET:...}`）

- 密钥长度 ≥ 256 bits（HMAC-SHA256 要求）

- HTTP Header 传输，禁止放在 URL QueryString

- 前端：Token 存储于 `localStorage` 或 `Pinia store`，不得放 Cookie（除非 HttpOnly + Secure）

#### 3.2.3 密码安全

- 密码存储算法：**BCrypt**（`PasswordEncoder` 的实现）

- 密码字段必须：`@JsonIgnore`（响应时不返回）+ 数据库仅存 hash（长度 ≥ 100）

- 注册/登录密码：前端 `jsencrypt` RSA 加密传输，后端解密后再 BCrypt 校验

- **严禁**：任何日志打印明文密码、任何接口返回密码

### 3.3 输入校验与注入防护

#### 3.3.1 XSS（跨站脚本）攻击防护

- 全局机制：FilterConfig + `XssFilter`（如启用）

- 富文本输出必须经过 HTML 转义 / 白名单过滤

- 禁止直接拼接 HTML 字符串到响应（前端 `v-html` 必须先过滤）

#### 3.3.2 SQL 注入防护

- ✅ 必须使用 MyBatis-Plus `#{param}` 占位符（参数预编译）

- ✅ 动态查询使用 `LambdaQueryWrapper`（无字符串拼接）

- ❌ 严禁 `${param}` 字符串拼接 SQL（除非必须做动态表名，此时须加严格白名单校验）

- ❌ 严禁直接把前端参数拼接到 `ORDER BY` / `LIMIT`，必须在 Service 层做枚举映射

**`${}` 模板变量的信任契约（v13.8 新增，来自真实缺陷）**：

`${}` 是**文本替换**，安全性完全取决于"内容是谁写的"。本项目现有 24 处 `${}` **全部登记在册**
（`MapperTemplateGuardTest` 强制；新增 `${}` 必须先说明信任来源，否则测试失败），三类各自的口径：

| 类别 | 谁能写 | 保护机制 |
|---|---|---|
| `${params.dataScope}`（9 处） | **只有 `DataScopeAspect`** | 切面写**受信键** `params[trustedDataScope]`；`SqlTemplateGuardInterceptor` 在 SQL 渲染前把它复制到 `${}` 读取的 `params[dataScope]`，**没有受信键就清空**（客户端 `?params[dataScope]=...` 一律丢弃并告警） |
| `${params.orderByColumn}` / `${params.isAsc}`（14 处） | 查询对象自身 | 入参须继承 `PageDomain`（setter 白名单：列名 `^[a-zA-Z][a-zA-Z0-9_]{0,63}$`、方向 asc/desc）；map 形态另有拦截器 fail-closed 兜底 |
| `${sql}`（1 处，代码生成器建表） | 后端按表元数据拼装 | 管理端专用功能，DDL 无法参数化；**不得**把用户输入接进该路径 |

- ⚠️ **禁用 `MapperMethod.ParamMap` 上取不存在的键**：它覆写了 `get()`，会抛
  `BindingException: Parameter 'x' not found`（写拦截器/工具类时用 `containsKey` 守卫）。
- ⚠️ **拦截 `${}` 必须在 BoundSql 渲染之前**：`InnerInterceptor#beforeQuery` 拿到的 `BoundSql`
  已经完成 `${}` 替换（改参数无效）；应挂在 `Executor` 上作为**最外层插件**。

#### 3.3.3 命令注入 / 路径遍历防护

- 文件名必须清理 `../`、`\0`、控制字符

- 文件类型必须校验 MIME + 实际内容字节头

- 文件大小限制在前端 + 后端双重校验

- 上传目录必须与代码执行目录严格隔离

### 3.4 敏感信息与数据脱敏

`@Sensitive(desensitizedType = DesensitizedType.XXXX)` 注解用于字段级脱敏：

| 类型             | 示例                   |
| -------------- | -------------------- |
| `MOBILE_PHONE` | `138****1234`        |
| `EMAIL`        | `ab****@example.com` |
| `ID_CARD`      | `3301**********1234` |
| `PASSWORD`     | `********`           |

**必须脱敏的字段**：手机号、邮箱、身份证号、银行卡号、密码、住址、真实姓名

**日志脱敏**：日志中禁止打印完整 Token、密码、手机号、身份证

### 3.5 防重放 / 防重复提交 / 限流

#### 3.5.1 `@RepeatSubmit`（防重复提交）

适用于**写操作接口**（下单、支付、发布文章、点赞）：

```java
@RepeatSubmit(interval = 5000, message = "{repeat.submit.message}")
@PostMapping
public AjaxResult add(@RequestBody ArticlePublishDTO dto) { ... }
```

#### 3.5.2 `@RateLimiter`（接口限流）

适用于高频公开接口（注册、登录、搜索、文章列表）：

```java
@RateLimiter(key = "portal_article_list", time = 60, count = 100, limitType = LimitType.IP)
@GetMapping("/list")
public TableDataInfo list() { ... }
```

| `LimitType` | 含义         | 适用场景         |
| ----------- | ---------- | ------------ |
| `DEFAULT`   | 全局 key 限流  | 后台管理通用接口     |
| `IP`        | 按客户端 IP 限流 | 门户公开接口、注册/登录 |
| `USER`      | 按用户 ID 限流  | 写操作接口        |

#### 3.5.3 幂等性要求

以下接口必须实现幂等：

- 支付/订单类（防止重复扣款）

- 批量删除（重复调用不报错）

- 文件上传（重复上传不产生重复文件）

### 3.6 越权访问防护

#### 3.6.1 水平越权（用户只能操作自己的数据）

必须校验：当前登录用户是否拥有该资源的所有权。

```java
@DeleteMapping("/article/{id}")
public AjaxResult remove(@PathVariable Long id) {
    Long currentUserId = SecurityUtils.getLoginUser().getPortalUser().getId();
    PortalArticle article = portalArticleService.getById(id);
    if (!article.getAuthorId().equals(currentUserId) && !isAdmin()) {
        return AjaxResult.error(403, "无权操作");
    }
    portalArticleService.removeById(id);
    return success();
}
```

#### 3.6.2 垂直越权（普通用户不能调用管理员接口）

- 管理端接口必须带 `@PreAuthorize("@ss.hasPermi(...)")`

- 严禁在门户端 `@Anonymous` 路径下出现管理功能

#### 3.6.3 统一异常处理

所有鉴权失败 / 参数异常 / 业务异常统一走 `GlobalExceptionHandler`，返回结构化 `AjaxResult`：

```json
{ "code": 401, "msg": "未登录或 Token 已过期" }
{ "code": 403, "msg": "无权操作该资源" }
{ "code": 404, "msg": "资源不存在" }
{ "code": 500, "msg": "服务器内部错误" }
```

**严禁**在异常信息中暴露堆栈、SQL 语句、表结构、内部路径等。

### 3.7 接口日志与操作审计

#### 3.7.1 `@Log` 注解

关键写操作接口必须标注，用于记录到 `sys_oper_log` 表：

```java
@Log(title = "文章管理", businessType = BusinessType.INSERT)
@PreAuthorize("@ss.hasPermi('cms:article:add')")
@PostMapping
public AjaxResult add(@RequestBody PortalArticle article) { ... }
```

#### 3.7.2 登录日志

登录/退出行为必须落到 `sys_login_infor`，包含 IP、浏览器、操作系统、登录结果。

### 3.8 文件与资源安全

**硬性规则**:

- 允许的扩展名白名单（`jpg/png/gif/mp4/pdf/docx`），且做 MIME + 文件头双重校验

- 文件大小上限：单文件 ≤ 10MB（头像 ≤ 2MB），由 `application.yml` 配置

- 文件存储：默认 MinIO，严禁写回 `src/main/resources`

- 文件 URL：签名 URL 或带时间戳的短链

**文件下载前必须做权限校验**（只能下载自己上传的文件）。

### 3.9 前端安全（与本规范第 4 节呼应）

| 风险     | 规避方案                                      |
| ------ | ----------------------------------------- |

### 3.11 常见漏洞与处置

| 漏洞类型   | 典型场景                                     | 处置方式                                            |
| ------ | ---------------------------------------- | ----------------------------------------------- |
| SQL 注入 | `SELECT * FROM t WHERE name = '${name}'` | 改为 `#{name}` 或用 QueryWrapper                    |
| 越权访问   | 删除文章时未校验 `authorId`                      | 查询当前用户 + 对比所有者                                  |
| 暴力破解   | 登录接口无限次尝试                                | `@RateLimiter(limitType=IP, count=5, time=300)` |
| 敏感信息泄漏 | 响应体返回 password 字段                        | `@JsonIgnore` + `@Sensitive(PASSWORD)`          |
| 任意文件上传 | 上传 `.jsp` / `.exe` 文件                    | 扩展名白名单 + MIME + 文件头三重校验                         |
| SSRF   | 后台文件上传支持任意 URL                           | URL 协议白名单（仅允许 http/https）                       |
| 并发下单   | 重复点击造成多扣费                                | `@RepeatSubmit` + 数据库乐观锁 / Redis 分布式锁           |

**跨端硬约束（v13.10 新增，来自真实缺陷）**：

- **禁止在小程序可达的代码路径里使用 DOM API**（`document`、`window`、`HTMLCanvasElement`、
  `querySelector`）。小程序**没有 DOM**：这类代码在 H5 能跑，在小程序端**静默失败**。
- **条件编译 `// #ifdef H5` 只能用于"平台确有差异"之处，不能用来掩盖"某端根本没实现"**。
  真实案例：收银台二维码 `renderQr` 整体包在 `#ifdef H5` 内、异常又被 `catch` 吞掉 →
  小程序端**从不渲染二维码**，界面只剩"请使用微信扫一扫"的空框，且无人察觉。
  正解是用跨端 API 写同一套实现（`uni.createCanvasContext`，见 `src/utils/qrcode.js`）。
- **canvas 画二维码**：`qrcode` 只深引用纯计算模块（无 `fs`/canvas 依赖）+ 自行 `fillRect`；
  **禁止** `QRCode.toCanvas`（依赖 DOM）与 `from 'qrcode'`（Node 入口会把 `fs`/`stream` 打进小程序包）。

#### 4.4.1 页面顶部栏与布局规范（门户端统一标准）

**适用范围**：moyun-portal 所有内容型页面（列表页、详情页、发布/编辑页、个人中心页）。

**背景**：历史页面顶部栏风格混乱——有的用面包屑、有的用"返回 XXX"按钮、有的中央显示页面名称、有的配 Hero 区大标题，导致视觉不统一且信息重复。本规范以文章模块（ArticleDetailPage / ListPage）为参考标准统一收敛。

**① 顶部栏结构（强制统一）**

所有页面顶部栏必须采用以下结构，禁止自行发挥：

```vue
<!-- 吸顶面包屑栏 -->
<div
  class="border-b sticky top-0 z-30 backdrop-blur-sm py-3"
  style="background-color: var(--theme-surface); border-color: var(--theme-border);"
>
  <div class="max-w-7xl mx-auto px-4 sm:px-6 lg:px-8 flex items-center justify-between gap-4">
    <Breadcrumb :items="breadcrumbs" />
    <!-- 右侧操作按钮（可选，无则留空占位） -->
    <div class="flex items-center gap-2">
      <slot name="actions" />
    </div>
  </div>
</div>
```

**② 禁止的顶部栏写法**

| 禁止写法                            | 原因                     | 正确做法                |
| ------------------------------- | ---------------------- | ------------------- |
| 中央显示页面名称（如 `<span>面试经验</span>`） | 与面包屑最后一项重复；移动端挤压操作按钮空间 | 用面包屑，最后一项自动加粗显示当前页名 |
| "返回 XXX" 文字按钮                   | 与浏览器/路由后退重复，且丢失导航上下文   | 用面包屑，支持点击任意层级跳转     |
| 仅显示 `<ArrowLeft>` 图标无面包屑        | 无法体现层级位置，SEO 无结构化数据    | 用面包屑                |

**③ Hero 区规范（强制精简）**

- **禁止**：Hero 区放置与顶部栏重复的大标题（如顶部栏已有面包屑显示"面试经验"，Hero 区再放一个 `<h1>面试经验</h1>`）

- **禁止**：Hero 区仅放"标题 + 一句废话"而无任何交互元素（搜索框、按钮等），此类空洞 Hero 应整体删除

- **允许**：Hero 区包含搜索框、筛选器、CTA 按钮等实质交互时，可保留 Hero 容器，但删除重复的大标题，仅保留交互元素

- **推荐**：列表页的搜索/筛选功能可直接放在顶部工具栏中，不单独占 Hero 区

**④ 面包屑数据规范**

```ts
// 列表页示例
const breadcrumbs = computed(() => [
  { label: '面试指南', path: '/interview' },
  { label: '面试经验' },  // 最后一项无 path，自动加粗为当前页
]);

// 详情页示例
const breadcrumbs = computed(() => [
  { label: '面试指南', path: '/interview' },
  { label: '面试经验', path: '/interview/experiences' },
  { label: experience.value?.title || '详情' },  // 当前详情标题
]);

// 发布/编辑页示例

  { label: '面试指南', path: '/interview' },
  { label: '面试经验', path: '/interview/experiences' },
```

注意：`Breadcrumb` 组件会自动在最前面补"首页"项，业务 items 不应包含"首页"。

**⑤ 主内容区域宽度规范**

所有页面主内容区域必须统一使用：

```vue
<div class="max-w-7xl mx-auto px-4 sm:px-6 lg:px-8">
```

- 响应式内边距必须完整：`px-4 sm:px-6 lg:px-8`，不可缺失断点

**⑥ 移动端兼容**

- 面包屑组件已内置移动端优化（首页仅显示图标、文字 `truncate` 截断）

### 4.5 API 请求规范（核心）

#### 4.5.1 管理端请求封装

**入口**：`src/utils/request.js`（Axios 实例 + 请求/响应拦截器）

**API 文件约定**（每个模块一个文件，放在 `src/api/{module}/`）：

```js
// src/api/cms/article.js
import request from '@/utils/request';

export function listArticle(query) {
  return request({ url: '/cms/article/list', method: 'get', params: query });
}

export function getArticle(id) {
  return request({ url: '/cms/article/' + id, method: 'get' });
}

export function addArticle(data) {
  return request({ url: '/cms/article', method: 'post', data: data });
}

export function updateArticle(data) {
  return request({ url: '/cms/article', method: 'put', data: data });
}

export function delArticle(id) {
  return request({ url: '/cms/article/' + id, method: 'delete' });
}

export function delArticleBatch(ids) {
  return request({ url: '/cms/article/batch', method: 'delete', data: ids });
}
```

**命名规范**：`listXxx / getXxx / addXxx / updateXxx / delXxx / delXxxBatch`，与后端 Controller 方法对齐。

#### 4.5.2 门户端请求封装

**入口**：`src/api/client.ts`（统一 Axios 实例 + 响应类型）

```ts
// src/api/client.ts
import axios from 'axios';

const client = axios.create({
  baseURL: import.meta.env.VITE_API_BASE || '/api',
  timeout: 15000,
  headers: { 'Content-Type': 'application/json' }
});

// 请求拦截器：注入 Token（从 Pinia store 读取）
// 响应拦截器：统一处理 401 跳转登录、403 提示、500 友好错误

export default client;
```

#### 4.5.3 请求方法 & HTTP 语义

| 操作   | 方法                  | 后端约定                     | 前端示例                     |
| ---- | ------------------- | ------------------------ | ------------------------ |
| 列表查询 | `GET /xxx/list`     | 返回 `{ rows, total }`     | `listArticle(params)`    |
| 单条查询 | `GET /xxx/{id}`     | 返回 `{ code, data, msg }` | `getArticle(id)`         |
| 新增   | `POST /xxx`         | body 传对象                 | `addArticle(payload)`    |
| 修改   | `PUT /xxx`          | body 传对象（含 id）           | `updateArticle(payload)` |
| 单条删除 | `DELETE /xxx/{id}`  | 路径参数                     | `delArticle(id)`         |
| 批量删除 | `DELETE /xxx/batch` | body 传 `[1,2,3]`         | `delArticleBatch(ids)`   |

#### 4.5.4 Token 管理

- 管理端：Pinia `user.js` + `auth.js` 工具

- 门户端：`Pinia user store` + `localStorage`（key：`portal_token`）

- 所有请求：`Authorization: Bearer {token}`

- 401 响应：自动清理 Token + 跳登录 + 回跳原页面

- 严禁在 URL QueryString / 日志 / 页面文案中暴露 Token

### 4.13 前端安全

- [ ] `v-html` 内容必须经过 DOMPurify / HTML 白名单过滤（富文本除外，且需过滤）

- [ ] Token 仅存 `localStorage` 或 Pinia store，不得存明文密码、身份证

- [ ] 登录/支付/删除前加 `ElMessageBox.confirm` 二次确认

- [ ] 所有表单输入做前端基本校验，后端做最终校验

- [ ] URL 参数（`route.query.id` / 动态路由）必须校验合法性，禁止直接拼业务逻辑

- [ ] `npm audit` 定期扫 CVE

### 4.14 开发流程规范

```
需求评审 → 接口约定（OpenAPI）→ 前后端并行开发
            ↓
前端：定义 TS 类型 / API 方法 → 组件 & 页面 → 自测 + Mock
            ↓
联调（前端 .env.development 代理到后端 8080）
            ↓
PR / Code Review → 合并 main → 预发布验证 → 生产发布
```

**Commit 信息（与后端一致）**：`feat(portal)`、`fix(cms)`、`refactor(admin)`、`chore`、`docs`

### 4.15 自测清单

- [ ] 页面能正常打开（无白屏、控制台错误）

- [ ] 列表查询 / 新增 / 修改 / 删除全部跑通

- [ ] 分页、排序、筛选正常工作

- [ ] 权限按钮按角色正确显示 / 隐藏

- [ ] 登录、退出、Token 过期场景均已测

- [ ] 移动端 / 不同分辨率下布局不崩

- [ ] `npm run build:prod` / `npm run build` 成功

- [ ] 门户端 `vue-tsc -b` 零类型错误

- [ ] `npm run lint` 无 Error 级别问题

- [ ] 敏感字段（手机号、邮箱）已脱敏

### 4.16 禁止事项

- ❌ 禁止在前端组件中直接引入 jQuery 或通过 `$` 操作 DOM

- ❌ 禁止把后端返回的 raw HTML 直接 `v-html` 插入（富文本除外，且需过滤）

- ❌ 禁止硬编码 API 路径：所有请求必须走 `src/api/` 下的方法

- ❌ 禁止使用 `any`（门户端）：所有变量必须有明确类型或 `unknown` + 类型守卫

- ❌ 禁止在前端存储真实密码 / 支付信息

- ❌ 禁止 `.env.production` 中写入任何生产密钥

- ❌ 禁止直接引入完整 Element Plus / Lodash（按需自动导入已配置）
