# 全端·多环境配置与运维手册 V1.0

> 适用：`moyun-server`（后端）、`moyun-portal`（门户 Web）、`moyun-admin-vue`（管理后台）、`moyun-ledger-app`（记账 App / uni-app 三端）
> 目标：**一份代码 + 环境变量/Profile 驱动**，三种场景切换只改少数文件，做到彻底环境隔离。
> 编制：2026-10-03（配合收费功能下线 v14.68~v14.71）

---

## 0. 核心设计原则（先看这一节）

| 原则 | 说明 |
|---|---|
| **同源优先** | 前端一律请求**相对路径 `/api`**，由 dev server（开发/穿透）或 Nginx（UAT/生产）反代到后端 8080 ⇒ **没有跨源，就没有 CORS，也不用为每个域名改后端白名单** |
| **模式即环境** | 前端用 Vite `--mode`（`.env.<mode>`）区分环境；后端用 `SPRING_PROFILES_ACTIVE`（`application-<profile>.yaml`）区分环境 |
| **敏感项只走环境变量** | 数据库密码、Redis 密码、第三方 Key、`JWT_SECRET` 等**不写进仓库**，用环境变量注入（`application.yaml` 已支持 `${ENV:默认}` 占位） |
| **mock 一律关** | 收费功能已整体下线；任何 mock 开关在 UAT/生产必须为 `false` |
| **fail-closed** | 生产未配置的跨源、支付、实名等一律**拒绝**而不是放行（沿用现有守卫思路） |
| **改动面最小** | 换环境只动：① `.env.<mode>` 1~2 个值；② 后端 `application-<profile>.yaml` 的库/Redis/第三方；③ Nginx 反代目标 |

## 1. 三种场景总览

| 维度 | ① 完全本地开发（Win10 四端本机） | ② 内网穿透（natapp 等） | ③ 生产（云服务器 + 自有域名） |
|---|---|---|---|
| 后端 | `http://localhost:8080`，profile=`dev` | 同 ①（穿透只暴露前端） | 云主机 + `profile=prod`，只监听内网/127.0.0.1，由 Nginx 反代 |
| 门户 portal | `https://localhost:3000`（自签） | `npm run dev:natapp` → 公网域名 | `npm run build` → Nginx 静态托管 |
| 记账 App(H5) | `http://localhost:5173` | `npm run dev:h5:natapp` → 公网域名 | `npm run build:h5` → 同域 `/ledger/` |
| 记账 App(小程序) | 微信开发者工具 + 勾"不校验合法域名"，接口填**局域网 IP** | 同 ①（小程序不能走前端代理） | 正式 https 域名 + 小程序后台配置 request 合法域名 |
| 管理后台 | `http://localhost:80/88`（Vue CLI dev） | 可选（一般不穿透） | `npm run build:prod` → Nginx `/admin/` |
| 接口地址 | `/api`（代理） | `/api`（代理，已剥 Origin） | `/api`（Nginx 反代） |
| CORS | 不需要（同源） | 不需要（代理已剥 Origin/Referer） | 不需要（同源反代，`allowed-origins` 留空 fail-closed） |
| HTTPS | 门户自签证书 | 无（http 域名） | 正式证书（Let's Encrypt / 云厂商免费证书） |
| 数据库/Redis | 本机 MySQL 8 / Redis | 同 ① | 云 RDS + 云 Redis（或自建 + 定期备份） |

## 2. 各端环境差异明细（现在有什么、改什么）

### 2.1 后端 `moyun-server`

**现有文件**

| 文件 | 作用 |
|---|---|
| `application.yaml` | 公共项 + `spring.profiles.active: dev` 默认值 + 环境变量占位 |
| `application-local.yaml` | 纯本机零依赖联调（最小化） |
| `application-dev.yaml` | 本地开发（含 LAN/CORS 便利开关、mock） |
| `application-uat.yaml` | **本次新增**（由 dev 派生，与生产同构、数据独立） |
| `application-prod.yaml.example` | 生产模板（**需复制为 `application-prod.yaml`**） |

**切换方式（关键）**

```bash
# 本地
mvn -o spring-boot:run                     # 默认 dev
# UAT（必须同时带 dev：公共非敏感项来自 dev）
java -jar moyun-server.jar --spring.profiles.active=uat,dev
# 生产
java -jar moyun-server.jar --spring.profiles.active=prod,dev
```

> ⚠️ **不能只写 `prod`/`uat`**：数据源、Druid、日志等公共项在 `application-dev.yaml`，单独激活会启动失败（`application.yaml` 注释已记录此坑）。

**每个环境要改的项（UAT/生产）**

| 项 | 键 | 生产建议 |
|---|---|---|
| 数据库 | `spring.datasource.url/username/password` | 云 RDS，独立账号，最小权限 |
| Redis | `spring.data.redis.host/password/database` | 云 Redis + 密码 + 独立 db |
| 跨源 | `moyun.cors.allowed-origins` | **留空**（同源反代）；确需跨源才填精确域名 |
| 站点地址 | `moyun.site.url`（门户 SEO/分享） | 正式 https 域名 |
| 文件存储 | MinIO/OSS endpoint、bucket、AK/SK | 独立 bucket，私有读写 + 签名 URL |
| 邮件 | SMTP host/user/pass | 独立发信账号（避免用个人邮箱） |
| AI | 大模型 API Key、ASR/TTS Key | 独立 Key + 配额告警 |
| 日志 | `logging.level.*`、日志文件路径 | `INFO`（排查期临时 `DEBUG`），保留 30 天 |
| 敏感密钥 | `JWT_SECRET` 等 | **环境变量注入**，不入库不入仓 |

```bash
# 生产启动示例（敏感项走环境变量）
export SPRING_PROFILES_ACTIVE=prod,dev
export SPRING_DATASOURCE_PASSWORD='***'
export SPRING_DATA_REDIS_PASSWORD='***'
export JWT_SECRET='***'
nohup java -Xms1g -Xmx2g -jar moyun-server.jar > /dev/null 2>&1 &
```

### 2.2 门户 `moyun-portal`

**现有 + 新增 env（均只改 `VITE_API_BASE_URL` 与 `VITE_SITE_URL`）**

| 文件 | `VITE_API_BASE_URL` | `VITE_SITE_URL` | 用途 |
|---|---|---|---|
| `.env.development` | `/api` | 空 | `npm run dev`（localhost:3000，https 自签） |
| `.env.natapp`（新增） | `/api` | 空 | `npm run dev:natapp`（穿透联调） |
| `.env.uat`（新增） | `/api` | `https://uat.example.com` | `npm run build:uat` |
| `.env.production` | `/api` | **必填真实域名** | `npm run build` |

**dev proxy（`vite.config.ts`）**：`/api` → `http://localhost:8080`（含 `ws:true` 透传语音面试 WebSocket）；`/moyun` → MinIO `127.0.0.1:9001`。

**生产**：`npm run build`（构建期守卫要求 `VITE_SITE_URL` 为真实 https）+ Nginx 静态托管 + `/api` 反代。

### 2.3 管理后台 `moyun-admin-vue`

沿用 RuoYi 约定，**已具备三套**，无需改动：

| 文件 | `VITE_APP_BASE_API` | 构建命令 |
|---|---|---|
| `.env.development` | `/dev-api` | `npm run dev` |
| `.env.staging` | `/stage-api` | `npm run build:stage`（**本手册将其对应 UAT**） |
| `.env.production` | `/prod-api` | `npm run build:prod` |

> 三种前缀都需在**该环境的 Nginx** 里反代到后端 8080（见 §4 第 2 段）。

### 2.4 记账 App `moyun-ledger-app`

| 文件 | `VITE_API_BASE_URL` | 用途 |
|---|---|---|
| `.env.development` | `http://localhost:8080` | H5 本地直连 + **小程序真机**（可换为局域网 IP） |
| `.env.natapp` | `/api` | `npm run dev:h5:natapp`（穿透，同源代理） |
| `.env.uat`（新增） | `/api` | `npm run dev:h5:uat` / `build:h5:uat` |
| `.env.production` | `/api`（**本次改为同源**） | `npm run build:h5` / `build:mp-weixin` |

**构建期守卫（`vite.config.js`）**：生产构建接受 ① 同源相对路径 `/api`（推荐，Nginx 反代）或 ② `https://` 绝对地址；**拒绝**空值、`http`、`localhost/127.0.0.1`、`example.com` 占位。

**小程序端注意**：微信小程序**不支持相对路径**，必须用 `https` 绝对域名并加入小程序后台 request 合法域名（真机调试阶段可勾"不校验合法域名"）。

## 3. 场景①：完全本地开发（Win10，四端都在本机）

**前置**：JDK 21、Maven、Node 18+、MySQL 8、Redis、MinIO（可选）

| 步骤 | 命令 | 端口 |
|---|---|---|
| 1. 数据库 | 导入 `moyun-server/src/main/resources/init-sql/moyun-db-ddl.sql` + `moyun-db-dml-init.sql` + `moyun-menu-redo.sql` + `moyun-portal-category-redo.sql` | 3306 |
| 2. 后端 | `cd moyun-server && mvn -o spring-boot:run`（profile=dev） | 8080 |
| 3. 门户 | `cd moyun-portal && npm i && npm run dev` | **3000（https 自签）** |
| 4. 管理后台 | `cd moyun-admin-vue && npm i && npm run dev` | 80/88 |
| 5. 记账 H5 | `cd moyun-ledger-app && npm i && npm run dev:h5` | 5173 |
| 6. 记账小程序 | 微信开发者工具导入 `dist/dev/mp-weixin`；接口地址用**局域网 IP**（`ipconfig` 查），勾"不校验合法域名" | — |

**联网后 IP 变了怎么办**：只改 `moyun-ledger-app/.env.development` 的 `VITE_API_BASE_URL=http://192.168.x.x:8080`；后端 dev profile 的 `moyun.cors.allow-lan-dev-origins: true` 会精确放行私网 IP 字面量 Origin，无需额外配置。

## 4. 场景②：内网穿透（natapp 等）

**只穿透前端端口**，后端不出网 —— 这样无需为公网域名维护 CORS。

| 步骤 | 操作 |
|---|---|
| 1. 启后端 | 同场景① 第 2 步（后端仍在 127.0.0.1:8080） |
| 2. 启前端（带 natapp 模式） | 门户：`npm run dev:natapp`（3000）<br>记账 H5：`npm run dev:h5:natapp`（5173） |
| 3. 配置 natapp | 隧道指向 **3000**（门户）或 **5173**（记账 H5），得到公网域名如 `http://xulin.mynatapp.cc` |
| 4. 访问 | 浏览器开该域名即可（前端请求同源 `/api`，由 dev server 转发到 8080） |

**为什么这样就行（两个坑已处理）**

| 坑 | 现象 | 处理 |
|---|---|---|
| **Private Network Access** | `blocked by CORS policy: … more-private address space 'loopback'` | 前端走同源 `/api` 代理，**浏览器不再直连 `localhost:8080`**（[moyun-ledger-app/vite.config.js](../moyun-ledger-app/vite.config.js) 注释已写明） |
| **后端 CORS fail-closed** | 换 `/api` 后仍 `403 Forbidden`（`moyun.cors.allow-lan-dev-origins` 只放行私网 IP 字面量，公网域名不在内） | 代理转发时**剥掉 `Origin`/`Referer`**（无 Origin 即非跨源请求，正常放行） |

> 若确实要**直连公网域名**访问 API（例如第二条隧道给 8080、或小程序真机用公网地址），才需要后端显式放行：
> `moyun.cors.allowed-origins: http://xulin.mynatapp.cc`（或环境变量 `CORS_ALLOWED_ORIGINS`）。

## 5. 场景③：生产环境（云服务器 + 自有域名）

### 5.1 拓扑

```
                    ┌──────────────── 云服务器（单机起步） ────────────────┐
用户 ──https──> Nginx │  /            → portal 静态（dist）                │
                      │  /admin/      → admin-vue 静态（dist）            │
                      │  /ledger/     → ledger H5 静态（dist）            │
                      │  /api/        → 反代 127.0.0.1:8080（剥前缀）     │
                      │  /moyun/      → 反代 MinIO/OSS（图片）            │
                      └──────────────┬───────────────────────────────────┘
                                     │ 内网
                        Spring Boot 8080 ── MySQL/Redis（云 RDS/Redis）
```

### 5.2 部署步骤（首次）

| # | 步骤 | 命令/要点 |
|---|---|---|
| 1 | 服务器初始化 | 创建非 root 用户、SSH 密钥登录、防火墙只开 80/443/22 |
| 2 | 域名与备案 | 域名实名 + **ICP 备案**（个体户可备非经营性）+ **公安联网备案**（上线 30 日内）；主页显著位置标注备案号 |
| 3 | 安装运行时 | JDK 21、Nginx、MySQL 8（或用云 RDS）、Redis |
| 4 | 建库 | 按顺序导入 §3 的 4 个 SQL；**再执行** [moyun-archive-20261003-pay-vip.sql](../moyun-server/src/main/resources/init-sql/moyun-archive-20261003-pay-vip.sql)（收费表归档 + 菜单字典下线） |
| 5 | 后端打包 | `cd moyun-server && mvn -o -B clean package -DskipTests` → `target/*.jar` |
| 6 | 后端配置 | 复制 `application-prod.yaml.example` → `application-prod.yaml`，改库/Redis/域名/第三方；敏感项走环境变量 |
| 7 | 后端启动 | `SPRING_PROFILES_ACTIVE=prod,dev java -jar moyun-server.jar`（建议 systemd 托管 + 开机自启） |
| 8 | 门户构建 | `VITE_SITE_URL=https://你的域名 npm run build` → `dist/` |
| 9 | 后台构建 | `npm run build:prod` → `dist/` |
| 10 | 记账 H5 构建 | `npm run build:h5` → `dist/build/h5` |
| 11 | 小程序构建 | `npm run build:mp-weixin` → 微信开发者工具上传审核（接口域名须 https 且已加白名单） |
| 12 | Nginx 配置 | 见 §5.3 |
| 13 | HTTPS | 证书签发（Let's Encrypt/云免费证书）+ 80→443 跳转 |
| 14 | 验证 | 门户首页/登录/面试/简历链路；`/admin/` 可登录；记账 H5 可登录；小程序真机可用 |

### 5.3 Nginx 关键片段（同源反代，**无需 CORS**）

```nginx
server {
    listen 443 ssl http2;
    server_name 你的域名;
    ssl_certificate     /etc/nginx/ssl/fullchain.pem;
    ssl_certificate_key /etc/nginx/ssl/privkey.pem;

    # 门户（SPA：history 路由回落 index.html）
    root /var/www/portal;
    location / { try_files $uri $uri/ /index.html; }

    # 管理后台（RuoYi，子路径部署）
    location /admin/ { alias /var/www/admin/; try_files $uri $uri/ /admin/index.html; }

    # 记账 H5（子路径部署，需与 vite base 一致）
    location /ledger/ { alias /var/www/ledger/; try_files $uri $uri/ /ledger/index.html; }

    # 后端 API（剥离 /api 前缀）
    location /api/ {
        proxy_pass http://127.0.0.1:8080/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        # 语音面试：WebSocket 升级（ASR/TTS 流式）
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 600s;
        client_max_body_size 20m;   # 简历/音频上传
    }

    # 图片（MinIO/OSS 私有读 + 代理）
    location /moyun/ { proxy_pass http://127.0.0.1:9001/; }
}
```

> **子路径部署注意**：admin 与 ledger 若部署在 `/admin/`、`/ledger/`，需在对应构建里设置 `base`（Vite `base: '/ledger/'`；RuoYi 用 `publicPath`）。若嫌麻烦，可用**独立子域名**（`admin.域名`、`ledger.域名`）——此时 `base` 保持 `/`，配置更简单。

### 5.4 UAT 与生产的差异（建议）

| 项 | UAT | 生产 |
|---|---|---|
| 域名 | `uat.example.com` | `www.example.com` |
| 库/Redis | UAT 独立实例 | 生产实例 + 每日备份 + 只读从库（可选） |
| 数据 | 可用脱敏数据；可开调试日志 | 真实数据；`INFO` 日志；禁用一切 mock |
| 发布节奏 | 随时 | 灰度：先备份 → 停服/热更 → 冒烟 → 观察 |
| 备份 | 可选 | **每日自动备份 + 保留 30 天**（`mysqldump` + 对象存储） |
| 监控 | 基础可用性 | 进程存活、磁盘、JVM、接口错误率、慢 SQL 告警 |

## 6. 环境切换对照表（改什么，一眼看全）

| 想做什么 | 要改的文件 | 要执行的命令 |
|---|---|---|
| 本地 → 穿透 | 无（已备好 `.env.natapp`） | `npm run dev:natapp`（门户）/ `npm run dev:h5:natapp`（记账） |
| 穿透 → UAT | `.env.uat` 里的 `VITE_SITE_URL` | `npm run build:uat`（门户）/ `build:h5:uat`（记账）/ `build:stage`（后台） |
| UAT → 生产 | ① `.env.production` 的 `VITE_SITE_URL`（门户）<br>② `application-prod.yaml`（后端库/Redis/第三方）<br>③ Nginx `server_name`/证书/root 路径 | 见 §5.2 第 5~13 步 |
| 换服务器/域名 | 只改 Nginx + `.env.production` 的 `VITE_SITE_URL` + 后端 `moyun.site.url` | 重新构建前端 + 重载 Nginx |
| 换数据库 | 只改 `application-<profile>.yaml` 的 datasource（或环境变量） | 重启后端 |
| 后端接第三方 | 改对应 profile 的 key（优先环境变量） | 重启后端 |
| 小程序接口域名变更 | `.env.production` 的 `VITE_API_BASE_URL` + 微信后台 request 合法域名 | `npm run build:mp-weixin` + 重新上传 |

**环境隔离边界（保证不串环境）**

| 隔离手段 | 说明 |
|---|---|
| 前端 | 一个 `mode` 一个 `.env` 文件，构建产物里**只含该环境的值**（无运行时回落，避免"构建了 A 环境却连 B 环境"） |
| 后端 | 一个 profile 一个 yaml；敏感项只从环境变量注入 |
| 数据库 | 三套独立库/账号，UAT 与生产**不共享实例** |
| 存储 | UAT/生产独立 bucket 与前缀 |
| 域名/证书 | 独立域名；生产仅 443 对外 |

## 8. 常见问题（FAQ）

| 现象 | 原因 | 处理 |
|---|---|---|
| 穿透后请求报 `more-private address space 'loopback'` | 浏览器直连 `localhost:8080`（Chrome PNA） | 用 `npm run dev:h5:natapp`（同源 `/api` 代理） |
| 换 `/api` 后仍 `403 Forbidden` | 后端 CORS 精确白名单 fail-closed，公网域名不在内 | 代理已剥 `Origin`/`Referer`（已实现）；或后端加白名单 |
| 登录 403 但验证码 200 | 同上（POST 才带 Origin） | 同上 |
| 生产构建失败提示 `VITE_SITE_URL`/`VITE_API_BASE_URL` | 构建期守卫（防占位域名上线） | 填真实值；同源方案填 `/api` |
| 小程序真机请求失败 | 用了相对路径 / 未配合法域名 / http | 用 https 绝对域名 + 后台加白名单（调试期可勾"不校验合法域名"） |
| 页面 https、图片 http 被拦 | 混合内容 | 走 `/moyun/` 图片代理（门户已实现） |
| 单独 `--spring.profiles.active=prod` 启动失败 | 公共项在 dev profile | 用 `prod,dev` |
