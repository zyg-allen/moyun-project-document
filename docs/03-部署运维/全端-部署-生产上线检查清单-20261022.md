## 2. dev 与 prod 差异

| 项 | dev | prod |
|---|---|---|
| 激活方式 | 默认 `dev` | `SPRING_PROFILES_ACTIVE=prod` |
| 配置来源 | application-dev.yaml | application-prod.yaml（`*.example` 为模板，真文件 gitignore） |
| 数据源账号 | root/123456 默认值 | 必须 env 注入（`MYSQL_*`），无默认 |
| Redis | 无密码默认 | 必须 env 注入（`REDIS_*`） |
| JWT | 固定开发密钥，可启动 | `TOKEN_SECRET` 必填，且 admin/portal 建议分离 |
| MinIO | 默认 `admin123` | 必须真实凭据 + `MINIO_ACCESS_URL` 公网地址 |
| Druid 控制台 | 开启 | **默认关闭**（并有 prod 硬拦截） |
| Knife4j/Swagger | 开启 | **关闭**（并有 prod 硬拦截） |
| 支付/短信 | 可 mock | 默认 `false`（需显式开启并配凭据） |
| 前端 | `/dev-api` 代理 | 后台 `/prod-api`、App `/api`（由 Nginx 反代） |

## 5. 上线前必须完成（P0）

1. **MinIO 必须真的在跑**：本机 9000/9001 当前**无监听**。启动 MinIO 并确认 bucket 初始化成功，否则凭证/商品图上传全部失败。
2. **密钥**：`TOKEN_SECRET`/`TOKEN_ADMIN_SECRET`/`TOKEN_PORTAL_SECRET` 用强随机串（≥64 字符、三者不同）；`MOYUN_SECURITY_CERT_NO_ENCRYPT_KEY` 等加密密钥必须为真实值。
3. **数据库账号**：生产不得用 root；建最小权限账号，并先执行 `init-sql` + 全部 `increment-sql`。
4. **Nginx + HTTPS**：按 `deploy/nginx.conf.example` 落地 gzip/缓存/安全头/反代；小程序要求 HTTPS 合法域名。
5. **健康检查放行**：`/actuator/health` 当前被安全链拦截，需给监控放行（仅 GET，限内网），否则无法做存活探测。
6. **匿名字典确认**：prod 下 `/portal/ledger/dict/**` 返回 401。若 App 未登录时需要字典（例如登录页分类兜底），需要在该路径加 `permitAll`；若确认只在登录后使用，可保持现状。

## 6. 建议（P1）

- **移除 `spring.profiles.group.prod=dev` 继承**：让 prod 完全自包含，避免 dev 配置再次覆盖生产开关（本次只对排障端点做了硬拦截，其他 dev 项仍可能覆盖）。
- 清理 `PortalSecurityConfig` 中已无对应 Controller 的 `/portal/debug/**` 放行。
- Druid `filters: stat,wall,slf4j` 的 wall 过滤器对每条 SQL 做语法检查，高并发下有额外开销，生产可只保留 `stat`。
- 管理后台首屏仍为 556KB gzip，Element Plus 按需后可到 ~300KB。
- 建立备份：MySQL 每日全量 + binlog；MinIO 桶每日同步到异地；备份文件不与被备份数据同盘。
