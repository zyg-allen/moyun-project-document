# 接口治理：零调用接口下线流程

> 适用：`moyun-server` 977 个接口的持续收敛
> 依据：评审 V2「接口规模远超产品面」的结论

---

## 一、数据来源

| 来源 | 用途 |
|---|---|
| `GET /cms/monitor/api-stats?limit=300` | 调用排行（方法 + URI 归一化计数） |
| `GET /cms/monitor/api-stats/zero-call` | 启动至今从未被调用的接口 |
| `logs/api-zero-call-YYYY-MM-DD.log` | 每日 09:30 自动落盘的零调用清单 |
| 后台：系统监控 → 接口统计 | 可视化查看与搜索 |

> 计数在内存中，**服务重启清零**。因此判断“零调用”必须跨重启累计观察，不能只看一天。

---

## 二、判定规则

一个接口可以下线，需要同时满足：

1. 连续 **14 天**零调用（跨至少 2 次重启）；
2. 三端源码全局搜索无引用（App / Admin / Portal）；
3. 不是以下类型：
   - 第三方回调（支付、微信、短信回执）；
   - 开放 API（带 API Key / 对外文档）；
   - 定时任务或内部服务通过 HTTP 调用；
   - 运维/监控/健康检查入口。

---

## 三、下线步骤

```
1. 导出零调用清单
   GET /cms/monitor/api-stats/zero-call

2. 人工确认（按模块）
   - 搜前端：grep "路径片段" app/admin/portal
   - 搜后端：是否有 Service 内部调用、@Scheduled 调用
   - 问自己：是否给外部合作方用过

3. 标记 @Deprecated（保留 2 周）
   - Controller 方法加 @Deprecated + Javadoc 注明替代接口
   - 日志打一次 warn：deprecated api called

4. 观察 2 周
   - 若 api-stats 仍为 0 → 删除
   - 若出现调用 → 回滚标记，查调用方

5. 删除
   - Controller 方法
   - Service 接口 + 实现
   - 前端 API 封装（若还有）
   - 更新文档/权限点
```

---

## 四、禁止事项

- ❌ 仅凭一天统计就删接口；
- ❌ 删除支付/微信回调、开放 API；
- ❌ 删除前不搜三端源码；
- ❌ 保留“空实现”假装接口还在（会误导调用方）。

---

## 五、当前进展（2026-10-27）

| 项 | 数值 |
|---|---|
| 接口总数 | 977 |
| 已删除旧接口 | 存钱 `/deposit`、`/fail` |
| 已删除前端死封装 | 5 个 |
| 写接口防护 | `@RepeatSubmit` / `@RateLimiter` 已覆盖记账与门户主要写接口 |
| 零调用报告 | 每日 09:30 自动生成 |

## 六、责任与节奏

- **每周一**：看一次零调用清单，标记本周候选；
- **每两周**：批量处理 `@Deprecated` 到期的接口；
- **每次发版**：新增接口必须同时登记权限点与契约测试。
