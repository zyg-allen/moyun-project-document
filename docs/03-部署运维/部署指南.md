## 一、环境准备

### 1.1 必需软件

| 软件 | 版本要求 | 说明 |
|------|----------|------|
| JDK | 21+ | Java 运行环境 |
| Node.js | 18+ | 前端构建工具 |
| MySQL | 8.0+ | 关系型数据库 |
| Redis | 6.0+ | **必需组件** — 登录态、验证码、限流、字典缓存 |
| Maven | 3.8+ | Java 项目构建 |
| Git | 最新版 | 版本控制 |

### 1.2 可选软件

| 软件 | 版本 | 说明 |
|------|------|------|
| MinIO | 最新版 | 对象存储（不装则降级为本地文件存储）|
| MongoDB | 6.0+ | 辅助中间件（可选，不影响核心功能）|
| Docker | 20+ | OJ 判题沙箱（不装则判题功能不可用，其他功能正常）|

### 1.3 Redis 必要性

> Redis 是**核心依赖**，不是可选组件。以下功能依赖 Redis：
> - 用户登录态（`login_tokens:{uuid}` / `portal_login_tokens:{uuid}`）
> - 图形验证码（`captcha_codes:{uuid}`，2 分钟过期）
> - 接口限流（`@RateLimiter`）
> - 防重复提交（`@RepeatSubmit`）
> - 密码错误锁定计数
> - 字典缓存

**没有 Redis → 系统完全不可用。**

### 1.5 JDK 21 环境排查（v10.0 P0-4 新增）

> **背景**：Spring Boot 3.3.2 强制要求 Java 21+，但开发机/服务器上常见 PATH 优先级问题导致 `java -version` 实际指向 Java 8，编译时报 "class file version 65.0" 等错误。本节给出排查方法。

**排查步骤**（PowerShell）：

```powershell
# 1. 检查当前 java 版本（必须显示 21+，不是 1.8）
java -version

# 2. 检查 JAVA_HOME 环境变量
echo $env:JAVA_HOME   # 应指向 JDK21 安装目录，如 D:\dev_en\JAVA21

# 3. 检查 PATH 中 java 的实际来源
where.exe java        # 第一个匹配项必须是 JDK21\bin\java.exe
where.exe mvn         # Maven 必须指向真实 Maven 安装目录，而非 C:\Windows\System32\mvn

# 4. 如果 mvn 指向 System32（损坏的 shim），用全路径执行
& "D:\dev_en\apache-maven-3.9.14\bin\mvn.cmd" -version
```

**修复方法**（Windows 开发机）：

```powershell
# 临时（仅当前会话生效）
$env:JAVA_HOME = "D:\dev_en\JAVA21"
$env:PATH = "$env:JAVA_HOME\bin;$env:PATH"

# 永久（写入用户环境变量，需重启 PowerShell）
[Environment]::SetEnvironmentVariable("JAVA_HOME", "D:\dev_en\JAVA21", "User")
[Environment]::SetEnvironmentVariable("PATH", "$env:JAVA_HOME\bin;" + [Environment]::GetEnvironmentVariable("PATH", "User"), "User")
```

**编译验证命令**（使用全路径 mvn + 临时 JAVA_HOME，已验证通过 1190 源文件 BUILD SUCCESS）：

```powershell
$env:JAVA_HOME = "D:\dev_en\JAVA21"
$env:PATH = "$env:JAVA_HOME\bin;$env:PATH"
cd d:\zyg_new_work\moyun-project-document\moyun-server
& "D:\dev_en\apache-maven-3.9.14\bin\mvn.cmd" clean compile -DskipTests
```

**生产环境部署注意**：
- 必须在生产服务器上安装 JDK 21（不是 JRE 21）
- `JAVA_HOME` 必须在系统级环境变量中配置（非用户级），确保 systemd/service 启动的 Java 进程也能读到
- Docker 部署使用 `eclipse-temurin:21-jdk-alpine` 或 `amazoncorretto:21-alpine` 基础镜像
- K8s 部署在 Pod spec 中显式设置 `JAVA_HOME=/usr/lib/jvm/java-21-amazon-corretto`

## 二、数据库初始化

### 2.1 创建数据库

```sql
CREATE DATABASE moyun-db DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
```

### 2.2 执行初始化脚本

**脚本目录**：`moyun-server/src/main/resources/sql/`

初始化已整合为 **DDL / DML 两个文件**（2026-08-20 拆分），按顺序执行即可：

```bash
cd moyun-server/src/main/resources/sql

# 1. 建表（157 张表，按业务模块分组：ai_* → gen_* → portal_* → qrtz_* → sys_* → 其他，含 DROP TABLE IF EXISTS）
mysql -u root -p moyun-db < moyun-db-ddl-202608201435.sql

# 2. 初始化数据（33 张含数据表，幂等：每表先 DELETE FROM 再 INSERT）
mysql -u root -p moyun-db < moyun-db-dml-202608201435.sql
```

> ⚠️ **注意**：
> - DDL 含 `DROP TABLE IF EXISTS`，会**重建表结构**；已有数据的库重跑 DDL 会清空数据，**仅适合全新初始化**。
> - DML 每表先 `DELETE FROM` 再 `INSERT`，**幂等可重复执行**。
> - `moyun-db-ddl-moyun-db-202608201435.sql` 为拆分前的整合源文件（归档留存），日常初始化不使用。
> - 后续表结构变更：在 DDL 文件对应模块末尾追加增量 `ALTER TABLE`，不改动原 `CREATE TABLE`。

### 2.3 验证数据库

```sql
USE moyun-db;
SHOW TABLES;  -- 应看到 sys_*/qrtz_*/act_*/portal_* 系列表

-- 验证 v6.7 审核字段

DESC portal_topic;      -- status 默认值应为 pending
DESC portal_column;     -- 应含 auditor_id / audit_remark / audit_time

-- 验证敏感词表

```

## 三、后端服务部署

### 3.1 配置文件说明

配置文件位于 `moyun-server/src/main/resources/`：

| 文件 | 用途 | 启动参数 |
|------|------|----------|
| `application.yaml` | 基础配置（所有环境共用） | 默认 |
| `application-dev.yaml` | 开发环境（环境变量回退） | `--spring.profiles.active=dev` |
| `application-local.yaml` | 本地开发（明文凭据，仅本机） | `--spring.profiles.active=local` |
| `application-prod.yaml.example` | 生产环境模板 | 复制为 `application-prod.yaml` 后使用 |

### 3.2 开发环境启动

```bash
cd moyun-server

# 方式一：本地 profile（零配置，明文凭据仅本机用）
mvn spring-boot:run -Dspring-boot.run.profiles=local

# 方式二：dev profile（通过环境变量注入凭据）
export MYSQL_PASSWORD=your_password
export TOKEN_SECRET=your-secret-key-at-least-64-chars-long-hs512
mvn spring-boot:run -Dspring-boot.run.profiles=dev
```

### 3.3 生产环境部署

```bash
# 1. 复制生产配置模板
cp application-prod.yaml.example application-prod.yaml

# 2. 通过环境变量注入凭据（切勿在配置文件中写明文）
export MYSQL_URL="jdbc:mysql://db-host:3306/moyun-db?useUnicode=true&characterEncoding=utf-8&useSSL=true&serverTimezone=Asia/Shanghai"
export MYSQL_USERNAME="moyun"
export MYSQL_PASSWORD="your_strong_password"
export REDIS_HOST="redis-host"
export REDIS_PASSWORD="your_redis_password"
export TOKEN_SECRET="openssl rand -base64 64 生成的密钥"
export DRUID_USERNAME="druid_admin"
export DRUID_PASSWORD="druid_strong_password"
export MINIO_ENDPOINT="http://minio-host:9000"
export MINIO_ACCESS_KEY="your_access_key"
export MINIO_SECRET_KEY="your_secret_key"
export MINIO_ACCESS_URL="http://minio-host:9000"

# 3. 打包并启动
mvn clean package -DskipTests
java -jar target/moyun-server-*.jar --spring.profiles.active=prod

# 4. 后台运行
nohup java -jar target/moyun-server-*.jar --spring.profiles.active=prod > logs/moyun-server.log 2>&1 &
```

### 3.4 验证后端

- 服务地址：http://localhost:8080
- Swagger 文档：http://localhost:8080/doc.html（生产环境通过 `KNIFE4J_PRODUCTION=true` 关闭）
- 健康检查：http://localhost:8080/actuator/health
- 默认账号：`admin` / `admin123`

## 四、门户前端部署（moyun-portal）

### 4.1 开发环境

```bash
cd moyun-portal
npm install        # 或 pnpm install
npm run dev        # 启动开发服务器，默认 3000 端口
```

环境变量（`.env.development`）：
```
VITE_API_BASE_URL=http://localhost:8080
```

### 4.2 生产环境构建

```bash
cd moyun-portal
npm install
npm run build      # 产物输出到 dist/
```

环境变量（`.env.production`）：
```
# 生产环境通过 Nginx 反向代理 /api → 后端 8080
VITE_API_BASE_URL=/api
```

### 4.3 Nginx 配置示例

```nginx
server {
    listen 80;
    server_name your-domain.com;

    # 门户前端静态资源
    location / {
        root /path/to/moyun-portal/dist;
        try_files $uri $uri/ /index.html;
    }

    # API 反向代理
    location /api/ {
        proxy_pass http://127.0.0.1:8080/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

## 七、常见问题

### 7.1 数据库连接失败

- 确认 MySQL 已启动
- 检查 `application-*.yaml` 中 `spring.datasource.url/username/password`
- 确认数据库 `moyun-db` 已创建

### 7.2 Redis 连接失败

- 确认 Redis 已启动：`redis-cli ping` 应返回 `PONG`
- 检查 Redis 密码配置

### 7.3 Token 相关报错

- 开发环境：`TOKEN_SECRET` 未设置会回退到 dev 默认密钥
- 生产环境：`TOKEN_SECRET` 未设置或长度不足 64 字符会 **fail-fast 拒绝启动**
- 生成密钥：`openssl rand -base64 64`

### 7.4 菜单不显示 / /getRouters 报错

- 确认 96 脚本已执行（菜单数据在 sys_menu 表）
- 确认 `sys_role_menu` 角色关联已建立
- admin 用户走 isAdmin 旁路，能看到所有菜单

### 7.5 逻辑删除失效

- 确认 `application-*.yaml` 中 `mybatis-plus.global-config.db-config.logic-delete-field` 为 `delFlag`
- 确认 `logic-delete-value` 为 `"2"`，`logic-not-delete-value` 为 `"0"`
- BaseEntity 的 `@TableLogic` 注解会覆盖全局配置，但全局配置需保持一致

### 7.6 Druid 监控页无法访问

- 地址：http://localhost:8080/druid/
- 凭据通过 `DRUID_USERNAME` / `DRUID_PASSWORD` 环境变量配置
- 生产环境 IP 白名单通过 `DRUID_ALLOW_IP` 配置（默认 127.0.0.1）

## 八、增量变更方式

初始化脚本已整合为 DDL/DML 两个文件，不再维护分阶段升级脚本。

后续表结构变更时：
- 在 `moyun-db-ddl-202608201435.sql` 对应业务模块末尾追加增量 `ALTER TABLE`（不改动原 `CREATE TABLE`）
- 数据变更在 `moyun-db-dml-202608201435.sql` 对应表追加幂等语句（`DELETE FROM` 后重新 `INSERT`，或 `UPDATE`）

> 已有数据库的环境：按需手动执行增量语句，或全量重建（先 DDL 后 DML，会清空并重建）。
