# 前台 Portal + Admin 管理页 · AI 自测指导文档

> **用途**：指导 AI（或人工）对 moyun-portal 及对应 admin 管理页做系统性自测
> **结构**：总（方法论）→ 分（逐模块自测卡）→ 总（验收清单）
> **核心原则**：每个页面必须形成「入口 → 操作 → 反馈 → 沉淀 → 再入口」闭环，且数据流转可追溯
> **配套**：`功能闭环自测文档.md`（业务闭环）+ 本文档（页面级流转）

# 第一部分 · 总：自测方法论

## 1.1 自测的五个维度

每个页面必须从五个维度验证：

| 维度      | 问题       | 验证方式        |
| ------- | -------- | ----------- |
| **入口**  | 用户怎么到这？  | 从首页/导航能自然到达 |
| **操作**  | 能做什么？    | 所有按钮/表单可用   |
| **反馈**  | 做完知道结果吗？ | 成功/失败都有提示   |
| **沉淀**  | 数据存哪了？   | 刷新后数据还在     |
| **再入口** | 下一步去哪？   | 有引导，不是死胡同   |

## 1.2 通用自测清单（每页必查）

### A. 入口与前置

| #   | 检查项   | 预期                  |
| --- | ----- | ------------------- |
| A1  | 路由可直达 | 直接输 URL 不白屏         |
| A2  | 未登录访问 | 需登录的跳登录页，带 redirect |
| A3  | 未实名访问 | 需实名的提示认证，可跳过则跳过     |
| A4  | 无权限访问 | 提示无权限，不报 500        |
| A5  | 返回上一步 | 有返回按钮或浏览器后退可用       |
| A6  | 面包屑正确 | 层级与导航一致             |

### B. 操作与接口

| #   | 检查项   | 预期               |
| --- | ----- | ---------------- |
| B1  | 列表加载  | 有 loading，失败有重试  |
| B2  | 分页    | 翻页正常，总数正确        |
| B3  | 筛选/搜索 | 条件生效，可清空         |
| B4  | 详情跳转  | 带 ID 跳转，详情数据正确   |
| B5  | 表单提交  | 校验前置，提交有 loading |
| B6  | 二次确认  | 删除/支付/发布有确认      |
| B7  | 接口失败  | 有错误提示，不白屏        |

### C. 反馈与状态

| #   | 检查项  | 预期          |
| --- | ---- | ----------- |
| C1  | 成功提示 | toast/弹窗明确  |
| C2  | 失败提示 | 说明原因，可操作    |
| C3  | 空状态  | 有引导，不是空白    |
| C4  | 加载状态 | 骨架屏/loading |
| C5  | 错误状态 | 网络错误有兜底     |

### D. 数据流转

| #   | 检查项   | 预期               |
| --- | ----- | ---------------- |
| D1  | 列表→详情 | 详情数据与列表一致        |
| D2  | 详情→操作 | 操作后详情刷新          |
| D3  | 操作→列表 | 返回列表数据更新         |
| D4  | 跨页数据  | query/store 传递正确 |
| D5  | 刷新恢复  | 刷新后状态保持（关键页）     |

### E. 特殊处理

| #   | 检查项    | 预期              |
| --- | ------ | --------------- |
| E1  | 异步任务   | 提交→轮询→完成，可刷新续轮询 |
| E2  | SSE 流式 | 分片到达即渲染，断开有提示   |
| E3  | 多轮对话   | 上下文保持，追问正常      |
| E4  | 长任务    | 有进度，可离开再回来      |
| E5  | 并发操作   | 防重复提交           |

## 1.3 数据流转的黄金法则

```
列表页（分页/筛选）
    ↓ 点击行 → 带 ID 路由跳转
详情页（加载详情数据）
    ↓ 操作按钮 → 弹窗/表单
弹窗/表单（提交）
    ↓ 成功后 → 刷新详情 + 提示
详情页（数据更新）
    ↓ 返回 → 列表页刷新
列表页（数据同步）
```

**铁律**：

1. 详情数据必须由 ID 重新拉取，不能只靠路由传参
2. 操作成功后，当前页数据必须刷新
3. 返回列表时，列表数据必须同步
4. 任何一步失败，都要有明确提示，不能静默

## 1.4 特殊场景处理规范

| 场景            | 规范                                                |
| ------------- | ------------------------------------------------- |
| **异步任务**      | 提交返回 taskId → 轮询状态 → 完成展示结果；刷新后 URL 带 taskId 可续轮询 |
| **SSE 流式**    | 事件分片到达即渲染；断开显示重连；错误显示原因                           |
| **多轮对话**      | 每轮带上下文；支持打断；支持结束                                  |
| **WebSocket** | 连接状态可见；断线重连；心跳保活                                  |
| **多轮查询**      | 分页游标正确；无重复/遗漏；总数一致                                |

## 附录：AI 自测执行指引

### AI 自测的执行顺序

```
1. 路由遍历：所有路由可直达（爬 sitemap）
2. 接口冒烟：所有 GET 接口返回 200
3. 主流程走查：按模块走核心流程
4. 边界测试：空数据/超长/特殊字符
5. 闭环验证：走完整用户旅程
```

### AI 自测的输出格式

每个页面输出：

```
页面：/interview/voice
状态：✅ 通过 / ⚠️ 部分通过 / ❌ 失败
问题：
  - [P0] 报告页无"去练习"入口
  - [P1] 刷新后会话丢失
证据：截图/接口返回/控制台日志
```

### AI 自测的局限

- 无法验证视觉细节（样式/动画）
- 无法验证真实语音（ASR/TTS 质量）
- 无法验证 LLM 输出质量
- 需人工复核主观项
