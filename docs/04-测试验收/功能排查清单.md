## 使用说明

### 链路结构

每条链路以"用户完成一个业务目标"为主线，串联前端页面 → API 接口 → 后端处理 → 数据变更：

```
链路名（目标）
├─ 节点1：前端操作 → 接口 → 后端处理 → 副作用
├─ 节点2：...
└─ 节点N：...
```

### 测试字段说明

| 字段 | 含义 |
|------|------|
| 节点编号 | L{模块}-{序号} |
| 节点描述 | 做了什么 |
| 前端/页面 | 在哪个页面/组件操作 |
| 接口 | 方法 + 路径 |
| 后端处理 | Controller → Service → Mapper 关键逻辑 |
| 副作用/数据变更 | DB 表变更、缓存、事件、通知等 |
| 业务规则/约束 | 校验、幂等、权限等 |
| 问题描述 | 已知或测试中发现的问题 |
| 测试是否通过 | ☐ 未测试 / ✅ 通过 / ❌ 失败 / ⚠️ 部分通过 |
| 关联 BUG | BUG-X |

### BUG 状态图例

| 图例 | 含义 |
|------|------|
| ✅ | 已修复 |
| ⚠️ | 仍存在 |
| 🔄 | 已变更（不再是原来的问题） |
| ❌ | 已移除（功能已删除） |
