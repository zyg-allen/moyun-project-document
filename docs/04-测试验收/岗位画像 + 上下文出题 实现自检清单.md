# 岗位画像 + 上下文出题 实现自检清单

**用途**：交给 Trae（或你自己）逐项检查当前实现是否符合“岗位画像 + 上下文出题”的设计方案。  
**对照标准**：基于“锚点题 + AI 出题”的混合策略。

**使用方式**：

- ✅ 已实现且符合设计
- ⚠️ 已实现但需要调整
- ❌ 未实现或缺失

## 一、岗位画像模块

### 1.1 岗位基础数据

| 检查项                                                  | 状态  | 说明/问题                    |
| ---------------------------------------------------- | --- | ------------------------ |
| 是否有多岗位分类（技术岗/公考/技能岗等）                                | ☐   |                          |
| 每个岗位是否有独立的 `scene` 标识（tech/gongkao/skill/management） | ☐   |                          |
| 岗位是否绑定了技能标签列表                                        | ☐   |                          |
| 岗位是否有难度等级（1-5）                                       | ☐   |                          |
| 岗位是否有默认题量配置                                          | ☐   |                          |
| 岗位是否有面试时长配置                                          | ☐   |                          |
| 岗位画像是否包含“能力模型”定义（如技术岗的“技术深度/逻辑表达/项目经验”）              | ☐   |                          |
| 岗位画像是否有对应的系统提示词模板                                    | ☐   | 技术岗、公考岗等不同 scene 是否有不同模板 |

**预期目标**：每个岗位有完整画像，作为出题和评分的“锚点”。

**检查命令**：

```sql
SELECT id, name, scene, difficulty, question_count, duration FROM portal_job_position;
SELECT p.name, COUNT(st.id) as skill_count FROM portal_job_position p
LEFT JOIN portal_position_skill ps ON p.id = ps.position_id
LEFT JOIN portal_skill_tag st ON ps.skill_tag_id = st.id
GROUP BY p.id;
```

### 1.2 岗位-题库关联（锚点题）

| 检查项                               | 状态  | 说明/问题             |
| --------------------------------- | --- | ----------------- |
| 每个岗位是否至少有 30-50 道锚点题              | ☐   |                   |
| 锚点题是否覆盖了该岗位的核心考察维度                | ☐   | 技术岗：八股/算法/项目/系统设计 |
| 锚点题是否已标记 `is_anchor = 1`          | ☐   |                   |
| 锚点题是否按难度分级（简单/中等/困难）              | ☐   |                   |
| AI 出题是否有“锚点题兜底”机制（AI 出题失败时降级到锚点题） | ☐   |                   |

**预期目标**：每个岗位有足够的锚点题作为面试“基准线”，AI 出题失败时有降级方案。
