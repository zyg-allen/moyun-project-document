# 记账 App · 存钱计划：日历标记 + 流水按需关联 设计方案

> 版本：V1.1（2026-10-26，替代 V1.0 的"强制转账/只进不出"方案）
> 变更：**不做任何拦截**；存入是否关联流水由用户选择；计划记录与资金账户解耦。

---

## 1. 设计原则（V1.1）

1. **用户主导**：每期"成功/失败/跳过"由用户自己标记，系统不替用户判断；
2. **关联可选**：记计划时可不关联流水、可关联已有流水、可现场创建一笔转账；
3. **账户只随流水动**：不关联就不动账户；关联后由流水驱动余额，计划侧不重复加钱；
4. **不拦截**：存钱账户可以正常支出/转出，最多在 UI 上提示"这是存钱账户"；
5. **提醒轻量**：到期只发站内消息（App 消息中心），复用现有本地/微信提醒，不做强制扣款。

---

## 2. 核心流程：一期记录的三种处理方式

用户在日历上点某一天 → 弹出该期面板，三个动作：

```
[ 标记已存 ]  [ 标记未完成 ]  [ 跳过 ]
      │
      └─ 已存时，再选资金处理方式：
           ① 不关联流水（仅打卡，账户不变）
           ② 关联已有流水（从当天/近 7 天的转账、支出里选）
           ③ 创建转账（现场填：从哪个账户 → 存钱账户）
```

### 方式①：不关联（纯打卡）

- `saving_record.status=1`，`transaction_id=null`；
- 账户余额不变；
- 列表标注「未关联流水」，可后续补关联。

**适用**：用户已经用别的 App/现金存了，只想打个卡。

### 方式②：关联已有流水

- 弹出流水选择器：默认按 `recordDate` 当天、金额接近本期目标、类型为 `transfer/expense` 过滤，可切换日期范围；
- 选中后：`transaction_id=该流水`，标记 `status=1`；
- 校验：
  - 流水属于当前用户；
  - 该流水**未被其他期关联**（`transaction_id` 唯一索引）；
  - 金额不要求相等，但若差异 > 20% 给出提示"金额与目标差异较大，确认关联？"。

**适用**：用户先在"记一笔"里做了转账，再回来记计划。

### 方式③：现场创建转账

- 内嵌小表单（不跳页）：
  - 转出账户（默认计划绑定的工资卡）
  - 转入账户（默认计划的存钱账户）
  - 金额（默认本期目标金额，可改）
  - 日期（默认本期 `recordDate`）
  - 备注（默认"存钱计划-第N期"）
- 保存：创建一条 `type=transfer` 流水（`account_id=source`，`target_account_id=savings`），同时回填 `transaction_id`；
- 复用现有转账逻辑，账户余额由转账自身更新，**计划侧不再加钱**。

**适用**：用户还没记账，想一步完成"存钱 + 记账"。

## 3. 数据模型（最小改动）

```sql
-- 计划：只作为"默认转账账户"的来源，可为空
ALTER TABLE ledger_saving_plan
  ADD COLUMN source_account_id  bigint NULL COMMENT '默认转出账户',
  ADD COLUMN savings_account_id bigint NULL COMMENT '默认存入账户';

-- 记录：流水关联可选
ALTER TABLE ledger_saving_record
  ADD COLUMN transaction_id bigint NULL COMMENT '关联流水ID，可空',
  ADD COLUMN paid_at        datetime NULL COMMENT '标记已存时间';
-- 唯一索引：一条流水只能被一期关联
ALTER TABLE ledger_saving_record ADD UNIQUE KEY uk_record_txn (transaction_id);

-- 状态：0待存 1已存 2未完成 3跳过
-- 是否关联流水由 transaction_id 是否为空表达，不新增字段
```

**不新增** `is_savings` 强约束；如需 UI 标识，可在账户表加一个仅用于展示的 `tag` 字段（可选，P1）。

## 4. 账户同步规则（关键）

| 用户选择 | 账户余额 | 计划进度 |
|---|---|---|
| 不关联 | 不变 | 记录汇总 +1 |
| 关联已有流水 | 不变（流水创建时已变过） | 记录汇总 +1 |
| 创建转账 | 转账自身更新两边余额 | 记录汇总 +1 |

> 一句话：**钱只在流水里动一次，计划永远只做统计**。避免"转账加一次、计划再加一次"的双记。

对账口径：
- 账户余额 = 初始余额 + 所有流水；
- 计划已存 = `saving_record where status=1` 的 `amount` 之和；
- 两者不必相等（因为允许不关联），报表上分别展示"计划完成"和"账户实际"。

## 5. 状态与操作

| 操作 | 结果 |
|---|---|
| 标记已存（不关联） | `status=1`，`amount=实际金额`，`transaction_id=null` |
| 标记已存（关联/创建） | `status=1`，`transaction_id=流水ID` |
| 标记未完成 | `status=2`，可填原因 |
| 跳过 | `status=3`，不计入失败 |
| 取消已存 | 回到 `status=0`；若有关联流水，询问"仅取消关联（保留流水）"或"同时删除流水" |
| 补关联 | 已存但无流水 → 可再选"关联已有/创建转账" |
| 换关联 | 先解除旧关联，再选新流水（旧流水保留） |

**不自动改流水**：任何计划侧操作都不静默删除用户流水，删除必须用户确认。

## 6. 日历 / 周 / 月 标记

详情页分段：**日 | 周 | 月**。

- **日**：月历格；状态用角标/底色：
  - 已存 + 有流水：绿底 + 小链条图标；
  - 已存 + 无流水：绿底 + 空心圆（提示未关联）；
  - 未完成：红点；跳过：灰点；待存：虚线框。
- **周**：月内自然周分组，每行 7 格 + 周汇总（完成 x/y、金额）；
- **月**：12 宫格，进度环 + 完成/失败数。

点某天 → 面板显示：目标金额、状态、关联流水（可点进流水详情）、三个操作按钮 + "关联流水"入口。

## 7. 到期提醒

| 渠道 | 触发 | 说明 |
|---|---|---|
| **站内消息** | 到期日 09:00（或计划设定时间） | 写 `sys_notification`，标题"今天该存「买房基金」第 3 期"，点击跳转详情 |
| 本地通知 | App/H5 打开时 | 复用 `remindScheduler`，到期弹通知 |
| 微信订阅消息 | 小程序 | 复用已有订阅消息能力（需模板/AppID） |

- 提醒只发一次（记录 `notified_at` 或复用 `reminded` 语义）；
- 未完成不重复轰炸：到期后 3 天再提醒一次，最多 2 次。

## 8. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/saving-plans/{id}/records/{rid}/mark` | `{status:1|2|3, amount?, reason?}` 仅标记 |
| POST | `/saving-plans/{id}/records/{rid}/link` | `{transactionId}` 关联已有流水 |
| POST | `/saving-plans/{id}/records/{rid}/transfer` | `{fromAccountId,toAccountId,amount,date,remark}` 创建转账并关联 |
| POST | `/saving-plans/{id}/records/{rid}/unlink` | `{deleteTransaction?:boolean}` 解除关联 |
| GET | `/saving-plans/{id}/linkable-transactions?date=&amount=` | 可关联流水候选 |
| GET | `/saving-plans/{id}/calendar?granularity=day|week|month&month=` | 日历聚合 |

## 9. 边界处理

1. **流水被删除**：`transaction_id` 置空，记录保持已存，标"流水已删除"；
2. **金额不一致**：允许，记录实际 `amount`，详情显示"目标 500 / 实存 300"；
3. **一条流水关联多期**：唯一索引阻止，接口提示"该流水已关联第 N 期"；
4. **删除计划**：记录保留，流水保留（不级联删）；
5. **跨月补记**：允许，按 `recordDate` 落在对应月份。

---

## 10. 分期

| 阶段 | 内容 |
|---|---|
| **P0** | 三选一标记（不关联/关联已有/创建转账）、日历日视图、站内到期提醒 |
| **P1** | 周/月视图、补关联/换关联、未完成二次提醒 |
| **P2** | 自动定投（可选开启）、计划与账户对账报表 |

---

## 11. 与 V1.0 的差异

| 项 | V1.0 | V1.1 |
|---|---|---|
| 只进不出 | 硬拦截支出 | **不拦截**，仅 UI 提示 |
| 存入 | 强制生成转账 | 用户三选一，可不关联 |
| 计划账户 | 必填 | 可空，仅作默认值 |
| 账户同步 | 计划与账户双写 | 只由流水驱动，计划只统计 |
| 提醒 | 未展开 | 站内消息 + 本地/微信 |
