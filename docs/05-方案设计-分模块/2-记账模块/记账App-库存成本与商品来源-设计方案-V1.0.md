# 库存成本与商品来源 · 设计方案 V1.0

> 目标：让「采购 → 库存 → 销售 → 利润」形成**闭合链条**，且与记账模块**不重复计钱**。

---

## 一、已确认的三条口径

| # | 决策 | 理由 |
|---|---|---|
| 1 | **权责发生制**（方案 B） | 采购不算消费支出，卖出时才结转成本；毛利才真实 |
| 2 | 二手分**「进货二手」**与**「自用转卖」** | 后者是资产处置，有折旧，混进库存成本会失真 |
| 3 | 赠品**公允价值选填**；物流/包装/时间成本**选填，不填为 0** | 用户自己决定精细度 |

---

## 二、来源类型 = 固定枚举（用户不可增删）

来源决定**成本怎么算**，属于业务规则。开放自定义会让成本算法失序。

| 枚举 | 名称 | 成本算法 | 用户需填 | 财务联动 |
|---|---|---|---|---|
| `purchase` | 采购 | `(总额 + 附加成本) ÷ 数量` | 关联支出流水 或 手填总额 | **生成/关联支出流水** |
| `self_made` | 自产 | `(材料 + 人工 + 其他 + 附加成本) ÷ 数量` | 成本构成 或 手填总成本 | **不产生支出**（原材料已记过） |
| `gift` | 赠品 | `(公允价值 + 附加成本) ÷ 数量`，都不填则为 **0** | 公允价值、赠送方（选填） | 无 |
| `second_hand` | 二手（进货） | `(购入价 + 附加成本) ÷ 数量` | 购入价 | 无 |
| `other` | 其他 | `(手填总额 + 附加成本) ÷ 数量` | 总成本 | 无 |

**系统生成、不在下拉里出现**：

| 枚举 | 触发 | 成本 |
|---|---|---|
| `transfer_in` | 移库转入 | 沿用原成本 |
| `stocktake_gain` | 盘盈 | 同商品加权平均成本 |
| `return_in` | 销售退货入库 | 沿用原成本 |

### 可自定义的字段（不是来源）

| 字段 | 说明 |
|---|---|
| `source_party` | 供应商 / 赠送方 / 平台，自由文本 |
| `remark` | 备注 |

## 三、成本以「总额」为准，单价是派生值

```
存：cost_total      decimal(18,2)   成本总额（权威值）
存：cost_price      decimal(18,2)   派生 = cost_total ÷ quantity
```

**原因**：500 ÷ 3 = 166.666…，若以单价为准，`166.67 × 3 = 500.01`，库存价值会比实际多 1 分。
以总额为准则永远对得上。

## 四、权责发生制的具体落地

### 4.1 采购入库

```
① 用户选「采购」，填总支出 500（或关联已有支出流水）
        ↓
② 生成一条记账流水：支出 500，标记 stock_in = 1
        ↓
③ 商品成本 cost_total = 500 + 附加成本
        ↓
④ 财务报表统计「消费支出」时 **排除 stock_in = 1 的流水**
   （或单独归为「经营性支出」，不计入生活消费）
```

### 4.2 销售出库

```
卖出 3 件，成交价 200/件
        ↓
收入 600 进现金账户
成本 = 3 × cost_price 从库存扣除
毛利 = 600 - 成本   → 计入「经营利润」，不塞进资产账户
```

### 4.3 一票多品（必须支持）

超市小票 500 元买了牛奶 + 面包 + 纸巾：

```
ledger_product_source（关联表，商品 × 流水，带分摊金额）
  ├─ 牛奶   txn_id=123   amount=200
  ├─ 面包   txn_id=123   amount=180
  └─ 纸巾   txn_id=123   amount=120
             合计 500 ✓
```

因此**不能**只在商品表放一个 `source_txn_id`。

## 五、自用转卖（资产处置，不进货架）

| 情况 | 归属 |
|---|---|
| 收来旧货直接转卖 | 来源 = `second_hand`，走库存 |
| 买来自用 N 年再卖（婴儿车） | **资产处置**，走 `ledger_asset_disposal` |

### 处置流程

```
① 登记：原值 1000，已用 24 个月，残值率 30%
        ↓
② 估值：净值 = 1000 × 30% = 300
        ↓
③ 卖出 400
        ↓
④ 处置损益 = 400 - 300 = +100 → 计入损益
```

**不进货架**：因此不参与库存价值、不影响库存报表。

| `extra_packaging` | 包装 | 0 |
| `extra_time` | 时间成本（手工估算） | 0 |

不填即为 0，全部计入 `cost_total`。

## 七、利润勾稽（让报表可验证）

```
期初库存 + 本期采购入库 - 期末库存 = 本期销售成本
```

报表需补两个数：**期初库存价值**、**期末库存价值**，否则成本算错也无从发现。

## 十、批次成本法：移动加权平均（已定）

同商品多次进货价不同，用**移动加权平均**，不做先进先出。

```
1/01  进 10 件 @10 元  →  均价 10
1/05  进 10 件 @12 元  →  均价 = (10×10 + 10×12) / 20 = 11
1/10  卖 5 件          →  成本 = 5 × 11 = 55
      剩 15 件         →  账面 15 × 11 = 165
```

### 计算规则

```
入库（有成本）：
  新均价 = (现有数量 × 现有均价 + 入库数量 × 入库单价) ÷ (现有数量 + 入库数量)
  新成本 = 新均价 × 新数量

出库：
  成本 = 出库数量 × 当前均价     （均价不变）
  剩余成本 = 当前均价 × 剩余数量
```

**不需要批次表** —— 只需在入库时重算 cost_price 与 cost_value。

### 二手单件天然适用个别计价

二手商品数量恒为 1，cost_price 就是那一件的实际成本，
移动加权平均退化为个别计价，无需额外处理。

### 与现状的差异（必须改）

现在 ledger_product.cost_price 是**建商品时定死、进货不改**，等价于「固定成本法」：
再次进货价不同时，库存价值与毛利都会偏。P0 必须改成入库时重算。

## 十一、多单位进货（已定：做换算）

### 模型：基础单位 + 包装单位 + 换算系数

```sql
ledger_product.base_unit   varchar(20)  基础单位（瓶）   ← 库存与成本一律按这个记
ledger_product.pack_unit   varchar(20)  包装单位（箱）   ← 可空
ledger_product.pack_size   int          换算系数（24）   ← 1 箱 = 24 瓶
```

### 录入与换算

```
进货 1 箱，1 箱 = 24 瓶，总价 240 元
        ↓
录入：数量 = 1，单位 = 箱
        ↓
换算：qty_base = 1 × 24 = 24 瓶
成本：cost_total = 240（+ 附加成本）
单价：cost_price = 240 ÷ 24 = 10 元/瓶
        ↓
库存按 24 瓶记，成本价按 10 元/瓶
```

### 规则

| 规则 | 说明 |
|---|---|
| **库存与成本一律按基础单位** | 避免同一商品混用两套数量口径 |
| 入库/出库都可选单位 | 选包装单位时自动乘 pack_size |
| 单价始终是「元/基础单位」 | 箱价只是录入便利，不落库 |
| pack_size 为空 = 不支持换算 | 此时单位就是基础单位 |

### 界面

```
单位   [瓶] [箱]
数量   −  [ 1 ] 箱  ＋          ← 选了箱
       = 24 瓶  · 单价 10.00 元/瓶   ← 实时换算提示
```

## 十二、产品定位带来的取舍（定稿依据）

这个平台**不是精准财务系统**：记账与出入库本质上都是**事后补录**。
自律性强的用户能记得准，多数人记不全 —— 所以库存数据只求「大致可信、能复盘」，不求会计级精确。

真正有价值的三件事：

| # | 价值 | 说明 |
|---|---|---|
| 1 | **借出/借入不遗忘** | 应收应付，用户最强烈的需求 |
| 2 | **轻量库存 + 协作** | 快速录入、随时查找、多人卖同一商品时数据互通，避免重复卖出 |
| 3 | **真实复盘经营** | 卖了多少、赚了多少，能回看 |

### 因此确定的取舍

| 决策 | 说明 |
|---|---|
| **库存相对独立于记账** | 不强绑流水；关联是可选项，不是前置条件 |
| **利润按「记录时的成本」算** | 不追求权责发生制的严格结转，录了什么成本就按什么算 |
| **自用转卖保留在库存内** | 不单独建资产变现表，用来源枚举区分即可 |
| 移动加权平均 | 保留（采购品多次进货必须），零额外表 |
| 多单位换算 | 保留（买 1 箱 = 24 瓶是刚需） |
| 一票多品分摊表 | **不做** |
| 4 项附加成本 | **合并为 1 项「其他成本」** |
| 资产处置表 | **不做** |

## 十三、最终来源枚举（4 类）

| 枚举 | 名称 | 成本 | 补流水 | 说明 |
|---|---|---|---|---|
| `purchase` | 采购 | 实付总额 | ✅ 可补 | 新买的、买别人的二手，本质都是采购 |
| `self_made` | 自产 | 默认 0，可填 | ❌ | 原料成本已在记账里 |
| `used_resale` | 自用转卖 | 默认 0，可填 | ❌ | 当年买它时已记过支出 |
| `gift` | 赠品 | 默认 0，可填 | ❌ | 没花钱 |

**只有 `purchase` 需要成本可追溯**；其余三类默认 0，知道成本的可手填（填了毛利更准，不填就标注「成本未计」）。

`used_resale` 单独成一个枚举值而不建表的目的：报表可以**一键排除自用转卖**，
既保持了表单统一（都在库存里录），又不让「经营利润」被资产变现污染。
