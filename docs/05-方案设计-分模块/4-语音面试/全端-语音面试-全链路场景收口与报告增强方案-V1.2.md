## 1. 设计原则（先立规矩）

| # | 原则 | 落到本方案 |
|---|---|---|
| 1 | **公共归网关、场景归配置、业务归 Service**（2B 铁律） | 面试全旅程所有 LLM 调用走 `ai_scene_config` 配置行 + `AiSceneJsonClient`/网关会话通道，**零代码拼提示词** |

## 3. 场景顶层设计（核心裁决：一张地图 + 三条新增）

### 3.1 面试族场景地图（终态）

| scene_code | 用途 | 调用时机 | max_tokens | 预算纪律 |
|---|---|---|---|---|
| `voice_interview`（主码） | 会话流式追问（session 模式，跳过意图分类） | 每轮作答后 | 流式 | 滑窗记忆裁剪，沿用现状 |

| `:industry_insight` **（新增）** | 发展方向建议（个人化锚定） | **懒生成**：首次打开 tab | 1536 | 不打开不花钱；**预留 knowledge_library_ids**（V1.1#4：RAG 真动态来源） |

**不新增的东西（同样重要）**：
- ❌ 不新增主场景枚举（8 个 task 全挂 `voice_interview`）
- ❌ 不为「追问预测」单开调用/配置行（并入 `:report_review`，见 §3.2）
- ❌ 不接行业实时搜索 API（列 TODO，见 §6.3）
- ❌ 不恢复已删除的「相关知识点」tab（L1368 已裁决：题库 tags 聚合对自由面试无参考价值）

### 3.2 关键裁决：追问预测**并入**复盘调用，不单开；复盘输出瘦身防爆

两触点输入完全同源（简历摘要 + 岗位 + JD + qaList），单开 = 输入 token 翻倍。

| 方案 | 每场调用数 | 输入 token | 输出 token | 代价 |
|---|---|---|---|---|
| A. 预测独立成 task | +1 | +2.5K | +1.2K | 贵；但 prompt 独立、失败隔离 |
| **B. 并入 report_review**（采纳） | +0 | +0（同上下文） | +~1K | schema 变长；预测失败随复盘一起降级 |

选 B 的依据：复盘和预测共享全部上下文，模型一次看完对话后"顺带"产出预测问题质量反而更高（它知道哪些问过哪些没问）；成本增量收敛到 ~1K 输出 token。

**B 方案的配套防爆措施（V1.1#2）**——合并后单次输出曾估算 ~3.2K 贴 max_tokens 天花板，JSON 截断 = 整场复盘降级规则版。三招压回 ~2.2K：

1. **perQuestion 瘦身**：逐题点评文本复用 `:answer_analysis` 每答落库的 `llm_analysis_json`（数据已有，复盘里再生成一遍是重复产出），复盘 schema 的 perQuestion 降为「题号 + 分数修正」两项
2. 预测问题上限 **6 条**（已问+未问合计）
3. max_tokens 3072 → **2560**（schema 缩短后留足余量）

### 3.4 明确不合并：追问流式与 answer_analysis 保持分离（防后人当优化点）

曾评估过更激进的合并——把每答分析并入追问流式调用（每场省 ~14K token，成本大头）。**结论：不合并。** 追问是会话流式模式（输出是对话文本，SSE 增量推给前端），分析是独立 JSON 调用（结构化落库）；合并后一个 prompt 既要说人话又要吐 JSON，流式体验和结构化输出互相污染，且分析失败会连坐追问。**分开不是浪费，是两种输出形态的边界。**此条写入文档防止后人误判。

## 5. 全流程梳理（用户旅程 × AI 触点 × 接口）

### 5.1 面试准备（`/interview/voice` 入口页）

| 步骤 | 内容 | AI 触点 | 接口 |
|---|---|---|---|
| P1 | 选简历（或上传新简历） | 上传走 `resume_parse`（规则引擎，同步毫秒级，v13.38） | `POST /portal/interview/resume/user/parse` |
| P2 | 选岗位（`portal_job_template` 5 模板，JD 回填） | 零调用（JD 是存量数据） | `GET /portal/interview/jobTemplate/list` |
| P3 | （可选）岗位匹配预览 | `resume_optimize:job_match` 复用 | 既有接口 |
| P4 | 开始面试 | — | `POST /{id}/start` |

### 5.2 进入面试（一次 warmup 调用 + 降级保障）

- Service 组装：岗位 + JD + 简历摘要（`buildResumeDigest`，v13.38 后 full_text 有保证）+ 知识库片段 → `:warmup`
- 产出：候选人画像 / 考察计划 / 开场白 / 首题
- **失败降级**（V1.1#1）：`generateOpening` 兜底 → 走 `:opening_fallback` 配置行，产出简版开场白+首题（无画像无计划，追问质量降一档但**永远能开场**）
- 全场总倒计时启动（`voice.interview.durationMinutes`，默认 20 分钟）；每题**不限时**（v13.40：正计时 + 90 秒软提醒，用户提交触发）

### 5.3 面试进行中（每轮 2 触点）

| 触发 | 触点 | 说明 |
|---|---|---|
| 用户提交答案（语音转写/文字，**不限时**，v13.40） | ② 会话流式追问 | 网关 `executeConversationStream`，SSE delta/end/error；记忆滑窗 + 摘要由 ContextManager |

| 用户点「提示」（≤3 次/题） | ⑤ `:hint`（新收编） | 一句话思考引导；失败走配置行 `fallback_response` |

### 5.4 报告生成（结束触发，异步带进度条）

```
进度 0-80%   规则兜底（评分聚合/维度均值/亮点薄弱/建议）——现状不变，永不失败
进度 85%     :report_review（一次调用，双产出）★
              输入：岗位+JD+简历摘要+qaList（含初评分+逐题落库的 llm_analysis_json 摘要）
              输出 schema：
                ① levelEstimate 水平定级（junior/mid/senior，V1.1 从拼进 summary 文本改为结构化字段，
                   概要 tab 做徽章 + 发展方向 tab 做个人化锚点）
                ②-⑦ 现有 6 字段（overallComment/jobMatch/highlights/weakPoints/suggestions/dimensions）
                ⑧ perQuestion：瘦身版，每题仅 {题号, 分数修正}（V1.1#2：点评文本复用 answer_analysis 落库数据）
                ⑨ predictedQuestions: [ 上限 6 条（已问+未问合计）
                    {question 预测问题,
                     briefAnswer 要点式简答≤80字,
                     analysis 为什么会被问≤60字,
                     knowledgePoint 考点标签2-6字,
                     askedThisRound bool 本场是否已问,
                     askedScore 本场得分(已问时)}
                  ] —— 提示词硬约束：只能基于简历摘要真实内容提问，禁止推断未提及经历、
                      禁止编造项目名或技术栈；已问判断以对话记录为准；
                      未被问到的问题优先覆盖：简历写了但本场未深挖的条目、岗位要求中简历未体现的差距项

```

### 5.5 发展方向（懒生成，不在报告链路里）

- 首次打开 tab5 → `POST /{id}/insight` → Service 组装 → `:industry_insight`
- **输入差异化（V1.1#3，与 job_match 划清边界）**：岗位 + JD + 简历技能 + **本场报告上下文**（weakPoints + levelEstimate + 低分维度）——个人化建议每条强制引用真实薄弱点，杜绝"建议学云原生"式与简历优化页撞车的通用废话
- **配置行预留 `knowledge_library_ids`（V1.1#4）**：知识库有行业资料时洞察走 RAG 检索产出有据内容（网关原生支持，零新代码）；搜索 API 仍列 TODO（§6.3）
- 结果连同 `generatedAt` 写回 report JSON 的 `industryInsight` 字段（**并发幂等**：生成中加 Redis 锁，防双击双花）
- 前端展示「生成于 X 日 · 刷新」按钮，超 7 天提示可刷新
- **口径诚实**：输出为"技术趋势方向 / 技能供需结构 / 结合个人短板的 3 条行动建议"，**不承诺实时行业动态**（LLM 无实时数据，编造"Q3 岗位需求涨 X%"是"错值用户会信"的典型事故）；提示词硬约束：严禁标注具体百分比、薪酬数字或"2026年Q3"类时效数据

## 6. 报告内容与布局（终态：三层五 tab，V1.1#7 信息架构重排）

### 6.1 信息架构：一条主线，三个层次

5 个 tab 不是平铺的功能，是按用户心智分层的旅程：

```
第一层【复盘区】这场我打得怎么样（向后看）
  📋 面试概要（结论）→ 🔍 问题分析（归因）→ 💬 对话回放（证据，殿后）

第二层【备战区·个人】下次真面试会怎样
  🔮 追问预测（真面试官拿到简历会问什么）

第三层【备战区·环境】我该往哪走
  🧭 发展方向（把本场短板放进行业坐标系）

主线：表现 → 归因 → 证据 → 个人预测 → 环境导航
```

```
┌──────────────────────────────────────────────────────────────┐
│ 报告头部：总分 + 定级徽章(levelEstimate) + 岗位 + 时间          │
├──────────────────────────────────────────────────────────────┤
│ 📋 面试概要 │ 🔍 问题分析 │ 🔮 追问预测 │ 🧭 发展方向 │ 💬 对话回放 │
└──────────────────────────────────────────────────────────────┘
```

**回放殿后的理由**：回放是**原始证据**不是消费内容——用户只在对某题不服时才翻原文。证据层的正确姿势是**被引用**（问题分析的"查看原文"锚点跳转过来），不是排在第 2 位挡道。

### 6.2 逐 tab 内容契约

| Tab | 层次 | 内容 | 数据源 | 状态 |
|---|---|---|---|---|
| 📋 面试概要 | 结论 | **首屏**：总分大数字 + 六维雷达 + 匹配度 + 定级徽章；**叙事区**：AI 总评 3-5 句；**行动区**：亮点 2-4 + 薄弱点 2-4 + 改进建议 3-5（薄弱与建议相邻，问题挨着答案）；**归档区（折叠）**：面试者简介/岗位信息/自我介绍评分/心态趋势/可疑信号（资料降权，现状 11 板块无主次的病症） | 规则兜底 + `:report_review` | 瘦身重排（批次 2） |
| 🔍 问题分析 | 归因 | 逐题点评、得分、追问链（现状）；**新增**：按维度聚类视图（最低维度相关题置顶聚合，如"表达流畅相关：第 3/6/8 题"）+ 跳转回放锚点 | questionReviews + `llm_analysis_json` | 增强排序（批次 2） |
| 🔮 追问预测（原"简历分析"改名，V1.1#8） | 个人预测 | **分组 A「本次已问」**：问题 + 你的得分 + 标准答案要点对照（复盘视角：答得对不对）；**分组 B「未被问到」★核心价值**：预测问题 + 要点简答≤80字 + 提问动机≤60字 + 考点标签（预警视角：下次真面试的押题清单） | `:report_review` 第⑨字段 | **批次 2** |
| 🧭 发展方向（原"行业洞察"改名，V1.1#9） | 环境导航 | **① 技术趋势** 3-4 条（title≤12字 + detail≤60字 + maturity 成熟期/上升期/早期）；**② 供需结构** 存量技能 vs 增量技能标签云（对照简历标 ✅已具备/⚠️欠缺）；**③ 行动建议** 3 条，每条**必须引用本场真实薄弱点**（relatedWeakPoint 强制对应）；生成时间戳 + 刷新 | `:industry_insight` 懒生成 | **批次 3** |
| 💬 对话回放 | 证据 | 完整对话流（面试官/候选人双列气泡），从第 2 位移到第 5 位 | qaList | 移位（批次 2，纯前端） |

**改名理由留档**：
- 「简历分析」→「追问预测」：原名与简历优化模块语义冲突（用户预期简历修改建议，实为预测问题）
- 「行业洞察」→「发展方向」：原名承诺"洞察行业"但 LLM 无实时数据（编时效数据是事故）；新名诚实且与备战区连贯

### 6.3 布局纪律

- tab4/5 缺数据时**整个 tab 隐藏**（对齐"旧数据字段为空按缺失隐藏"惯例；无简历场次 tab4 隐藏）
- tab5 未生成时显示占位卡片「生成发展方向分析（约 10 秒）」+ 按钮，**不自动触发**
- tab5 顶部固定一句定位说明：「基于本场表现与岗位方向的个人化分析 · 生成于 X 日」

### 6.4 发展方向的 TODO 占位（本期不做）

配置行 `config_json` 预留 `searchApi.enabled=false`；接搜索增强（火山/博查/Tavily）时改配置不改代码——对齐"第三方集成先 TODO 占位"铁律。RAG 通道（`knowledge_library_ids`）为第一优先的真数据来源，搜索 API 为第二优先。

## 8. 实施批次（每批独立 commit + 四同步）

| 批次 | 内容 | 交付物 |
|---|---|---|
| **批次 0：修地基（V1.2 新增）** | ① **答题并发保护**（幂等键 + 状态机 + QA 唯一约束）—— 现 `submitAnswer` 无任何并发保护，双发同 `qaId` 会覆盖答案/双倍 token/同 idx 插两条 QA；② **超时口径统一**（`SSE_TIMEOUT` 120s ＜ 模型 180s）；③ **断连中止 LLM**（无 `onCompletion`，断连后继续烧 token）；④ **事务边界**（聚合链无 `@Transactional`）；⑤ **自介评分接线**（V1.2#1）；⑥ **hint 计费/限流口径**（免费 + Redis 计数）；⑦ **多实例守卫**（`RUNNING_ANALYSIS` 静态内存 → `DistributedLockUtil`） | 代码 3~4 文件（无 DDL 除 QA 唯一约束） |
