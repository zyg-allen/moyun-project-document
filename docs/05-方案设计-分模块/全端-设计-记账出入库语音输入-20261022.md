# 记账 / 出入库「按住说话」语音输入 · 设计方案

> 状态：设计稿（2026-10-22）
> 范围：App（H5 / 小程序 / 未来 APK），记账与出入库两个场景
> 原则：**语音只是更快的输入方式，最终仍落到现有表单与保存接口**；识别不确定的字段必须让用户看见并改。

---

## 1. 目标与非目标

### 目标

1. 用户按住按钮说一句话，自动完成：转文字 → 拆字段 → 回填表单；
2. 回填后**可逐项修改**，确认再提交（记账=保存，出入库=提交）；
3. 单次交互控制在 **10 秒内**（说 3~5 秒 + 确认 3 秒）；
4. 识别失败/低置信时**优雅降级**为手动输入，不阻塞。

### 非目标（首期不做）

- 一句话多笔（"早饭 10 块午饭 20"）→ 先提示"一次说一笔"；
- 连续对话式补全（"金额多少？"）；
- 离线识别；
- 方言专门优化。

## 2. 用户体验流程

### 2.1 入口

| 页面 | 入口形态 |
|---|---|
| 记一笔 | 保存按钮上方一个**圆形麦克风按钮**（或与「保存」并排的次级按钮） |
| 出入库 | 提交栏左侧麦克风按钮 |

点击后进入"按住说话"浮层，不跳页。

### 2.2 状态机

```
idle ──按下──▶ recording ──松手──▶ recognizing ──成功──▶ review ──确认──▶ submitting ──▶ done
  ▲                │                    │                    │
  │                └─上滑取消───────────┘                    └─取消/返回─▶ idle
  └──────────────────失败/取消─────────────────────────────────┘
```

### 2.3 交互细节

**录音中**
- 浮层显示波形/音量条 + 计时（`0:03`）+ 提示「松手结束，上滑取消」；
- 上滑超过 80px 进入"松开取消"态（按钮变红、提示变化）；
- 最长 60 秒自动结束。

**识别中**
- 显示「正在识别…」骨架，禁止重复点击；
- 超时 8 秒 → 失败态：「没听清，重说一次 / 手动输入」。

**结果确认（review 面板）**
底部半屏面板，自上而下：

1. **原始文本**（可编辑，改完点「重新解析」）；
2. **字段卡片**：每个字段一行「标签 + 值 + 置信度标记」；
   - 高置信：正常；
   - 低置信/多候选：黄色底 + 「请确认」，点开候选列表；
   - 缺失必填：红色「待补充」，点击聚焦对应表单输入；
3. **主按钮**「填入表单」；次按钮「重新说」。

> 关键决策：**review 面板不直接保存**，而是"填入表单"后由用户在原有表单里最终确认。这样复用现有校验（余额不足、分类必填、库存校验），也符合"修改更正"的要求。

**填入后**
- 回到表单，已填字段加 1.5 秒高亮描边（`voice-filled`）；
- 顶部提示「已按语音填入 5 项，请核对后保存」；
- 焦点落在第一个低置信字段。

## 3. 技术架构（复用现有能力）

```
App 录音(RecorderManager)
   │ multipart: audio + scene
   ▼
POST /portal/ledger/voice/recognize
   │
   ├─ VoiceAsrService.transcribe(audio)     ← 复用现有 ASR（qwen3-asr-flash / 后台可配模型）
   │
   ├─ 解析管线：规则 + 词典 + 置信度
   │     └─ 低置信/未命中 → AI 网关（LLM，JSON Schema，temperature=0）
   │
   └─ 返回 { text, fields, confidence, missing, candidates }
   ▼
App review 面板 → 填入表单 → 用户确认 → 原有保存/提交接口
```

**复用清单**

| 能力 | 现有实现 | 复用方式 |
|---|---|---|
| 语音转文字 | `VoiceAsrService.transcribe(MultipartFile)` | 直接调用 |
| 实时流式（可选 P2） | `PortalAsrWebSocketConfig` + fun-asr-realtime | 二期接入 |
| LLM 结构化解析 | AI 网关（模型配置 + 调用日志 + 成本计量） | 新增一个"记账解析"提示词/模板 |
| 分类/账户/商品/渠道词典 | 后台字典 + 用户数据 | 作为实体匹配词表 |
| 成本与配额 | `ai_execute_log` 已有 token/成本 | 语音调用单独记一条 |

## 4. 接口设计

### 4.1 识别 + 解析

```
POST /portal/ledger/voice/recognize
Content-Type: multipart/form-data
  audio: File (m4a/mp3, ≤10MB, ≤60s)
  scene: ledger | inventory
```

响应：

```json
{
  "code": 200,
  "data": {
    "text": "昨天午饭花了三十块五，用微信付的",
    "fields": {
      "type": "expense",
      "amount": "30.50",
      "categoryId": 21,
      "categoryName": "餐饮",
      "accountId": 12,
      "accountName": "微信零钱",
      "transactionDate": "2026-10-21",
      "transactionTime": "12:30",
      "description": "午饭"
    },
    "confidence": { "amount": 0.99, "categoryId": 0.86, "accountId": 0.72, "transactionTime": 0.4 },
    "missing": ["transactionTime"],
    "candidates": { "categoryId": [{ "id": 21, "name": "餐饮" }, { "id": 22, "name": "外卖" }] },
    "durationMs": 4120
  }
}
```

### 4.2 文本重解析（用户在 review 里改字后）

```
POST /portal/ledger/voice/parse
{ "scene": "ledger", "text": "昨天午饭30.5微信" }
```
返回同上（不含 audio/text 识别部分）。

### 4.3 记录（可选，用于优化）

`ledger_voice_log`：`user_id, scene, text, parsed_json, confidence_avg, duration_ms, model, cost_yuan, created_at`
**不保存音频**。提供开关：用户可在隐私设置关闭"语音记录用于改进"。

## 5. 字段与解析规则

### 5.1 记账字段

| 字段 | 必填 | 识别来源 | 示例 |
|---|---|---|---|
| type | 是 | 动词 | 花了/买了→支出；收到/工资→收入；转给→转账；借出/还我→借出/收款 |
| amount | 是 | 数字（含中文数字、块/元/毛） | "三十块五"→30.50；"1万2"→12000 |
| categoryId | 是 | 词典 + LLM | 吃饭/午饭/外卖→餐饮；打车/地铁→交通 |
| accountId | 否 | 账户词典 | 微信/支付宝/招行 |
| targetAccountId | 转账时必填 | 同上 | "从招行转到微信" |
| transactionDate | 否 | 时间词 | 今天/昨天/上周五/10月20号 |
| transactionTime | 否 | 时间词 | 中午/下午3点/12:30 |
| description | 否 | 剩余文本 | 去掉已识别实体后的部分 |
| merchant / tags | 否 | 商家词典/标签 | "星巴克" |

### 5.2 出入库字段

| 字段 | 必填 | 识别来源 | 示例 |
|---|---|---|---|
| mode | 是 | 动词 | 进货/入库/收了→入库；卖出/出库/发了→出库 |
| itemId | 是 | 商品名模糊匹配（含别名） | "AirPods 二代" |
| quantity | 是 | 数量 + 单位 | "3 个"、"两箱" |
| totalCost / unitPrice | 入库建议必填 | 金额 | "一共花了 240" |
| channelId / sourceChannel | 出库建议 | 渠道词典 | 闲鱼/微店/朋友 |
| shelfId | 否 | 货架名 | A 区 3 层 |
| date | 否 | 时间词 | 今天 |
| expiryDate | 否 | "保质期到…" | 2026-12-01 |
| remark | 否 | 剩余文本 | |

### 5.3 解析管线

1. **归一化**：全角转半角、中文数字转阿拉伯、单位统一（块/元/毛/角）；
2. **规则抽取**：金额正则（含口语）、时间词表、类型关键词表、数量+单位；
3. **词典匹配**：分类/账户/商品/渠道（来自后台字典 + 用户自己的数据），支持别名与模糊匹配；
4. **置信度**：精确命中 0.9+；模糊命中 0.6~0.9；LLM 推断 0.5~0.8；
5. **LLM 兜底**：规则未覆盖或必填缺失时，调用 LLM 输出严格 JSON（只允许字段白名单，ID 必须来自候选列表，禁止编造）；
6. **合并**：规则优先，LLM 只补空；金额/数量以规则为准；
7. **校验**：必填缺失 → `missing`；多候选 → `candidates`。

### 5.4 口语数字示例

| 说法 | 解析 |
|---|---|
| 三十块五 | 30.50 |
| 一百二 | 120 |
| 1 万 2 | 12000 |
| 两块五毛 | 2.50 |
| 二百四十五 | 245 |

## 6. 权限、隐私与合规

- **权限**：小程序 `scope.record`；App `RECORD_AUDIO`；H5 `getUserMedia`（必须 HTTPS）。拒绝后只提示一次，并保留手动输入。
- **音频**：仅在内存/临时文件，转写完成即删除，**不上传对象存储、不落库**。
- **文本**：默认仅用于本次解析；"用于改进"需显式开关（默认关）。
- **隐私政策**：新增"麦克风与语音"小节，说明用途、是否上传、保存期限。
- **成本**：ASR 按音频时长计费，LLM 仅在低置信时调用；建议免费用户 20 次/日、专业版 200 次/日，超限提示手动输入。

## 7. 分阶段实施

| 阶段 | 内容 | 预估 |
|---|---|---|
| **P0** | 记一笔：按住说话 → ASR → 规则解析（金额/分类/备注/日期）→ review → 填表 | 3~4 天 |
| **P1** | 出入库场景；全类型（收入/转账/借还）；LLM 兜底；候选与低置信交互；日志与配额 | 3~4 天 |
| **P2** | 实时流式识别（边说边出字）、多笔拆分、连续补全 | 5 天+ |

P0 验收：10 条常用话术，金额与分类准确率 ≥ 90%，用户从按下到保存 ≤ 15 秒。

---

## 8. 埋点与验收指标

| 指标 | 目标 |
|---|---|
| 识别成功率（有文本） | ≥ 95% |
| 字段一次填对率 | ≥ 80% |
| 语音发起 → 最终保存 转化率 | ≥ 60% |
| 平均耗时（按下→保存） | ≤ 15s |
| 放弃率（识别后未保存） | ≤ 25% |

埋点事件：`voice_start / voice_cancel / voice_asr_fail / voice_review_show / voice_field_edit / voice_fill / voice_save`。

## 9. 风险与降级

| 风险 | 应对 |
|---|---|
| 噪音/口音识别差 | 失败态引导重说；保留手动输入；P2 实时字幕让用户知道听到了什么 |
| 金额歧义 | 规则优先 + review 高亮金额要求确认 |
| 一句话多笔 | 明确提示"一次说一笔"，首期不拆 |
| ASR 超时/限流 | 8 秒超时、失败降级；配额与限流 |
| 隐私顾虑 | 音频不落盘、可关闭日志、隐私政策明示 |
| 小程序审核 | 录音属敏感能力，需在隐私协议与功能说明中声明用途 |

## 10. 待决问题

1. 小程序端是否额外接微信「同声传译」插件（免后端、但仅小程序且需插件审核）？建议**统一走后端 ASR**，行为一致。
2. 首期是否只做"记一笔支出"？建议是，验证准确率后再扩。
3. 是否启用实时流式（P2）？取决于用户对"边说边看字"的诉求。
