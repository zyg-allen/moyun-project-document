> 对照：现有 33 个页面
> 结论：**记账主链路是完整的**；缺的是“上架合规、数据可迁移、账户可管理、商业化闭环”四类能力。

## 二、缺口（按优先级）

### P0：上架与合规必备

| # | 缺口 | 说明 |
|---|---|---|
| 1 | **账号注销** | 协议里承诺“可申请注销”，但 App 无入口；应用商店审核会查 |
| 2 | **数据导出入口** | CSV 导出只在报表页，设置里没有“导出全部数据” |
| 3 | **系统权限管理** | 通知/麦克风/相册授权没有集中说明与跳转设置 |
| 4 | **协议版本更新弹窗** | 后端有版本留痕，App 未在换版后强制重签 |

### P1：记账 App 的核心完整性

| # | 缺口 | 说明 |
|---|---|---|
| 5 | **全局搜索** | 不能按金额/备注/商户/分类搜历史流水 |
| 6 | **账户详情页** | 点账户看不到该账户流水与对账入口 |
| 7 | **数据导入** | 不支持支付宝/微信 CSV、其他记账 App 迁移 |
| 8 | **备份与恢复** | 无手动备份/恢复，换机只能靠云端（若有） |
| 9 | **安全锁** | 无手势/指纹/面容解锁；金额隐藏只有局部 privacyMode |
| 10 | **订阅/会员页** | 后端已有 VIP/支付能力，App 无购买与权益页 |

### P2：进阶与差异化

| # | 缺口 | 说明 |
|---|---|---|
| 11 | 多账本 | 个人账与生意账分离 |
| 12 | 家庭/共享账本 | 多人协作记账 |
| 13 | 发票/报销 | 标记可报销、导出报销单 |
| 14 | 新手引导 | 首启没有 3 步引导 |
| 15 | 版本更新/崩溃上报 | 无检查更新、无前端错误上报 |
| 16 | 离线与冲突 | 弱网下无本地缓存与冲突提示 |
| 17 | 多币种/国际化/无障碍 | 当前仅 CNY、中文 |

## 三、最小可上线补齐（建议顺序）

1. **账号注销**（含二次确认、7 天冷静期可选）；
2. **设置页“导出全部数据”**（复用 CSV 接口，覆盖流水/账户/预算/存钱）；
3. **隐私与权限页**（系统权限说明 + 跳转设置 + 协议版本重签）；
4. **安全锁**（4 位 PIN + 生物识别，进入后台/启动时验证）。

这 4 项完成后，应用商店合规与“敢给真实用户用”基本达标。

## 四、第二批（体验完整）

5. 全局搜索；
6. 账户详情；
7. 数据导入（先 CSV）；
8. 备份/恢复；
9. 订阅/会员页（若商业化）。

## 五、判断依据

- 现有页面没有 `search / account-detail / import / backup / vip / security-lock`；
- 协议与隐私政策已写明“可注销、可导出”，但功能未落地，属**承诺与实现不一致**；
- 后端 `vip/pay` 能力存在，App 无入口，商业化未闭环。
