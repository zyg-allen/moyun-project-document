## 总 · 项目全景

**定位**：AI 驱动的求职面试与学习成长平台。四端一云：

| 端 | 技术 | 职责 |
|----|------|------|
| moyun-server | Spring Boot 3.3（JDK 21）+ MyBatis-Plus | 唯一后端，三端统一 API |
| moyun-portal | Vue 3 + TS + Tailwind | 前台门户（内容社区/面试/学习/钱包） |
| moyun-admin-vue | Vue 3 + Element Plus（RuoYi-Vue） | 管理后台（内容/AI/支付/记账运营） |
| moyun-ledger-app | Vue 3 + uni-app | 记账 App（小程序/H5/App 三端） |

**核心业务域**：内容社区（文章/专栏/话题/审核中心）、AI 语音面试（平台旗舰）、简历中心、学习工具（题库/OJ/图谱/日历）、成长体系、读书空间、个人记账（App）、商业化（支付/钱包/VIP/打赏）。

## 分 · 各模块实现方法与代码特点

### 1. AI 统一网关（com.moyun.ext.aigateway，项目核心骨架）

**实现方法**：所有 LLM 调用一律经 `AiGatewayService` 收口，业务方通过 `AiSceneJsonClient.executeForJson(sceneCode, input, userId)` 获取结构化结果。

```
业务层（拼 input: task/context/transcript）
  → AiGatewayService（限流 → 注入防护 sanitize → 成本熔断 → 场景配置校验 → Agent/模型路由）
  → ai_execute_log 落库（success/fail/error_msg/elapsed/model_used）
  → FallbackStrategy 降级 → 业务规则兜底
```

**代码特点**：
- 路由核心 `AiSceneRegistry`：Handler Bean 注册（Spring 扫描）+ 场景配置读取（**`ai_scene_config` 表**，旧 `ai2_scene_registry` 已废弃合并）
- **配置驱动，无逐场景 Handler 类**：场景差异全部由 `ai_scene_config` 声明，执行统一走 `DefaultSceneExecutor`（+ `AbstractAiSceneHandler` 基类与 `AiSceneHandler` 接口，仅 2 个文件）；后台可改，业务零感知
- 模型缓存键 = `模型ID:temperature:maxTokens:jsonMode`，同配置共享 ChatLanguageModel 实例
- 安全三件套：`PromptInjectionGuard`（输入清洗，重建可变 Map，勿传 `Map.of`）、Token 成本熔断、输出过滤
- **语义缓存必须按用户隔离**（v13.2 起）：键与语义扫描均为 `ai2:cache:u:{userId}:{scene}:...`，
  且 `userId` 为空时**不查也不写**（fail-closed）。缓存里是完整响应体（简历/财务/面试等私有内容），
  键不带 userId 会造成跨用户泄漏；确需跨用户共享的公共场景应显式声明作用域，不得默认共享。
  回归测试：`Ai2InfraSupportTest`（跨用户不命中 / 空用户不落键 / 扫描模式必须带 userId）
- 运行时开关走 `AiGlobalSwitch` → sys_config（`ai.global.enabled` 等，管理台热生效）；yaml `moyun.ai.enabled` 仅承担 bean 装配（固定 true）
- **Token 计量必须两条路径都覆盖**（v13.3 起）：非流式由服务端回传 usage；**流式拿不到 usage**
  （langchain4j beta3 不下发 `stream_options.include_usage`），故由 `TokenMeter` 用本地分词估算并置
  `token_estimated=1`。规则：**真实优先、估算兜底、估算必须可区分**——否则流式会绕过场景日配额、
  成本看板失真。回归测试：`TokenMeterTest` + `AiGatewayStreamTokenAccountingTest`
- 异步重任务走通用 AI 异步任务表（轮询进度），同步链路不做重活
- **异步执行必须指定受管执行器**（v13.5 起）：`CompletableFuture.runAsync/supplyAsync` **禁止不传执行器**
  （默认 `ForkJoinPool.commonPool()` 并行度仅 CPU-1，会被分钟级长任务占满，连带拖慢全站并行任务）；
  裸 `new Thread()` / `Executors.new*` 除守卫白名单外一律禁止。SSE 长任务用 `sseStreamExecutor`
  （queue=0、满即拒绝，调用方必须捕获 `RejectedExecutionException` 并回明确错误）；池矩阵见
  `项目开发规范` §1.12。回归测试：`ExecutorGovernanceGuardTest`

**开发规约**：新场景 = 后台建 `ai_scene_config`（绑定 Agent/模型/限流/输出模式）+ 业务拼 input，**通常零代码**；禁止直连 LLM 客户端。admin 端系统管理（agent/大模型配置等）的 AI 调用按 devlog v12.2.3 的用户决策保留直连，不在收编范围。

### 2. AI 语音面试（旗舰功能，com.moyun.ext.cms.interview）

**实现方法**：
- 对话链路：快链路（ASR 实时转写 → Agent 流式生成 → TTS 播报），Agent 驱动自由面试（滑窗记忆），意图分类器打断
- 逐题分析：`analyzeAnswerByLlm` 走网关 `voice_interview` 场景（task=answer_analysis），LLM 评分 + 规则分按 70/30 融合
- 整场复盘：`enhanceReportByAgent` LLM 二次复盘（基于简历 + JD + 全部对话），输出总评/岗位匹配度/亮点/薄弱点/建议
- 时长制：sys_config `voice.interview.durationMinutes`（默认 20 分钟倒计时）

**代码特点**：无状态调用、DB 为唯一真相源（qa/question/report 表）；报告生成异步化 + 状态机防竞态；历史页支持重新生成（路由参数 `regenerate=1` 触发）；报告分享页 token 免登录。

### 3. 简历中心（com.moyun.ext.cms.resume）

**实现方法**：上传（版本化附件）→ 网关场景解析反显 → 岗位匹配 → 深度优化（异步任务 + 逐项 diff 采纳回写）→ AI 建议。VIP 付费点（免费体验 2 次后收费）。

**代码特点**：优化项采纳走 diff 回放（保留原值可撤销）；`resume.advice.enabled` sys_config 热开关。

### 4. 记账 App（com.moyun.ledger + moyun-ledger-app）

**实现方法**：记一笔（支出/收入/转账/借款/还款五类型）→ 资产负债账户体系（借款自动建负债）→ 报表中心（分类/趋势/账户多维 + CSV）→ 预算/备忘录/储蓄目标/定时记账。

**代码特点**：
- **金额铁律**：全链路 RMB 元，DB `DECIMAL(18,2)` + Java `BigDecimal`，前端不乘除 100
- **账户余额写入权唯一**（v13.1 确立）：`balance` 只由 `LedgerTransactionServiceImpl.applyAssetDelta` /
  `applyLiabilityDelta` 的**原子 SQL**（`balance = balance + delta` + `version = version + 1` + `WHERE version = ?`）维护；
  **任何"改属性/归档"入口一律列级 UPDATE，禁止用 `updateById` 写回整表**（否则会抹掉并发记账结果、并把 `version` 写回旧值破坏乐观锁）。
  回归测试：`LedgerAccountMetaUpdateIsolationDbTest`
- **派生列同理**（v13.2）：`paid_terms`（已还期数）在**还款的同一条原子 UPDATE** 里联动（还款 +1、冲正 −1、借款不计），
  与 `settle_flag` 一并**不可由改属性接口写入**；`due_date` 为预留列（读取方有 fallback）
- **可空字段的"显式清空"**（v13.2）：账户更新接口用 `@RequestBody Map` + 白名单映射，并把 `body.keySet()`
  透传给 service —— 可空业务列**显式提供即以传入值为准（null=清空）**，未提供则保持原值。
  这样"清空月供/还款日/总期数"才真正生效，且不会误清未提交的字段
- AI 财务分析：月/季/年快照多版本留存，结构化契约 `evidence/expectedImpact`（量化依据），异步生成
- 小程序功能配置后台化（cms/ledger 运营统计：模块使用/AI Token 成本/收益）

### 5. 支付与商业化（com.moyun.pay）

**实现方法**：公共支付网关统一下单（微信通道 + mock 模拟器双模式，验签/回调/分账全真演练）→ 单钱包公账体系（所有收支走钱包流水）→ 平台分账 → 提现闭环。

**代码特点**：支付回调免登录 + 验签；分账按 `pay.platform.fee-rate`（sys_config 可调）；VIP 三模块（面试/简历/记账）接入统一收银台；银行卡/提现敏感操作强制短信验证。收银台二维码在 H5 与小程序**共用一套绘制**（`qrcode` 纯计算模块 + `uni.createCanvasContext`，v13.10）；小程序原生支付（`uni.requestPayment`）与服务端出图待依赖/商户配置。

### 6. 内容社区与审核（com.moyun.ext.cms + portal）

**实现方法**：文章（原创/转载/付费阅读/版本管理）+ 专栏 + 话题 + 评论，统一审核中心（`sys_audit_task`，旧入口已隐藏）。

**代码特点**：审核任务统一收口（/portal/audit-center）；举报/反馈闭环；创作者认证（实名加密 AES-GCM）。

### 7. 学习工具与 OJ（portal/judge）

**实现方法**：题库练习 + ACM 编程题接真实 OJ 判题（ProcessBuilder 开发/Docker 沙箱生产 + 异步队列）+ 刷题日历/错题本/知识图谱/排行榜/竞赛。

**代码特点**：判题引擎类型后台可切（`moyun.judge.engine-type`）；异步判题 Redis 队列。

### 8. 成长体系与基础平台

- 成长事件统一追踪（学习/面试/阅读/写作）→ 时间线/等级/徽章/排行榜
- RuoYi 基础：用户/角色/菜单/字典/**sys_config 热配置**（AI 开关/面试时长/费率等运行时配置一律在此）
- 双 FilterChain：portal 免登录白名单 + admin 认证；金额/敏感字段加密（AES-GCM）
- **双链重叠路径必须显式定序且双向 fail-closed**（v13.6）：`/portal/admin/**` 名义属门户前缀、
  实际归核心链（admin token），而**两条链都匹配它**——`@Order` 只能标在 `@Bean` 方法上
  （标在 `@Configuration` 类上实测不生效，链顺序会退化为注册顺序），且两条链对该前缀
  **一律禁止 `permitAll`**（"反正轮不到这条链"也不行：顺序一翻转它就成了匿名放行）。
  后台端点权限粒度由每个端点的 `@PreAuthorize` 决定，由 `PortalAdminAuthorizationGuardTest` 强制
  （链归属 + 匿名拒绝 + 端点注解 + 扫描量自检）
- **定时任务走 Quartz JDBC 集群 JobStore**（v13.7）：`core.config.QuartzConfig` 显式注入**物理主库**
  （不能用 `dynamicDataSource` 路由数据源）；启动注册是 `sys_job` ↔ JobStore 的**幂等同步**，
  **禁止 `scheduler.clear()`**（共享 JobStore 下清库会删掉其他实例的任务）。
  多实例实测：集群形态同一触发器 7 秒执行 8 次（≈1 次/秒），两个 RAMJobStore 实例为 16 次（重复执行）。
  业务侧仍须幂等（集群只保证"不并发"，不保证"只一次"）。回归测试：`QuartzConfigWiringTest` +
  `QuartzClusterSingleExecutionDbTest`

### 一、变更与流程（五条）

1. **严禁私自把 git 回退到历史版本（最高优先级）**
   - **绝对禁止**任何"把代码变回过去"的操作：`git reset --hard`、回到历史提交的 `git checkout`、
     强推 `push --force`、`git rebase` 改写历史、`git stash` 反向覆盖工作区、
     切分支时丢弃改动（`checkout -f` / `clean -fd`），**以及以任何形式用历史版本覆盖当前代码**；
   - **唯一例外（纠错窗口）**：**上一步刚提交、且已明确确认该提交是错的**——可撤销它，属纠错而非回退；
   - **例外之外必须人工确认**：确有回退需要时，**先说明"为什么必须回退 / 影响哪些文件 / 如何验证恢复后正确"**，
     经人工确认后才执行；**AI 助手不得自行决定并执行回退，也不得把回退混在其它改动里一起做**；
   - **优先走"向前修正"**：撤销一个**已确认错误的历史提交**时，用 `git revert`（**新增一条反向提交**，
     历史完整保留、可再恢复）或直接写一个修正提交；**绝不改写历史**；
   - 目的：防止代码在无人察觉的情况下被历史版本覆盖（多端协作 + 多轮自动化改动并存时风险最高）。
   - **交付前自查**：`git reflog` 不应出现本次会话的 `reset` / `checkout <commit>` / `rebase` / `revert`
     记录（除已确认的纠错窗口）；有则必须在 devlog 说明原因与人工确认过程。

2. **devlog 逐次记录**：**每一次修改都必须登记**到 `docs/07-变更日志/devlog.md`
   （版本 + 修改类目 + 简介；细节进方案文档，不进日志）。要求"改完即记"，不允许改了不记或事后补记。

3. **四同步**：**代码 · 文档 · SQL · 菜单**必须同步更新，任何变更缺一不可。
   凡涉及**接口契约 / 配置键 / 表结构 / 状态机 / 外部通道行为 / 菜单权限**的改动，
   必须同步 `README.md` / `部署指南` / `项目开发规范` / 相关 `05-方案设计` 文档。
   纯内部重构、注释、日志类小改动至少要有 devlog 一条。

4. **提交前对照 git 自检**：`git log` / `git diff` 与 devlog 条目相互对照——
   "提交了什么 / devlog 记了什么 / 文档改了没有"三者必须自洽；发现遗漏**先补齐再提交**。

5. **代码是唯一事实来源**：代码与文档冲突时**一律回审代码后改文档**，绝不把代码改回文档；
   每次校正都要在 devlog 写明"以代码为准"具体改了哪些文档。

### 二、文档（四条）

6. **文档只写可验证行为**：不替作者断言设计意图；无法从代码 / devlog / commit 判断的列为待确认项，不擅自改。

7. **文档版本随修改升级**：文件名统一为「**端-模块-功能-版本**」（端 ∈ 全端 / 后端 / 门户 / 后台 / 记账App）；
   **内容有实质修改必须同步升版本号**（文件名与文内版本标注一起改）并在 devlog 登记；
   雷同或同一修改方向的文档**只保留最新主干版本**，其余归档至 `.archive/`。

8. **方案文档按模块归位** `05-方案设计-分模块/`；旧版 / 评估 / 排查类文档及时删除或归档。
   **严重滞后于代码的文档直接删除**（不再增补修订），保持文档与代码同向演进。

9. **分工与效力顺序（唯一性边界）**：全项目只有**两处**声明"唯一"，各管一段、不重叠——
   **本文是唯一「项目铁律」来源**（红线与流程：必须遵守什么、违反即失败）；
   [项目开发规范](../02-开发指南/全端-规范-项目开发规范-V13.30.md) 是唯一「**技术实现规范**」来源
   （细则与范例：具体怎么写）。**铁律是上位规则、规范是下位实现**——判定是否违规看本文，
   判定具体怎么写看规范；两者对同一事项都有描述且看似冲突时，**以本文为准**并回写规范。
   各端 `README` 是端内业务总览；`docs/README.md` 是文档索引。
   全项目效力顺序：**代码 > devlog > 本文（含铁律）> 项目开发规范 > 文档索引 > 其余文档**。

### 三、SQL 双轨（二条）

10. **`init-sql` 与 `increment-sql` 必须同步修改**
    - **`init-sql/` = 目标态**：新库只跑三件套（`moyun-db-ddl.sql` → `moyun-db-dml-init.sql` →
      `moyun-menu-redo.sql`）即可**直接初始化出可用项目**。任何结构 / 种子改动**必须同步改 init-sql**，
      否则新库装出来是旧结构；
    - **`increment-sql/` = 存量库执行件**：改结构 / 种子的同时**必须交付幂等增量脚本**供已有库升级；
      **两者内容必须一致，不允许只改一边**；
    - **菜单类变更不走增量脚本**：菜单结构由 `init-sql/moyun-menu-redo.sql` **单点维护**
      （已有库请在后台【菜单管理】直接改），避免增量脚本与初始化脚本**两套 `menu_id` 空间并存**；
    - **"已执行"不能只写在脚本注释里**：交付后必须**回查现网库核对**——用 init-sql 在临时库重建，
      与现网**逐表 / 逐列（类型·可空·默认值·collation）/ 逐索引**比对，**差异必须为 0**
      （现网只允许多出 `*_bak_*` 迁移备份表）。
      > 教训：脚本头写"dev 库已执行"但现网未生效**已发生两次**（collation 归一 160 列 + 支付金额列 8 列
      > 共 168 处漏迁移），均因交付时未回查现网库。

11. **增量脚本必须可重跑（"幂等"的判定标准）**：在**已迁移的库**上**连跑两次全 `exit 0`**——
    不是"报错属预期"。会报错的结构变更（`DROP KEY/INDEX`→1091、`ADD COLUMN`→1060、
    `ADD KEY/UNIQUE`→1061、`DROP/CHANGE COLUMN`）必须 `information_schema` 前置判断；
    破坏性清洗（`SET col=NULL` / 批量 `DELETE`）必须先建 `_bak_` 备份表，并在文件末尾给**可执行**复核 SQL
    （不是注释）。命名 `YYYYMMDD-NN-描述.sql`。

### 四、数据库口径（五条）

12. **金额一律 `decimal(18,2)`（元）**：禁止 `FLOAT/DOUBLE`，禁止 `BIGINT`（分）旧方案。
    唯一例外是按 token 计价的 5 个 AI 计费列（6 位小数，白名单）。

13. **软删列一律 `del_flag`**（`'0'`=存在 / `'2'`=删除，配 `BaseEntity` + 全局 `logic-delete-field`）；
    禁止新增 `deleted` / `is_deleted` 写法，**每表最多一个软删列**。
    现存例外：**仅** AI 11 表用 `deleted`（`AiBaseEntity` 有意设计，非违规）。

14. **collation 一律 `utf8mb4_0900_ai_ci`**：唯一例外 `ledger_ai_analysis_report` 的 `bin`（数据指纹 / JSON 精确匹配）。
    混用会让字符串列比较 / 连接报 `1267 Illegal mix of collations`。

15. **默认值必须 fail-closed**：核验 / 审核类状态列**不得**默认放行
    （`VERIFIED` / `APPROVED` / `PASSED` / …）——默认值是"绕过业务校验的直插 SQL"的兜底，
    默认放行等于把核验 / 审核做成可绕过；`update_time` 写了 `DEFAULT CURRENT_TIMESTAMP` 就必须同时写
    `ON UPDATE CURRENT_TIMESTAMP`，否则"看着自动维护、实际不刷新"。

16. **日期语义列用 `date`**：`birthday` 一类列不得用 `varchar` 存日期
    （比较按字符串、无法有效索引、年龄统计被迫 `STR_TO_DATE`）；Java 侧保持 `String` 亦可，
    但**列类型必须是 `date`**。

### 五、代码与模块（九条）

17. **统一收口**：LLM 走网关、返回走 `Result`、异常走全局处理、权限统一校验。

18. **模块依赖方向**：`common/util → core → system/portal/ledger/pay/vip → ext.*`，**下层不得反向依赖上层**。
    `core`/`util` 依赖业务模块属硬性禁止（需业务信息时做**依赖倒置**，范例
    `core.security.principal.PrincipalProvider`）；控制器不得住在 `core`；`util` 不得依赖业务实体。
    业务域之间的双向依赖是**已登记债务**（`portal`⇄`ext.cms`、`system→portal`、`pay/vip/ledger` 咬合），
    已在守卫冻结清单**按精确计数锁定**——**新增即失败、减少也要同步下调**。
    · **防腐层端口约定**：上层模块（如 `system` 管理端）不得直接 import 下层业务模块（如 `portal`）的
      实体 / Mapper；需要数据时在 `core` 定义**只暴露中性类型**（`String`/`Long`/`Map`）的端口，由业务侧实现
      （范例：`core.portal.AuditContentPort` + `portal.audit.AuditContentAdapter`）。

19. **移动 / 删除类后必须清 `target/classes`**，否则残留旧 `.class` 会造成
    `ConflictingBeanDefinitionException` 或 Mapper 解析失败级联污染测试上下文。

20. **网关输入用可变 Map**（`LinkedHashMap`/`HashMap`），**禁 `Map.of`**（不可变集合会被输入清洗路径击穿）。

21. **外部不可信数据走隔离通道**：转写 / 提问 / 简历等外部内容走 `input.context` / `transcript` +
    `PromptInjectionGuard.wrapData`，**禁走顶层 `userInput`**。

22. **`${}` 模板变量必须写清信任来源**：MyBatis 的 `${}` 是文本替换，安全取决于"谁写的内容"。
    数据权限片段**只能**由 `DataScopeAspect` 产出（写受信键，客户端 `?params[dataScope]=` 结构上进不了 SQL）；
    排序列名必须走 `PageDomain`（setter 白名单）；DDL 拼接仅限管理端代码生成。
    另注：`MapperMethod.ParamMap` 取不存在的键会抛异常（需 `containsKey` 守卫）；
    拦截 `${}` 必须早于 `BoundSql` 渲染（`InnerInterceptor#beforeQuery` 太晚）。

23. **运行时开关走 `sys_config`**（热生效）；yaml 仅做 bean 装配与结构化配置。

24. **同请求内不重复查同一配置行**：场景 / 开关类配置常在一次请求里被多处读取
    （鉴权前置校验 + 网关路由 + Handler 解析 + 参数裁剪）→ 用**请求级记忆化**
    （结果存 `RequestAttributes`，随请求销毁，**负结果也要记忆**）；
    **禁止用 TTL 缓存替代**——那会把"管理端改配置下次调用立即生效"降级为"最多 TTL 后生效"；
    非 HTTP 上下文（启动检查 / 异步线程 / 单测）自动退化为直查；共享实例**调用方只读**。

25. **LLM 输出解析只有一个入口**：禁止自写"首个 `{` 到最后一个 `}`"抠取，或自行处理 Markdown 代码围栏
    （收敛前 4 处抠取 + 3 处剥围栏，各自漏场景）；统一走 `com.moyun.util.json.LlmJsonExtractor`：
    `extract`（JSON 文本）/ `extractNode`（解析，失败 null）/ `stripCodeFence`（**散文场景专用**：
    只去围栏，不做 JSON 抠取）。实现含**括号配平扫描**（跳过字符串与转义）；截断不配平时返回空串，
    由调用方走降级分支。提示词模板里的围栏是合法用法，守卫不会误报。

### 六、事务（二条）

26. **事务只包 DB 写**：
    · 事务内**禁止**对象存储（MinIO/OSS）、HTTP、LLM/RAG、邮件短信、**本地磁盘写删**——开启事务即占用
      DB 连接，远程 IO 放里面等于用连接池额度等网络（并发打满连接池，且不报错不告警）；
    · 正确写法：IO 前置 / 后置到事务外，`TransactionTemplate` 只框住 DB 写（同时**去掉**原方法级 `@Transactional`）；
    · **注意"同文件私有 helper"**：`@Transactional` 方法调用含 IO 的私有方法，IO 照样在事务内（守卫有二阶扫描）；
    · **口径**：Redis / 缓存**不在**约束内（`start()` 的滑窗初始化有意留在事务内：Redis 失败即回滚建会话）；
      例外必须进守卫白名单并写理由（白名单有失效自检）；
    · **改动事务边界的验证要求**：静态守卫（一阶方法体 + 二阶同文件调用图）+ 运行时探针
      （真实 `TransactionTemplate` 观测活跃事务标志，IO 处 false / DB 写处 true）；探针必须带**灵敏度自检**
      与**证伪实验**（包进事务后必须翻转），否则会在失效时静默恒绿。

27. **回滚口径必须显式**：
    · 每个 `@Transactional` 都要写 `rollbackFor = Exception.class`——Spring **默认只回滚
      `RuntimeException`/`Error`**，受检异常会让多步写提交"半截数据"；`TransactionTemplate` 同口径
      （必要时 `setRollbackOnly`）；
    · **禁止 `noRollbackFor`**、**禁止类级 `@Transactional`**、
      **禁止注解标在 `private`/`protected`/`static`/`final` 方法上**（代理拦不到 → 静默无事务）；
    · `readOnly = true` 只加在确证只读的方法上，不为对齐而批量添加（当前全仓为 0，属有意选择）。

### 七、并发与安全（八条）

28. **增量写必须校验影响行数**：懒创建的聚合行（`portal_user_stats`/`portal_user_growth`/`portal_user_badge`）
    靠 `INSERT IGNORE + UPDATE ... col = col + ?` 维护，而 `INSERT IGNORE` 对非重复键原因的失败**静默**
    （只发 warning）→ **增量写 0 行必须 fail-closed 抛错**（事务回滚），不得裸调用丢弃返回值、不得只 `log.info`。
    · **范围仅限懒创建聚合行**；内容行计数（浏览 / 点赞 / 评论数）0 行=并发删除，属最佳努力，不扩张；
    · **"篇数/次数"类列固定 ±1**，不得复用成长规则的 `growthDelta`（真实事故：精选笔记数三处写入 → 单调虚高）；
    · 显式最佳努力路径允许不回滚，但 0 行必须 `log.error` 可见。

29. **按编号取资源必须校验归属**：凡"按业务编号取 / 改资源"的端点（`payNo`/`orderId`/`clientUuid`…）
    **必须校验归属当前登录用户**，只判"是否已登录"等于开放他人资源；失败响应与"资源不存在"一致
    （不泄露存在性）；状态变更（尤其 mock / 测试通道）的归属校验必须**早于**变更动作，
    且归属判断收口到唯一私有方法。

30. **跨域白名单不得用可伪造 pattern**：CORS 的 `allowedOriginPatterns` 中 `*` 是通配符
    （`http://192.168.*` 会匹配 `http://192.168.evil.com`）→ **内网放行必须按 Origin 解析 host
    并要求私网 IP 字面量**；生产未配置 `CORS_ALLOWED_ORIGINS` 时 **fail-closed**。

31. **WebSocket 握手凭证不得走 URL 明文 token**：浏览器 `new WebSocket()` 不能自定义请求头
    → 用**一次性短时效票据**（`POST /portal/ws-ticket` 需登录 → 32 hex 随机 + Redis 60s TTL +
    **Lua 原子取并删**只能用一次）；拦截器**显式拒绝 `?token=`**（防老客户端把 JWT 明文带回 URL）；
    小程序 / 原生 / 服务端用 `Authorization` 头；票据获取失败时保持轮询 / 批式降级，**不得**退回明文 token。

32. **外部地址 / 域名禁止留占位**：站点域名（前端 `VITE_SITE_URL`、后端 `PORTAL_DOMAIN`）、
    三方端点一律走环境变量**构建期 / 启动期注入**；**production 缺值即失败**，
    不留"注释提醒手工替换"的口子——实测占位域名 `xulin.example.com` 会随 `dist/` 上线
    （`index.html` / `robots.txt` / `sitemap.xml` 共 18 处，且后端动态 sitemap 默认值同一占位域名）。

33. **资金类幂等键必须叠加 `user_id`**：`clientUuid` 由客户端生成且无格式约束，
    **仅按 `clientUuid` 查 / 约束会命中他人单据**（随后复用其 `userId`/`amount` 下单）。
    唯一键一律 `(user_id, client_uuid)` 复合，**不得**做 `client_uuid` 全局唯一
    （全局唯一会让两个用户偶然撞同一 uuid 时报错）。

34. **异步自调用必须走代理**：`@Async`/`@Transactional` 同类内自调用不生效
    （`AsyncSelfInvocationGuardTest` 强制）；执行器统一治理（`ExecutorGovernanceGuardTest`）。
