## 二、重大项目转折分析（回溯 devlog）

> 识别 6 次方向性调整，理解"为什么是现在的架构"。

### 转折 1：v9.0（08-15）战略收缩——砍掉社区化，聚焦内容
删除 PK 对战、圈子社交两个模块（22+ Java 文件、DROP TABLE、菜单物理删除），首页回归内容型。
**动因**：社区功能拉新乏力、维护成本高。**影响**：确立"内容先行引流 → 体验留存 → 优质内容促进消费"的产品主线，此后所有功能围绕内容+工具价值展开。

### 转折 2：v9.5（08-16）分支合并——确立唯一开发基线
`main-dev-article` × `moyun-dev-kouzi` 精确文件抽取合并，放弃 git merge。
**影响**：自 v9.5 起单主干开发，杜绝分支漂移；随后 v9.6 后台体检（菜单收敛 + 27 类业务字典）完成"前台数据皆有后台管理"。

### 转折 3：v10.0~10.18（08-18~09-01）AI 面试成为核心差异化
旧版 MockInterview 下线（v10.3），新 AI 语音面试官从三引擎脚手架到 LLM 动态追问、面试报告分享全链路交付。
**动因**：内容平台竞争同质化，AI 面试是技术壁垒。**影响**：后续简历模块（v10.2~11.11）、题库刷题（v10.6~11.13）均围绕"面试求职"闭环建设。

### 转折 4：v11.0~11.3（09-01~09-02）商业化落地
微信支付公共通道 + 打赏分账 + 钱包提现，支付表统一 `pay_` 前缀，支付通知并入消息中心。
**影响**：变现链路具备，但 VIP 体系/积分商城仍未上线（见 §四 Phase 2）。

### 转折 5：v11.14~11.37（09-03~09-08）记账 App——第四端新产品线
从零新建 moyun-ledger-app（uni-app 三平台），后端 ledger 模块四阶段落地：核心记账 → 前端+凭证 → 报表/预算 → AI 财务分析。
**动因**：个人资产管理是独立高频场景，与求职场景共享账户体系。**影响**：产品从"求职工具+内容社区"扩展为"职业成长 + 个人财务"双场景；金额口径因此全项目统一（v11.31）。

### 转折 6：v11.38~11.43（09-08~09-09）AI 架构统一——Agent-First 方向
AiSceneEnum 场景注册表 → scene_code 全链路 → ai2 统一网关（`/api/ai/execute` 统一入口：场景配置/限流/语义缓存/执行日志/降级）。
**动因**：12 处业务硬编码直调大模型，模型/Agent/工作流无法配置化管理。**影响**：确立"Agent 嵌入 Workflow"的终局架构——业务只声明 scene_code，执行交给网关编排（详见 [AI能力统一接入层方案](../05-方案设计-分模块/AI能力统一接入层%20—%20完整方案文档.md)）。财务分析（finance_analysis）已作示范接入。
