## 三、这轮的关键提升

### 1. 防护覆盖（2% → 96%+）

- 21 → **522** 个限流点、**507** 个防重点；
- 覆盖记账、资产、库存、预算、CMS、面试、判题、题库等；
- 期间修复 7 处与既有注解重复的写法。

### 2. 校验真正生效

- 发现 `@Valid` 缺失导致 `@NotNull` 长期空转，已修；
- 流水 DTO：长度/时间格式；
- 存钱 mark/link/transfer：三个 DTO；
- 微信绑定：code 非空；
- 资产：名称/类型/余额；
- 上传：扩展名白名单 + 10MB + 空文件拦截，4 条单测。

### 3. 体验与视觉

- `PageState`：骨架/空态/失败重试；
- `FieldError`：存钱创建、记一笔、编辑流水行内红字；
- 定时记账加载骨架；
- 暗色/亮色 muted 对比度提升。

### 4. 框架

- `X-API-Version` 响应头 + 版本规范；
- 存钱主流程 E2E、公开接口冒烟、health 公开；
- 接口统计页 + 零调用每日报告 + 下线流程文档。

## 四、仍存在的短板

| 级别 | 问题 |
|---|---|
| P0 | **977 接口 / 33 页面**，接口规模仍远超产品面 |
| P0 | 校验集中在高频接口，大量 Map 入参接口仍靠手写判断 |
| P1 | 无 `/v1` 路径迁移；只有响应头版本 |
| P1 | 无 Prometheus 指标与告警，统计仅内存 |
| P1 | E2E 只覆盖存钱与公开接口，缺“记一笔→报表”链路 |
| P2 | 视觉 token、骨架屏仍未全量铺开 |
| P2 | 单机部署，DB/缓存/对象存储同机 |

---

## 五、下一步优先级

### P0（上线前）

1. MinIO 启动与凭据、Nginx/HTTPS、备份策略（环境项）；
2. 零调用接口按 14 天规则下线第一批；
3. 高频 Map 入参接口补校验（备忘、预算、定时任务）。

### P1

1. 指标导出 + 慢接口告警；
2. “记一笔 → 报表”E2E；
3. `/v1` 新接口规范落地。

### P2

1. PageState/Skeleton 全量；
2. 设计 token（字号/间距/圆角）；
3. 单机拆分。

---

## 六、结论

**单点能力 8 分，系统化 7.5 分，综合 7.7。**
三轮下来最大的变化不是功能，而是：**每个风险都有对应的机制**——限流、校验、契约、trace、统计、治理流程。

代码侧已接近“可上线”状态，剩下的是**部署环境**与**接口规模**两件事。
