## 1. 数据库口径：报告失真之处（本评审的第一手纠正）

### 1.1 事实：报告基于旧库，应用已切新库

| 依据 | 内容 |
|---|---|
| 报告 §方法 原文 | "dev 库实测（**`moyun-db`**，`COUNT(*)` 实测值）" |
| 报告 §9.2 复现命令 | `mysql -uroot -D **moyun-db** -e "…"` |
| 应用实际 | `application-dev.yaml` → `jdbc:mysql://localhost:3306/**moyun-db2**` |

### 1.2 两库 AI 配置**不是同一套数据**（实测对照）

| 指标 | `moyun-db`（报告所用） | `moyun-db2`（应用实际） |
|---|---|---|
| `ai_agent` | **7** 行（id 47~53） | **2** 行（id 1~2） |
| `ai_scene_config` 悬空 agent 引用 | **0** ✅ | **5** ❌（评审时） |
| `sys_config.defaultAgentId` | **48**（存在 ✅） | **48**（**不存在** ❌） |
| `ai_agent.model_config_id` 悬空 | **7** 行指向 17（不存在） | **2** 行指向 17（不存在） |
| `portal_voice_interview` | **18 行** ✅ | **0 行** |

```
moyun-db  :: agent: 47财务分析师 | 48AI面试官·默认 | 49 | 50 | 51 | 52 | 53
moyun-db2 :: agent: 1财务分析师  | 2AI面试官·默认
model     :: db: id 10/11/15/17   |  db2: id 1/2/3/4
```

### 1.3 需要改写的两条结论

| 报告原文 | 评审结论 |
|---|---|
| §0.1 结论 2：「dev 库三条链引用全悬空…**实测 `portal_voice_interview` 0 行（从未成功开面）**」 | ❌ **表述不准确**。"0 行/从未开面"**仅对 `moyun-db2` 成立**；`moyun-db` 有 **18 场**成功记录。真实语义是「**新库缺旧库的 AI 配置数据**」，非"系统能力不足" |
| §3.5：「父场景 `voice_interview.agent_id` = **48（不存在）**」 | ⚠️ **仅在 db2 成立**。db 中 **agent 48 存在**（`AI面试官·默认`，`enabled=1`） |

### 1.4 ★ 根因（报告未定位，本评审首次查明）

> **`init-sql` 种子里硬编码了来源库的 agent id，而 `ai_agent` 的 INSERT 不含 `id` 列。**

| 位置 | 原值 | 后果 |
|---|---|---|
| `moyun-db-dml-init.sql` 4 行 `ai_scene_config` | `'chat',48,` | 自增库 agent 恒为 1/2 → **必然悬空** |
| 同行 `sys_config.defaultAgentId` | `'48'` | **`start()` 直接抛「AI 面试官未配置」** |
| `finance_analysis` 行 | `'analysis',47,` | 同类缺陷（**报告未发现**） |
| 注释自认 | `-- voice_interview task 行绑定 agent_id=48` | 把来源库 id 当常量写死 |

**⇒ 这不是"环境数据坏了"，是"种子就有缺陷"**：**任何全新库初始化即带悬空引用**，面试必失败。

**已修复（v13.38/v13.39）**：
- `moyun-db-dml-init.sql` 5 处硬编码 → **按 `name` 子查询取 id**
- 新增增量 `20260929-04-AI绑定链修复（消除agent_id硬编码悬空引用）.sql`（幂等 + `_bak_` 备份）
- **现网 `moyun-db2` 已应用**：悬空 = **0**、`defaultAgentId=2`（AI面试官·默认）、4 场景绑 agent 2、finance 绑 agent 1
- 全新库验证：悬空 = **0**

## 3. 报告未覆盖的 6 项运行期隐患（本评审补测）

> 依据：独立核验员逐条取证 + 本评审实测。**均带 `文件:行号`。**

### 🔴 R1 — 答题链**无任何并发保护**（唯一会损坏数据的问题）

| 项 | 事实 |
|---|---|
| 唯一守卫 | `VoiceInterviewServiceImpl.java:688-695` 状态串判断，**读后不锁**；全类无 `synchronized`/`ReentrantLock`/`setIfAbsent`/乐观版本号 |
| 同 `qaId` 重复请求后果 | ① `:702-707` 两次都写 `userAnswer` → **后写覆盖前写**；② `:747` 两次都提交 → **两次 LLM 流式（双倍 token）**；③ `:795-818` 两边各自 `qaMapper.insert(nextQa)` 且 `questionIdx = +1` → **同一 idx 插两条 QA**（无唯一约束） |
| 不同题并发 | `ContextManager.java:64-69` `append` → `readWindow` **非原子**，两边互相看不到 |
| 接口限流 | `PortalVoiceInterviewController.java:86-87` `@RateLimiter(key="voice:answer", 3600, 60)` = **每小时 60 次**，对毫秒级连点**无约束** |
| 无状态机 | `phase` 字段仅在 `finish` 写入（`:1054-1056`），`submitAnswer` 不校验 `phase`/`currentIdx` |

**⇒ 报告把"一题评三次"列为 P1（可复现性差），却没看到"一题可插两条 QA"（数据损坏）。严重度排序应上调。**

### 🔴 R2 — 答题与报告聚合**无事务**

| 路径 | 事务 |
|---|---|
| `submitAnswer` | ❌ 无（QA 落库 + 建下题 + `recordEvent` 全自动提交） |
| `runBatchAnalysis:1131-1197` / `aggregateAndStoreReport:1213-1399` / `enhanceReportByAgent:1591-1777` | ❌ **全无 `@Transactional`**（含 QA 分回写 `:1254`、错题本 `:1377`、主表 report `:1390-1395`） |
| `start()` | ✅ 手写 `transactionTemplate.executeWithoutResult`（`:470-483`）只包 DB/Redis 写，LLM 在事务外（**v13.14 收窄，做得好**） |
| `finish():1039` / `regenerateReport():1498` | ✅ 有 |

**⇒ 聚合中途失败会留半成品**（部分 QA 已回写分数、主表未更新）。**注：SSE 长连接不持有事务，此点干净。**

### 🔴 R3 — LLM **无重试**；**超时口径冲突**

| 项 | 事实 |
|---|---|
| 模型超时 | `ModelConfigServiceImpl.java:712-714`（同步）/`:740-742`（流式），仅 `timeout != null` 时下发；种子 **180s**（`:69-70`）/ 60s（`:67-68`） |
| 场景级字段 | `AiSceneConfig.timeoutSeconds/retryCount` **除快照回写外零读取**（死字段）；`AiMetadata.retryCount` 从未赋值 |
| 网关重试 | `AiGatewayService.java` 全文件**无** `retry`/`@Retryable` |
| 唯一"重试" | 报告 JSON 解析失败后追问一次（`VoiceInterviewServiceImpl.java:1649-1656`） |
| ⚠️ **口径冲突** | `SSE_TIMEOUT = 120_000L`（`:281`）**＜** 模型 `timeout = 180s` ⇒ **模型还在跑，SSE 已超时** |

### 🔴 R4 — **客户端断开后服务端继续跑 LLM**

| 项 | 事实 |
|---|---|
| emitter 回调 | `:737-741` 有 `onTimeout`/`onError`，**但只打日志**（不 complete、不清状态） |
| `onCompletion` | **全仓无注册**（grep 仅命中 WebSocket 的 `OnlineUserTracker.java:42`） |
| `sendEvent` | **吞异常只记日志**（`:165-171`） |
| 取消通道 | 无 emitter 注册表；`AiGatewayService.java:438` `model.chat(messages, handler)` 持有回调但**无 `Disposable`/`Flux` 引用**，无取消手段 |
| 断连后行为 | `onCompleteResponse`（`:453-497`）**照常执行** → **继续耗 token、继续 `tokenCostGuard.consume`、继续写滑窗与执行日志** |

### 🟠 R5 — 面试场景**成本熔断实际未启用**

| 项 | 事实 |
|---|---|
| 熔断点 | `AiGatewayService.java:194/227-228`（同步）、`:326`、`:409/481`（会话流式） |
| 语义 | `TokenCostGuard.java:82-85`：**`limit <= 0` 即放行**（null/0=不限） |
| ⚠️ 面试场景 | `moyun-db-dml-init.sql:78` `voice_interview` 行 **`daily_token_limit` 位为 NULL** ⇒ **该场景无每日 token 上限** |
| 匿名桶 | 逐题分析传 `userId = null`（`:1159-1160`）⇒ 网关限流身份落 **`"anonymous"` 桶**（`AiGatewayService.java:178-179`）⇒ 所有匿名调用**共用配额桶** |

### 🟠 R6 — 性能未量化

| 项 | 实测 |
|---|---|
| **基线调用数/场** | **2N + 2**（N=题数）→ **5 题 = 12 次** |
| 构成 | 预热 1（`:656`）+ 对话 N（`:784`）+ 逐题分析 N（`:201`/`:1159`）+ 报告复盘 1（`:1648`） |
| 降级增量 | warmup 失败 `generateOpening` +1（`:673`）；复盘 JSON 失败重问 +1（`:1654`） |
| 旁路增量 | `requestHint` 每次 +1（`:1016`）；滑窗超窗每轮摘要可再触发 1 次（`ContextManager.java:97-99`） |
| **自介 4 维** | **0 次**（不可达，见论断 9） |
| 报告 prompt 体积 | 随题数**线性增长**（题≤150 / 答≤400 全量 QA 入 prompt，`:1591-1660`） |
| 首字延迟 | 未量化；`start()` 同步含 RAG 检索 + 预热 LLM |

## 4. 四视角评审结论（报告覆盖情况）

| 视角 | 报告表现 | 本评审补测 |
