## 一、为什么不做自动删除（重要）

CSS **没有构建期安全网** —— `vue-tsc` / `vite build` 都不会因"删掉了仍在使用的类"而失败，删错只会造成**静默的 UI 回归**。本项目此前已记录过"批量按文本模式删改导致结构损坏"的教训，因此该维度按"宁可保留、不自动删"处理。

扫描过程中实测确认了 **4 类系统性误判**，任何一类都足以造成 UI 回归：

| # | 误判类 | 实例 | 说明 |
|---|---|---|---|
| 1 | **Vue 过渡动画类** | `.fade-enter-active`、`.modal-leave-to`、`.sidebarLogoFade-enter` | 由 `<transition name="fade">` 在**运行期生成**，模板里永远不出现。已加入排除规则 |
| 2 | **第三方组件内部类** | `.el-input-number--small`、`.el-select--small`、`.el-scrollbar__view`、`.el-tree-node__content` | Element Plus 渲染的**子组件根元素**会带上父组件的 scoped 属性，故 scoped 规则**确实生效**；无法静态判定 |
| 3 | **解析器误读声明值** | 从 `background-image: url(".../login-background.jpg")` 解析出类名 `.jpg` | 选择器解析 bug（已修：声明行不再参与选择器解析） |
| 4 | **复合选择器 / 字符串拼接** | `.el-select-dropdown__item.selected`、`:class="'txn-icon ' + t.type"` | 类名只作为复合选择器的一部分，或由字符串拼接产生 |
