## 2. 关键设计取舍（验收时值得重点看的地方）

1. **请求级记忆化 vs TTL 缓存**（v13.19）：`AiSceneRegistry` 类注释原本承诺"管理端改配置下次调用立即生效"，
   所以**不用 TTL 缓存**（会降级为"最多 TTL 后生效"），改用随请求销毁的 `RequestAttributes`；
   `AiSceneRegistryRequestCacheTest#newRequestSeesFreshConfig` 专门锁死这一点。
2. **WebSocket 为什么是票据而不是请求头**（v13.21）：浏览器 `new WebSocket()` 不能自定义请求头，
   所以不可能"把 token 挪进 header"；子协议方案依赖服务端回显与代理转发，故取票据方案（一次性 + 60s）；
   拦截器**显式拒绝 `?token=`**，避免老客户端把漏洞带回来（`plainTokenInUrlIsRejected`）。
3. **防腐层的落点**（v13.22）：端口定义在 `core`（`system` 可依赖），实现放在 `portal`（业务侧）；
   代价是 `portal -> ext.cms` 78→82（适配器要调 CMS 业务服务），已在守卫里登记理由。
   `system -> portal` 余 6 条（看板/通知/代发私信）属后续批次。
4. **脚本"幂等"的判定标准**（v13.18）＝在**已迁移的库**上连跑两次全 exit 0，
   而不是"报错属预期"；会报错的结构变更必须 `information_schema` 前置判断。
