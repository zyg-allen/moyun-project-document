## 五、关键决策记录

### 5.1 为什么用积分打赏而不是真实资金？
- **决策**：v5.0 用积分替代真实资金
- **原因**：绕开支付资质门槛，先验证产品逻辑
- **后续**：流量起来后接真实支付通道，积分打赏逻辑保留

### 5.2 为什么代码执行临时下线？
- **决策**：v5.2 返回 503 临时下线
- **原因**：ProcessBuilder 无沙箱隔离，存在 RCE 风险
- **后续**：迁移到 Docker/gVisor 强隔离后恢复

### 5.3 为什么 SQL 脚本整理？
- **决策**：v5.2 将 90 个脚本归类为 12 个文件
- **原因**：原脚本 ALTER 分散，部分无幂等保护，重复执行报错
- **后续**：引入 Flyway 后，整理后的脚本作为 baseline

### 5.4 为什么 JWT 删除 fallback？
- **决策**：v5.2 删 DEV_FALLBACK_SECRET
- **原因**：硬编码 fallback 密钥，攻击者读源码可伪造身份
- **后续**：dev 环境在 application-dev.yaml 配默认密钥，prod 必须环境变量

## 六、开发规范要点

1. **SQL 脚本必须幂等**：CREATE TABLE IF NOT EXISTS、INSERT IGNORE、ALTER 用 information_schema 检查
2. **计数器必须原子**：`UPDATE ... SET count = count + #{delta} WHERE count + #{delta} >= 0`
3. **删除必须级联**：删主实体时清理评论/点赞/收藏/订单等关联数据
4. **越权必须校验**：所有写操作前校验 `existing.authorId == currentUserId`
5. **密码必须加密**：BCryptPasswordEncoder，禁止明文
6. **JWT 密钥必须环境变量**：≥ 64 字符，prod 无默认值 fail-fast
7. **文件上传必须白名单**：扩展名 + 大小限制
8. **异常必须脱敏**：GlobalExceptionHandler 返回通用提示，不暴露 SQL/堆栈
9. **Markdown 必须 sanitize**：sanitizeHTML 过滤 XSS
10. **评论必须登录**：SecurityConfig 不允许 permitAll
