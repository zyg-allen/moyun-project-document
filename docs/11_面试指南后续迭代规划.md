## 二、P0 优先级（决定性缺口，直接阻碍核心价值）

### 2.1 OJ 在线判题系统

**现状**：题目提交仅记录状态（`isPass`/`score`），无真实判题。代码答题是裸 textarea，无运行结果反馈。
**位置**：[QuestionDetailPage.vue:347-353](../moyun-portal/src/pages/interview/QuestionDetailPage.vue#L347)

**对标**：力扣 / 牛客 / Codeforces

#### 实现方案

**后端（重）**：
1. **判题沙箱**：基于 Docker / Firecracker 隔离运行用户代码，限制 CPU/内存/网络/文件系统
2. **测试用例模型**：题目增加 `test_cases` 表（input / expected_output / is_sample），支持多组用例
3. **判题队列**：Redis + 异步 Worker，避免阻塞请求线程
4. **判题结果**：返回 `status`（AC / WA / TLE / MLE / RE / CE）+ `runtime` + `memory` + `failed_case`
5. **复用现有**：项目已有 `codeRun.ts` API（学习中心模块），可改造为完整 OJ 判题

**数据模型新增**：
```sql
-- 题目测试用例
CREATE TABLE interview_question_test_case (
  id BIGINT PRIMARY KEY,
  question_id BIGINT NOT NULL,
  input TEXT NOT NULL,           -- 标准输入
  expected_output TEXT NOT NULL, -- 期望输出
  is_sample TINYINT DEFAULT 0,   -- 是否样例（前端展示）
  order_num INT DEFAULT 0,
  INDEX idx_question (question_id)
);

-- 判题提交记录
CREATE TABLE interview_judge_submission (
  id BIGINT PRIMARY KEY,
  question_id BIGINT NOT NULL,
  user_id BIGINT NOT NULL,
  code TEXT NOT NULL,
  language VARCHAR(20) NOT NULL,
  status VARCHAR(10) NOT NULL,    -- AC/WA/TLE/MLE/RE/CE
  runtime INT,                    -- ms
  memory INT,                     -- KB
  failed_case_id BIGINT,
  error_message TEXT,
  created_at DATETIME,
  INDEX idx_user_question (user_id, question_id)
);
```

**前端**：
- 提交后轮询判题状态（SSE 或 1s 间隔轮询）
- 展示用例通过情况（✅/❌ 逐个用例）
- 失败时高亮首个失败用例的 input/expected/actual

#### 验收标准
- [x] 算法题支持至少 5 组测试用例
- [x] 提交后 5s 内返回判题结果（同步路径立即返回，异步路径提交后秒级入队）
- [x] 支持 7 种语言（JS/TS/Python/Java/Go/C++/Rust）
- [x] 沙箱隔离，无法访问网络与文件系统（Docker 沙箱 `--network=none --read-only --cap-drop=ALL`）
- [x] TLE/MLE 限制可配置（默认 2s/256MB，由 `moyun.judge.timeout-ms` / `moyun.judge.memory-limit-mb` 控制）

#### v8.0 已交付清单（2026-08-13）

|---|---|---|
| ProcessBuilder 判题引擎 | `judge/ProcessJudgeEngine.java` | dev/test 默认，未做沙箱隔离 |

### 2.2 Monaco 代码编辑器

**现状**：代码答题是裸 `<textarea>`，无语法高亮、自动补全、快捷键。
**位置**：[QuestionDetailPage.vue:347-353](../moyun-portal/src/pages/interview/QuestionDetailPage.vue#L347)

**对标**：力扣（VSCode 同款 Monaco）/ 牛客（CodeMirror）

#### 实现方案

**选型对比**：

| 选项 | 体积 | 体验 | 推荐度 |
|---|---|---|---|
| Monaco Editor | ~2MB（gzip 600KB） | VSCode 同款，语法高亮+补全+快捷键 | ⭐⭐⭐⭐⭐ |
| CodeMirror 6 | ~400KB | 轻量，语法高亮+基础补全 | ⭐⭐⭐⭐ |
| 保持 textarea | 0 | 无 | ❌ |

**推荐方案**：Monaco Editor（按需加载，仅代码题路由引入）

**前端实现**：
```typescript
// 按需动态 import，避免打入主包
const loadMonaco = async () => {
  const monaco = await import('monaco-editor');
  return monaco;
};

// 语言映射
const LANG_MAP = {
  javascript: 'javascript',
  typescript: 'typescript',
  python: 'python',
  java: 'java',
  go: 'go',
  cpp: 'cpp',
  rust: 'rust',
};

// 主题跟随
watch(theme, () => {
  monaco.editor.setTheme(theme.value === 'dark' ? 'vs-dark' : 'vs');
});
```

**配置**：
- 字体：JetBrains Mono / Fira Code（已加载）
- Tab 大小：2（JS/TS） / 4（Python/Java/Go/C++/Rust）
- 快捷键：Ctrl+Enter 提交，Ctrl+S 保存草稿
- 主题：跟随站点 light/dark/eye 三主题

#### 验收标准
- [ ] 7 种语言语法高亮
- [ ] 自动补全（关键字/内置函数）
- [ ] 主题跟随站点切换
- [ ] 按需加载，首屏不增加体积
- [ ] 移动端降级为 textarea（Monaco 不适配小屏）

### 2.3 LLM 对话式面试

**现状**：模拟面试是 5 道固定题一问一答，无多轮追问，与真实面试官差距大。
**位置**：[MockInterviewPage.vue:217-248](../moyun-portal/src/pages/interview/MockInterviewPage.vue#L217)

**对标**：面试鸭 / 牛客 AI 面试

#### 实现方案

**后端（重）**：
1. **对话管理**：基于 LangChain4j + 通义大模型，维护对话上下文
2. **面试官 Persona**：根据岗位 + 场景 + 候选人画像，动态生成面试官人设
3. **追问策略**：
   - 答案不完整 → 追问细节
   - 答案过于简短 → 追问展开
   - 答案偏离 → 拉回主题
   - 答案优秀 → 升级难度
4. **评分维度**：每次回答从 5 维度评分（技术深度/逻辑清晰/表达流畅/项目理解/创新思维）
5. **结束判定**：达到题量上限 / 候选人主动结束 / 面试官判断已充分考察

**API 设计**：
```typescript
// 开始对话式面试
POST /portal/interview/mock/conversational/start
{ position, scene, personalized }

// 多轮对话
POST /portal/interview/mock/{sessionId}/chat
{ message }

// 结束并生成报告
POST /portal/interview/mock/{sessionId}/finish
```

**前端**：
- 聊天式 UI（参考 ChatGPT 界面）
- 面试官消息 + 用户消息气泡
- 支持语音输入（Web Speech API）
- 实时显示对话轮数 / 预计剩余时间
- 结束后生成对话式面试报告（保留现有雷达图 + 强弱项分析）

#### 验收标准
- [ ] 单次面试 8-15 轮对话
- [ ] 面试官能根据回答质量动态追问
- [ ] 每轮响应 < 5s（流式输出）
- [ ] 报告含 5 维度评分 + 强弱项 + 改进建议
- [ ] 画像驱动面试官 persona

### 3.2 简历模板套用渲染

**现状**：模板库是文件下载库，编辑器是结构化录入，两者无关联。
**位置**：[ResumeTemplatePage.vue](../moyun-portal/src/pages/interview/ResumeTemplatePage.vue) vs [ResumeEditPage.vue](../moyun-portal/src/pages/interview/ResumeEditPage.vue)

#### 实现方案

**模板字段扩展**：
- 简历模板表新增 `template_config`（JSON）：版式配置（颜色/字体/布局/section 顺序）
- 新增 `preview_renderer`：纯前端组件，根据 template_config + 用户数据渲染预览

**前端实现**：
1. 模板库卡片增加「使用此模板」按钮
2. 点击后跳转编辑器，URL 带 `?templateId=xxx`
3. 编辑器读取 templateId，加载 template_config，预览 Tab 按该版式渲染
4. 导出 PDF 时后端按 template_config 渲染对应版式

**版式预设**：
- `simple`：简约（单列，黑白）
- `business`：商务（双列，深蓝）
- `creative`：创意（色块，鲜艳）
- `campus`：校招专用（突出教育经历）

### 3.3 简历语义级 AI 建议

**现状**：AI 评分/建议为规则化（关键词命中、字段非空判断），无法做语义级评估。
**位置**：[api.ts:1297-1298](../moyun-portal/src/types/api.ts) `aiPowered: false`

#### 实现方案

**后端接入 LLM**：
1. 项目分析：STAR 法则检查（情境/任务/行动/结果是否完整）+ 量化表达建议（缺少数字指标）
2. 自我介绍优化：识别套话（"我热爱编程"）→ 改写为具体案例
3. 技能匹配度：JD 关键词提取 + 简历技能语义匹配（同义词/上下位词）
4. 整体连贯性：经历之间的逻辑性、时间线一致性

**API 改造**：
```typescript
// 现有
getResumeAiAdvice(id)  // 规则化

// 新增
getResumeAiAdviceDeep(id)  // LLM 语义级，流式返回
```

**前端**：
- 建议卡片增加「深度分析」按钮（消耗积分）
- 流式输出（SSE），打字机效果
- 支持「一键重写」项目描述（LLM 生成优化版，用户对比采纳）
