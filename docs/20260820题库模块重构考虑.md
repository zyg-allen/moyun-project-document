| ---- | ------------- | -------------------- |
| 用途   | 展示阅读（看题+答案）   | 交互练习（做题+判分+记录）       |
| 数据结构 | 问题描述+分类+公司+答案 | 题干+选项/测试用例+难度+解析+知识点 |
| 用户行为 | 浏览 → 阅读答案     | 做题 → 提交 → 判分 → 看解析   |

业内主流做法
------

**LeetCode / 牛客 / 力扣** 全部采用：**统一题库模型 + 题型字段区分**

* 一张基础题表存公共字段（标题、描述、难度、分类、标签、状态）
* `question_type` 区分：选择 / 编程 / 判断 / 填空 / 简答
* 差异化内容用 JSON 扩展字段或关联子表（选项表、测试用例表）
* 前台入口分离（"面试题浏览"vs"在线练习"），但底层共用一套数据

我的建议：统一题库，扩展复用
--------------

**不重新定义独立模块**，而是基于现有面试题库扩展。原因：

1. **数据高度重叠** — 题目标题、描述、分类、公司归属、答案/解析 80% 字段一致
2. **一题多用** — 同一道选择题，既能在"面试题库"里浏览答案，也能在"刷题中心"里做练习
3. **维护成本低** — 分类/标签/公司只维护一份，不用两套后台重复录入

### 数据模型设计

plaintext

现有面试题库表（扩展）

├── id

├── title（题目标题）

├── description（题目描述 / 题干）

├── category_id（分类）

├── company_id（归属公司，可空）

├── difficulty（难度：简单/中等/困难） ← 新增

├── question_type（题型） ← 新增

│ ├── 1 = 面试题（展示型，现有数据）

│ ├── 2 = 选择题

│ └── 3 = 编程题

├── content_extra（JSON 扩展字段） ← 新增

│ ├── 选择题: { options: [{label:"A", text:"..."},...], answer: "B" }

│ └── 编程题: { input_example:"...", output_example:"...",

│ testcases: [...], language_limit: [...] }

├── analysis（解析/解题思路） ← 新增

├── knowledge_tags（知识点标签 JSON） ← 新增

├── sort（排序）

├── status（状态：草稿/发布/下线）

└── 原有字段...

关联子表（新建）

├── question_option ← 选择题选项（也可放 JSON，看数据量）

├── question_testcase ← 编程题测试用例

├── user_question_record ← 用户做题记录（对错、用时、提交代码）

└── user_error_book ← 错题本
