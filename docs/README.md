## 维护规则

1. 每次修改登记 devlog；
2. 接口/表结构/状态机/配置变化同步对应文档；
3. 严重滞后的文档直接删除，不保留“过期但看起来有效”的版本；
4. 评审报告只保留最新一版结论，旧版删除；历史审计类保留并标注“历史归档”；
5. 文档只写可验证行为，不确定的列“待确认”。
## 版本命名规则

| 类型 | 命名 | 规则 |
|---|---|---|
| 规范/方案 | `端-模块-功能-Vx.y.md` | 内容有实质修改就升版本并改文件名，旧版删除 |
| 评审/扫描报告 | `...-YYYYMMDD.md` | 按日期归档，不改写历史 |
| 索引 | `README.md` | 只指向最新版；历史归档在 09 目录保留 |
